# Researcher-02: CLI gate surface, tests, kit metadata, doctor coexistence

Budget was 5 tool calls; findings below are grep-level, not exhaustive. Paths relative to repo root.

## Summary
- Gate logic in the CLI is concentrated in a few modules: `doctor/hard_gates/` (734 LOC, pure gate probe, dead without gates), `plan_doc/{approve,receipt}.rs` (221+249 LOC), `verdict_gate` (CLI 46 LOC + core), `validate/gate_authority*.rs` + `Section::Gates`, and `capability/lifecycle.rs` gated rows. Everything else only mentions gates in strings.
- `doctor` already has the exact scaffolding a coexistence report needs: `Check{name,status,detail}`, a `Place` (project/global) with `place.other()`, per-runtime ownership index, a hooks check, and a "scopes: hooks registered at both scopes run twice" WARN. `--global` exists.
- Test blast radius is large: 202/471 golden npm files, 304/1039 files under `crates/mewkit-cli/tests`, 83 `npm_behaviour` files mention gate terms. Goldens are frozen and cannot be regenerated; policy is hand-edit only for a deliberate change and record why.
- Hook retirement for existing installs: root `deletions.json` (130 lines, flat list of kit-relative paths). Hook scripts for gates are not yet listed.

### 4. doctor structure
16. `crates/mewkit-cli/src/commands/doctor/mod.rs`: `DoctorArgs` `:24` (flags `hard_gates :41`, `adopt :42`, `global :50`, targets, providers, state); `Status{Ok,Warn,Fail}` `:57`; `Check{name,status,detail}` `:65`, `Check::new :72`, `to_json :86` = `{"name","status":"ok|warn|fail","detail"}`; `run :90`. Flow: `toolchain::checks()` then `installs::checks(&place, place.other(), &targets)` then optional providers/state/hard_gates, then JSON array or text via `extras::report`. Exit nonzero only on Fail (`:148`).
17. Existing inspections: `installs.rs` (ownership index per runtime + owned files; both-scopes duplicate-hook WARN at `:18-24`; global-only project WARN `:42-50`); `hooks.rs` (`scripts()` reads `.claude/settings.json` / `.codex/hooks.json` / `.cursor/hooks.json`, verifies every kit hook script named exists; `coverage()` for non-Claude runtimes); `hook_commands.rs` (`kit_scripts`, `script_token`, `normalize` parse hook command strings: reusable to enumerate hook commands); `codex_trust.rs`; `extras.rs` (state, provider checks); `adopt.rs`; `provenance.rs`.
18. Data available: `Place::new(args.global)` gives project or global scope and `place.other()` the counterpart; `OwnershipIndex` (`mewkit-core/src/ownership.rs:40`, `load :104`) lists kit-owned files and hook handlers per runtime, so non-owned hook entries in the same settings file = foreign. NOT visible today: user-global `~/.claude/{agents,skills,rules}` listings, installed plugins (no grep hit for `plugins` in doctor), and other toolkits' skill/agent names. `--global` is implemented (installs.rs covers it); reading `~/.claude/*` directly would be new code, but `Place`/`ScopeKind::Global` already resolves the global root.
19. Best insertion point: new `doctor/coexistence.rs` module returning `Vec<Check>`, called from `run()` beside `installs::checks`, either always or behind `--coexistence` (flag pattern per `--providers`/`--state`). Rows can reuse `hooks::collect` and `hook_commands` to list non-kit hooks, plus a name-collision scan of kit skill/agent names versus global dirs.

## Recommendations
- Treat as three work items: (a) delete/rewrite gate code (hard_gates probe, `plan approve`, `verdict-gate`, `validate --gates`, lifecycle evidence strings), (b) retire hook files via `deletions.json` plus metadata JSON, (c) new `doctor` coexistence module.
- Keep `plan check --structural`, `plan archive`, `plan status`, the `review` pipeline (triage), and a slimmed `hard-gates`/ship probe that exercises `pre-ship.cjs` only. Decide on CLI flag compatibility: keep `--hard-gates` as an alias (avoids breaking golden argv cases) or remove it (rewrite goldens).
- Plan a dedicated "hand-edit goldens + DIVERGENCES rows" phase; do a precise count first by running the affected cargo tests after the code change rather than trusting the grep counts above (they over-count generic words like "contract").
- Coexistence report MVP: (1) hooks in each settings file not owned by the ownership index (foreign), (2) same-event hooks that could double-run (project vs global, already partly done), (3) agent/skill/rule name collisions between kit-owned files and `~/.claude/{agents,skills,rules}`, (4) plugin dirs under `~/.claude/plugins` if wanted. Emit as ok/warn Checks only, never fail, so JSON shape stays stable.
- Order: remove gate hooks and metadata first with `validate` green, then CLI code, then goldens.
