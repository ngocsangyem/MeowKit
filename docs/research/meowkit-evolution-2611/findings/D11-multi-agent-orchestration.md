## 2. Part 1 — Supervisor–Lead–Peer (SLP) article

**Precise claims (DOCUMENTED, vhlam.com):**
- Roles: Human (goals/priorities/trade-offs); Supervisor (talks to human on architecture, watches cross-scope drift, may speak directly to Peers but direction changes must return to Lead's shared state); Lead (holds room state, assigns ownership, handles dependencies, judges evidence, owns integration + acceptance); Peer (specialist responsibility: investigate/design/implement/review; may challenge premises, propose scope change). Peer kinds: Implementer, Reviewer, System Architect, Auditor.
- Role = responsibility + authority, not personality; "three agents with detailed title prompts, same context, same write access, nobody owning integration is not SLP".
- Ownership: agent ownership + state ownership; one owner per changing scope until explicit handover; peers may request, not overwrite.
- Communication: briefs separate goal / hard constraints / current design choice (choice is not a requirement); reviewer must know which version it reviews; a message ("I'll yield CPU") is not evidence, check real state.
- Escalation: Peer evidence (repro test) -> Lead (goal/constraint check, coordinate owner) -> Supervisor -> human if goal/cost change unapproved.
- Right to dissent, not duty to dissent; redesign proposals must themselves be challenged.
- Termination: no dedicated section (article never specifies stop conditions). Nearest: evaluate by "chain of change" (did intervention alter outcome), not counts of objections; remove a reviewer that rarely changes outcomes yet costs tokens; tune from telemetry; best improvements remove a mechanism.
- Scope limits: small changes may be better single-agent; skipped for human-feedback-heavy work (game feel, UI/UX).

**Evidence offered:** anecdotes from 3 personal projects (Nova, Quark, clinic CRM); one concrete bug story (47 tests passed, 4 added regressions failed); analogies (bicycle/parachute, boat). One citation to Ng (The Batch 2024), arXiv 2608.21156 (exists; verified: "Graph Engineering in the Era of LLM Agents", submitted 2026-08-21, cs.IR; a survey, author says it is not validation of SLP), Claude Code agent teams. No experiment, no baseline, no cost data, no failure rates. The author states it is subjective, not a standard. Model names cited (e.g. "Sol 5.6", "Astra", "Opus 5.5") and Codex multi-agent v1/v2 behaviour: UNKNOWN (not verified by me).

**Critique (INFERRED unless noted):**
- Testable: (a) one-owner-per-scope reduces overwrite/duplicate work (testable; consistent with CAID soft-vs-worktree isolation, F-D11-09, and the C-compiler failure log, F-D11-10). (b) reviewer that rarely changes outcome should be dropped (testable via ablation). (c) "right to dissent, no duty" avoids manufactured disagreement (testable: false-positive rate, cf. 2603.16244 review-noise result). (d) Supervisor layer reduces misdirection vs Lead-only (untested; no source anywhere).
- Rests on human-team analogy: Supervisor/Lead/Peer hierarchy, escalation chain, "owner until handover". Human-team org structure transfers unproven; LLM-specific failure modes (shared training prior, sycophancy, context loss at hand-off) differ.
- Strong point: brief separating goal/constraint/current choice targets MAST FM-1.1 (disobey task spec 11.8%) and the anchoring risk; also matches Cognition "share context" principle.
- Not addressed: token cost multiple; latency; correlated errors (all peers same model); context loss at Lead->Peer hand-off (the author raises "main selectively passes context" but gives no mitigation beyond reading transcripts); termination/stop rules; non-parallelisable vertical dependency (his own motivating case) is exactly where 2512.08296 shows MAS degrade; who verifies the Lead; escalation fatigue for the human; Supervisor-as-bottleneck.
- Internal tension: a Supervisor that can instruct Peers directly while Lead holds state is the conflicting-direction risk the article itself flags.
- Applicability to MeowKit: SLP ~ MeowKit orchestrator (Supervisor-ish router) + developer (Lead) + subagents (Peers) + human gates, but MeowKit's orchestrator "never writes code, only routes" (`orchestrator.md:3`), so it is not a Lead owning integration.

## 5. Part 3 — Six configurations (core question)

Core answer: for SE, multi-agent collaboration pays for itself only in narrow, evidenced conditions (parallelisable breadth or long-horizon decomposable work with strict test oracles and isolated workspaces; fresh-context review for defect detection). As a default for complex engineering tasks it is NOT supported (matched-budget controlled evidence is neutral-to-negative). Confidence: Medium on "not a default win", Low on magnitudes.

## 6. Part 4 — Execution philosophy (UNDERSTAND -> ACT -> INSPECT -> ADJUST -> ACT)

- Competing approaches: plan-then-execute (planner fixed, cheap executor), ReAct interleaving, fixed phase-gated kits (spec-driven, explore-plan-code-commit), harness loops (planner/generator/evaluator).
- Evidence: (a) Anthropic removed per-sprint decomposition and context resets as models improved, kept planner + one final evaluator pass (DOCUMENTED, F-D11-11) -> RESEARCH-SUPPORTED-weak for H2. (b) Plan-and-execute vs ReAct: only practitioner claims; no SE ablation (UNKNOWN). (c) Spec-first: mixed/null/vendor (F-D11-14). (d) Requirement omission and weak self-verification are the main SE agent bottlenecks (2511.04064) -> UNDERSTAND and INSPECT steps are evidenced; fixed phase count is not. (e) Clarification should be conditional on detected under-specification (Ambig-SWE, Ask or Assume); models are poor at deciding unprompted -> a conditional ask needs a detection mechanism, not just permission. (f) Stop conditions: MAST termination modes total ~18.6% (12.4+6.2) -> explicit stop/verify criteria are evidenced needs. (g) Gating: human approval is rubber-stamped (93% accept); action-class gating is the vendor remedy; classifier FNR 17% on overeager actions means automation is evidence, not authority (consistent with MeowKit gate invariant).
- H3 (adaptive beats rigid): HYPOTHESIS; no head-to-head found. Indirect: scaffolding value is model-dependent; reversibility-keyed gating beats volume gating on fatigue grounds (INFERRED).
- NOT settled: whether upfront planning helps modern models on SWE tasks; whether gates keyed to risk vs size change outcomes; optimal question rate; value of explicit phases for non-expert users vs expert agents.
- The requester's loop is compatible with evidence provided: INSPECT is a verification against external oracle (tests/compile), not self-review; ADJUST is bounded (repeat rounds raise noise); escalate/clarify/terminate are decision points with explicit triggers (spec ambiguity, irreversible action, repeated failure count, budget).

## 8. Experiments (test H4 for MeowKit)

Common: fixed model (one frontier + one smaller), fixed token budget cap per task logged, deterministic oracle (hidden tests + build), >=5 trials per arm per task (variance), report pass rate, tokens, wall-clock, human-intervention count, cost; paired analysis.
1. Pipeline ablation: 30 SWE-bench-Verified-style repo tasks (balanced difficulty). Arms: A native host single agent; B MeowKit default pipeline; C single agent + MeowKit rules only (no subagents). Falsifies "multi-agent pipeline adds value" if B <= A at higher cost.
2. Review arms on 40 seeded-defect PRs (injected + natural): same-session self-review; fresh-context diff-only; fresh-context + author rationale; different-model fresh-context; deterministic tests-only. Metrics F1, false-positive rate, cost. Tests anchoring and model diversity (evidence gap).
3. Parallel decomposition: 15 multi-module features with known file graph. Arms: sequential single; 2/3 worktree workers (zero overlap); 3 workers shared tree; 5 workers. Metrics integration failures, merge conflicts, duplicate work, pass rate, cost; tests the max-3 rule.
4. Clarification: 40 underspecified tasks (Ambig-SWE style). Arms: never ask; always ask; conditional (detector skill); human-approved plan gate. Metrics resolve rate, question count, human time. Tests over-asking cost and conditional trigger.
5. Gate design: 30 tasks containing a few irreversible actions; gate by task size vs by action risk vs no gate (auto classifier) with simulated approver fatigue; metrics dangerous-action pass-through, interruptions, completion.
6. (Optional) SLP vs lead+workers on vertically dependent task (his motivating case), 10 tasks x 5 trials; the only way to get SLP evidence.

## 9. Claim lists

RESEARCH-SUPPORTED: multi-agent not reliably better than single agent at matched budget on SE/reasoning (2512.08296, 2604.02460, 2505.18286); coordination adds 2-5x overhead and error amplification (2512.08296); parallel agents conflict more across agents (2607.04697); worktree isolation beats shared workspace (2603.21489); personas do not reliably help (2311.10054); debate not better than self-consistency by default, heterogeneity helps (2502.08788); fresh session beats repeated same-session review (2603.12123); multi-turn review adds false positives (2603.16244); interaction helps underspecified SE tasks (2502.13069, 2603.26233); breadth-first research benefits from MAS at ~15x tokens (Anthropic, internal).
HYPOTHESIS: SLP or any Supervisor layer improves outcomes; subagent value is chiefly context isolation (no ablation); adaptive workflows beat rigid ones (H3); max-3 is the right cap; risk-keyed gates beat size-keyed gates; reviewer without author reasoning detects more defects; different-model review > fresh same-model in SE.
CONTRADICTED: "multi-agent is better for complex coding by default" (matched-budget SWE-bench Verified -2 to -15%); "role specialisation per se improves quality" (persona null results); "more agents/rounds improve reviews" (2603.16244; CAID 8 workers < 4); Cognition 2025 "multi-agent never" narrowed by Cognition 2026 itself; earlier CCR headline superiority (revised, n.s. vs single review).
