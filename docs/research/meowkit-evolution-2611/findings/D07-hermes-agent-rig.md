## 2. Findings

### hermes-agent

**F-D07-01 Agent loop is a bounded iteration loop with budget + stop gates, not a phase pipeline.** VERIFIED. Loop continues while `api_call_count < max_iterations and iteration_budget.remaining > 0` (or one grace call): `H:agent/conversation_loop.py:1752-1753`; `IterationBudget` thread-safe counter, parent default 500, each subagent 50, `execute_code` iterations refunded: `H:agent/iteration_budget.py:1-45`. Wall-clock `--run-budget` injects a wrap-up notice at 80%: `conversation_loop.py:58-60`. Retries/fallbacks/compression/interrupt are separate phase modules (`turn_api_error`, `turn_loop_errors`, `turn_retry_state`). Interrupt: user correction rewrites the turn with scaffold text (`conversation_loop.py:74,324-352`). Why it matters: termination = budgets + model stop + evidence-nudge, no human gate in the loop. Counter-evidence sought: any mandatory plan phase; none found in core loop (plan-like behavior = optional skills).

**F-D07-02 "Done" is checked by a passive evidence ledger plus a bounded nudge, not a gate.** VERIFIED. `agent/verification_evidence.py:1-4` ("Deliberately passive — never runs a suite, never blocks completion, never upgrades targeted checks into repo green"); SQLite ledger of verification commands per session/root; stop-gate appends a synthetic user-role nudge when code was edited without fresh evidence (`agent/turn_stop_gates.py:36-60,178-185`); `pre_verify` hook may return `continue`; bounded by `max_verify_nudges` default 3 (`agent/verify_hooks.py:16,29-34`). Why it matters: closest analogue to MeowKit Phase 3.6 verify + Gate 2, but it is *deterministic evidence + cheap re-prompt*, bounded, no human approval, no reviewer agent. Effectiveness evidence: none found (HYPOTHESIS that it helps).

**F-D07-03 System prompt is small, model-conditional, and snapshot-tested.** VERIFIED. Prompt snapshots in `tests/fixtures/prompt_surface/`: stable+volatile+context prompt tokens for `cli-code.claude` = 1829+1268+134 (~3.2k tokens), tools = 9,464 tokens (21 tools) (`surfaces.json`); rendered prompts 10-15 KB (`prompts/*.txt`: claude 10,088 B, gpt 14,887 B, gemini 11,777 B, hermes 10,087 B). `AGENTS.md:19-21`: a prompt or `tools[]` change fails `tests/ci/test_prompt_surface.py` until snapshot is committed AND needs core approval. Persona file `SOUL.md` is 667 bytes (`H:SOUL.md`). Why it matters: a hard, CI-enforced footprint budget on always-loaded context; MeowKit has no analogue (its always-loaded rules are tens of KB; not measured here).

**F-D07-04 Scaffolding is varied per model family, and one variation was A/B-measured and REJECTED.** VERIFIED (claim in source comment; run not reproduced). `TOOL_USE_ENFORCEMENT_MODELS = ("gpt","codex","gemini","gemma","grok","glm","qwen","deepseek","muse")` (`H:agent/prompt_builder.py:362`); `EXECUTION_GUIDANCE_MODELS` (376-382) added "after Composio agentic-eval traces showed the same failure modes"; comment: "Claude does not exhibit these modes" (lines ~370-375); Nemotron deliberately excluded: 5 runs each on/off, "pass rate moved by under 1 point on SWE-bench Verified, SWE-bench Pro and GDPval, +3.7 on Terminal-Bench 2.1, not significant (p=0.14)" (lines ~363-366). Google/OpenAI-specific blocks (`GOOGLE_MODEL_OPERATIONAL_GUIDANCE`, `OPENAI_MODEL_EXECUTION_GUIDANCE`). Supports H2 (scaffolding is not uniformly useful; it is model-conditional and should be measured per model). RESEARCH-SUPPORTED? No: this is the project's own unpublished-in-repo measurement; treat as DOCUMENTED-in-source.

**F-D07-05 Core-tool deferral A/B: fewer schemas cost ~0 accuracy, saved tokens.** VERIFIED as repo artifact (not reproduced). `H:evals/core_tool_deferral/results/SUMMARY.md`: 288 live runs, 3 models; schema 47.4 KB -> 21.0 KB (-56%); grand accuracy base 0.923 vs 0.916 ("flat within rep noise"), tokens down on every model (-7% to -23%), turns +1-2, qwen wall +48%; one real regression (`clarify` used 18/18 -> 7/18; models ask as plain text); weaker models sometimes *improved* with a focused catalog line. Why it matters: concrete evidence that harness-surface changes are testable cheaply and that tool/skill surface trimming is roughly accuracy-neutral. Counter-evidence: tiny sample per cell (n=3, contested n=6), single-author harness.

**F-D07-06 Memory is deliberately tiny, frozen-per-session, injection-scanned; knowledge is routed to skills first.** VERIFIED.
- Files: `MEMORY.md` (agent notes) and `USER.md` (user profile); char limits 2200 / 1375 (`H:tools/memory_tool.py:62-66`, `memory_tool_store.py:188`). Entries delimited, tool ops add/patch/remove/batch.
- Prompt entry: FROZEN snapshot at session start; mid-session writes hit disk but never change the prompt (`memory_tool.py:1-4`; `memory_tool_store.py:179,224,656`) — driven by the "prompt caching is sacred" invariant (`H:AGENTS.md:15-18`).
- Validation: every write scanned with the `strict` pattern set (`_scan_memory_content`, `memory_tool_store.py:29-32`; patterns incl. `authorized_keys`, `hardcoded_secret`, agent-config-modification, exfil: `tools/threat_patterns.py`); drift detection refuses a write that would discard hand-edited text and writes `.bak.<ts>` (`memory_tool_store.py:51-60,732`); concurrent writers serialized by file lock; staged writes pinned to the exact entry reviewed (`memory_tool.py:_pin_matched_entries`).
- Write guidance: declarative facts not imperatives ("imperative phrasing gets re-read as a directive in later sessions"), "Skills come first", facts stale within a week belong to session history (`prompt_builder.py:195-235`).
- Who writes: foreground tool, and a background review fork after N turns (`memory.nudge_interval` default 10, `agent_init.py:1159,1193`) restricted by a dispatch-side whitelist; fork prompt requires grounding ("Never infer the user's traits… never turn a one-off request into a standing preference", `background_review.py:455-465`).
- Recall beyond the frozen snapshot: `session_search` = SQLite FTS5 over raw messages, no LLM (`tools/session_search_tool.py:1-8`, `hermes_state_fts.py:46`); optional single external memory provider plugin with prefetch, fenced in `<memory-context>` and stripped from output (`agent/memory_provider.py`, `agent/memory_context.py`).
- Effectiveness evidence that memory improves outcomes: NONE found (no eval under `evals/` for memory/skills; ls of `evals/` has compaction, core_tool_deferral, prompt_footprint, tool_search, etc., none for memory benefit). UNKNOWN. HYPOTHESIS only.
Why it matters for MeowKit: a "more elaborate" memory in the leading open agent is *smaller* than MeowKit's concept (~3.5K chars total in prompt), plus FTS over raw history. The elaboration is in safety (scan, drift, pinning, caps), not in retrieval sophistication.

Skill body/descriptions get an injection-pattern pass (`skills_tool_plugin._INJECTION_PATTERNS`).
- Self-improvement loop: `skill_manage` tool create/edit/patch/delete (`skill_manager_tool.py:1-12`); background review fork every `skills.creation_nudge_interval` (10) tool iterations asks "update the skill library. Be ACTIVE — most sessions produce at least one skill update" (`background_review.py:532-535`, `agent_init.py:1235-1237`); long anti-hoarding / do-not-capture prompt blocks ("Negative claims about tools… harden into refusals", "Unresolved failures… do NOT write dead ends as workflow", lines 478-529). `Curator` (inactivity-triggered, default every 7 days, stale 14d, archive 30d; LLM consolidation opt-in `DEFAULT_CONSOLIDATE=False`; only agent-created skills; archive never delete; pinned exempt) `agent/curator.py:1-35`. **F-D07-18 System prompt is one fixed ~1.7 KB string with no dynamic content.** VERIFIED `R:plugins/rig-basics/src/prompt.rs:19-45`: "no date, no paths, no instruction file contents and no tool rules in it"; tool rules live in each tool's description; AGENTS.md appended nearest-last after `RIG_HOME/AGENTS.md`; `CLAUDE.md` NOT read (`docs/agent.md:358-366`); cache-prefix guard test in rig-cassette (AGENTS.md:52). **F-D07-19 Context management: clear-then-summarize near window with note-before-clear.** VERIFIED (docs; code in `compaction.rs` 2,065 lines skimmed). Trigger within 16k tokens of window; first clear older tool outputs only after the model wrote notes on them, or when every one is an unchanged `read`; else structured summary (goal, progress, decisions, next steps, files read/changed); newest ~20k tokens kept; `/compact <focus>` (`R:docs/agent.md:386-407`). Retries: up to 4, honours Retry-After ≤60s, exponential 2-4-8-16-30 with jitter; a model that calls a nonexistent tool 3 times fails the turn (`[tools] max_unavailable_calls`, `crates/rig-ecs/src/tools.rs:619`). Model catalog (`rig-core/src/catalog/models.json`) carries per-model context/output limits, reasoning options, cost and cache pricing; reasoning effort is a first-class setting. No per-model prompt variants (single fixed prompt).
