`baseline/*.manifest.json` record what `mewkit init --target <t> --yes` (npm CLI)
wrote at origin/main 861db010. They are frozen: the npm CLI and the script that
produced them are gone, so they cannot be regenerated. They are a reference, not a
contract: `mewkit` must match them or list the difference here, with the decision
behind it.

Differences in what `init` accepts, not in what it writes (so not in the manifests):

- `--target` with a name that is not a runtime exits 2 here and 1 in the npm CLI; it takes a list here, and `tests/lifecycle.rs` pins the 2.
- `--mcp-profiles` reads `catalog/mcp-profiles.json` from the kit's Cursor bundle, which `scripts/kit-ship-set.cjs` ships. An older kit without it reports "no mcp-profiles.json catalog shipped" and installs without MCP.
- A project with a git remote needs `--allow-cloud-mcp`; without a terminal there is nobody to ask, so it is blocked (the npm CLI does the same on the explicit `--target cursor` path).

## Printed messages

Differences in what a command prints, pinned by the hand-edited goldens under `npm/`:

- 1 `providers --lifecycle --json` recording was hand-edited: `providers-lifecycle-matrix-json.json`, where the `pre_tool` proof for `claude-code` and `claude-plugin` named `src/__tests__/hooks/gate-enforcement.integration.test.ts`. Gate removal: that test went with the plan gate, and the surviving in-repo proof that a PreToolUse hook denies a call is the privacy block's replay case, `tests/hooks/golden/privacy-read-dotenv.json`. The `gate: true` claim itself is unchanged — it describes the host's ability to deny, not a MeowKit gate.
- 7 `validate` recordings were hand-edited, one line each, because the report lost two rows. `rules/gate-rules.md` left the always-on rule set (`validate-authoring.json`, `validate-authoring-strict.json`, `validate-broken-install.json`, `validate-docs-refs-default.json`, `validate-flat-copy.json`, `validate-mode-override.json`, `validate-portable.json` — the `[PASS] File exists: rules/gate-rules.md` row and one off the `N passed` tally), and the `Gates` section lost its only check (`validate-authoring.json`, `validate-authoring-strict.json` — the `Gates` heading with `[PASS] No automated gate-approval claims`, and a second off the tally). Gate removal: the rule file and the gate-authority lint are both gone, so neither row can be produced. The fixtures still carry `rules/gate-rules.md`, which is why only the report changed. `Section::Gates` itself stays in the renderer's order, unused, for the same reason `Inventory` does.
- 24 recordings were DELETED rather than edited, because the verb each one recorded no longer exists: `plan-approve-*.json` (11) and `plan-by-before-approve.json` for `plan approve`, `verdict-gate-*.json` (10) for `verdict-gate`, and `validate-gates.json` / `validate-gates-clean.json` for `validate --gates`. Their fixtures went with them (`plan-activation-blocked`, `verdict-gate`, `validate-gate-authority`); `plan-approvable` stays, because `plan check --structural` still reads it. Gate removal: a recording of a removed verb pins nothing, and keeping it would read as a case someone forgot to run.
- `capabilities` with no source (`npm/capabilities-no-source.json`) and with an invalid Codex snapshot (`capabilities-bad-snapshot`, whose stderr the case ignores and asserts on its own) tell the user to run `mewkit init …`, where the npm CLI said `npx mewkit init …`. `setup --system-deps`, when declined, likewise names `mewkit setup --system-deps` and `mewkit doctor` (no golden covers it). Maintainer decision 2026-11-15: the npm CLI is retired, so the native binary names itself and the kit and docs use the `mewkit <verb>` form.

Regeneration is manual and not gated in CI: the kit changes often and every
change moves thousands of digests. A CI job must exist before any phase claims
parity from these manifests.
