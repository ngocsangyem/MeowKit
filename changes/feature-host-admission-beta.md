---
section: Features
---
- `mewkit host` (beta): `status` samples machine load and prints a verdict; `run` puts a heavy build or test through one machine-wide fair queue at low priority and returns within a bounded wait, with exit 75 and `NOT VERIFIED` when the command has not finished; `jobs` waits for, reads and cancels jobs; `watch` tells each worktree which processes load the host; `clean` removes MeowKit's own stale host state and `status --caches` names Rust `target/` directories to clean. Settings `host.enabled`, `host.auto_clean` and `host.max_heavy` live in `~/.meowkit/config.yaml` only. See [Host Admission](/guide/host-admission).
- New observer `host-pressure` (Claude Code only, `hooks.host-pressure: false` turns it off). The opt-in completion check credits `mewkit host run -- <cmd>` as `<cmd>`, and `mewkit host jobs wait <id>` only for a job that ended with 0 on the current file tree.
- `mk:verify` and `mk:orchestrate` route full suites through `mewkit host run` and hold dispatch while the host is saturated.
- The host watcher follows the kit's lifecycle: it exits when `mewkit self-update` or a package upgrade replaces its binary (the hook starts the new one), `mewkit host watch --detach` replaces a watcher from another version, `mewkit uninstall --yes` stops it when the last runtime of an install leaves and names `~/.meowkit/host`, and `mewkit doctor` has a `host watcher (beta)` row.
- On macOS and Linux, a waiting `mewkit host run` or `host jobs wait` that receives SIGTERM or SIGHUP prints the not-finished block and exits 75, leaving the job running; Ctrl-C at a terminal cancels the job and exits 70.
- A job's identity includes its environment (minus per-shell and per-session variables such as `PWD`, `TMPDIR` and agent session ids), and callers that start the same command at once share one job. The log on disk is scrubbed of secrets as it is written. A job whose command exited while something it started kept the output open is stopped after 10 seconds, and a cancel in that time ends it as cancelled. Exactly one of the supervisor and a client that gave up waiting for it runs the command.
- The completion check credits `jobs wait` only for the tree the command ran on, unchanged from its start to its exit; `mk host jobs wait` and `--timeout` before the id are recognised. Admission checks free space on the volume the command runs on, not only the home volume. Host cleanup checks the owner of every file it removes; on Windows it removes files only when `~/.meowkit/host` is inside the user profile. `host.*` keys are no longer offered by the project config schema.
- Several projects on one machine keep apart: `mewkit host jobs list` shows the current worktree's jobs (`--all` for every worktree), `jobs cancel` refuses another worktree's job without `--any-worktree`, `jobs wait` and `jobs log` say when a job is another worktree's, and the completion check credits a job only in the worktree it ran in. Ended jobs are capped at the newest 200 and unused command key locks expire after a day.
