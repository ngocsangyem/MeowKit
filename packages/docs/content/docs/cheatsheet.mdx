## CLI

The native `mewkit` binary is the only CLI, and `mk` is the same binary under a shorter name. See [Installation](/installation). Run `mewkit <command> --help` for the flags of any command.

| Command | What it does |
|---------|-------------|
| `mewkit init` | Install the kit into this project (`--target`, `--profile`, `--dry-run`) |
| `mewkit upgrade` | Move the installed runtimes to a newer kit, keeping your edits |
| `mewkit uninstall` | Remove the kit (shows what would go unless `--yes`) |
| `mewkit doctor` | Check the toolchain, the installs and their hooks |
| `mewkit validate` | Check this project's structure and wiring |
| `mewkit setup` | Guided post-scaffold configuration |
| `mewkit versions` | Kits installed, cached and available |
| `mewkit self-update` | Replace this binary with the newest release |
| `mewkit providers` | What each runtime gets from the kit: files, skills, hooks, gaps |
| `mewkit task new\|list` | Create and list task files |
| `mewkit plan status\|check\|sync\|archive` | Inspect, sync or archive a plan under `tasks/plans/` |
| `mewkit note <decisions\|gotchas>` | Append a lint-checked entry to the team memory (entry on stdin) |
| `mewkit budget` | Token and USD spend from the cost log |
| `mewkit capabilities` | Explain, resolve and project the kit's capabilities |

`orient`, `task-state`, `review`, `advice`, `trace`, `skill`, `pack` and `backups` are also available.

## Agents

The agents that own a workflow phase. `.claude/agents/` holds 42 in all, including the Jira and Confluence executors.

| Agent | Runs when | Phase | Key output |
|-------|-----------|-------|------------|
| orchestrator | Every task | 0 | Routing decision and model tier |
| planner | Standard and complex tasks | 1 | Plan file under `tasks/plans/` |
| brainstormer | Explicit, or complex planning | 1 | Trade-off analysis |
| researcher | Research tasks | 0, 1, 4 | Structured findings |
| architect | Schema, API or infra changes | 1 | ADR and system design |
| tester | On request, always in `--tdd` mode | 2 | Tests (failing ones in `--tdd` mode) |
| security | Auth, payments or security changes | 2, 4 | BLOCK or PASS verdict |
| developer | After the planner (TDD off) or tester (TDD on) | 3 | Implementation |
| reviewer | After implementation | 4 | Five-dimension verdict |
| shipper | After review | 5 | PR and rollback docs |
| documenter | After ship | 6 | Updated docs and changelog |
| analyst | Session start and end | 0, 6 | Cost report and patterns |
| journal-writer | On failure or escalation | 6 | Root cause write-up |

## Workflow phases

| Phase | Name | What happens |
|-------|------|-------------|
| 0 | Orient | Read memory, load skills, pick the model tier |
| 1 | Plan | Challenge premises, write the plan, agree it with you |
| 2 | Test | Failing tests first with `--tdd` or `MEOWKIT_TDD=1`; optional otherwise |
| 3 | Build | Implement per plan, then 3.5 Simplify and 3.6 Verify |
| 4 | Review | Five-dimension audit and a written verdict |
| 5 | Ship | The ship check runs on commit, push, merge and PR; then commit, PR, CI check, rollback docs |
| 6 | Reflect | Update docs and memory, retrospective |

## Execution modes

| Mode | When | Agents | Ordering |
|------|------|--------|----------|
| Sequential (default) | All tasks | One per phase | Every phase |
| Parallel | Complex task with independent subtasks | Up to 3, one worktree each | Phases stay sequential |
| Party | Architecture decisions | 2 to 4 deliberating agents | No code, synthesis only |

## Model routing

| Tier | Examples | Model |
|------|---------|-------|
| TRIVIAL | Rename, typo, format | Cheapest |
| STANDARD | Feature, bug fix, tests | Default |
| COMPLEX | Architecture, security, auth | Best |

`mk:scale-routing` runs at Phase 0 and forces COMPLEX for domains such as fintech, healthcare and auth. [Agent Models](/guide/agent-models) lists the model each agent runs on.

## Hooks

The ones you meet most often. [Hooks](/reference/hooks) lists them all.

| Hook | Event | What it does | Refuses the action? |
|------|-------|-------------|---------------------|
| `pre-ship.cjs` | PreToolUse (Bash) | Ship check: lint, related tests and type-check before commit, push, merge or PR | Yes |
| `privacy-block.cjs` | PreToolUse | Blocks reads of `.env`, keys and credential files | Yes |
| `post-write.cjs` | PostToolUse (Edit\|Write) | Security scan of the written file; a hit goes back to the model | No |
| `build-verify.cjs` | PostToolUse (Edit\|Write) | Compile or lint after an edit; a failure goes back to the model | No |
| `pre-task-check.cjs` | PreToolUse (Bash) | Injection pattern detection, reported to the model | No |
| `delegation-brief-check.cjs` | PreToolUse (Task\|Agent) | Notes a subagent brief with no `Goal:` or `Return:` label, reported to the model | No |
| `project-context-loader.cjs` | SessionStart | Loads `docs/project-context.md` | No |
| `post-session.cjs` | Stop | Cost log and session trace | No |

## Planning (phase 1)

| Command | Purpose | Ends with |
|---------|---------|-----------|
| `mk:plan-creator` | Create a plan from scratch | Prints the plan and stops |
| `mk:plan-ceo-review` | Critique the plan's ambition and scope | Prints and stops |
| `mk:validate-plan` | Check an agreed plan across eight dimensions | Prints and stops |
| `/mk:cook [path]` | Build from the plan | Runs the pipeline |

Each planning skill stops after printing, so you decide when to run `/mk:cook [plan path]`. [Plan Creator Modes and Flags](/core-concepts/plan-creator-modes-and-flags) covers the modes.

| Command | What it does |
|---------|-------------|
| `mewkit task new --type feature "desc"` | Create a task file |
| `mewkit task list` | List task files with status, type and priority |

Task types are `feature`, `bug-fix`, `refactor` and `security`. Create a task file for any change that touches more than two files or takes more than about 30 minutes.

## Settings

Behavior settings live in one committed, schema-validated file: `.meowkit/config.yaml`.
The environment carries credentials, host values and per-invocation handoffs only.
Source of truth for the file's key surface: `crates/mewkit-core/schemas/config-v1.json`.

### Density + budget

| Key | Values | Effect |
|-----|--------|--------|
| `autobuild.mode` | `MINIMAL` \| `FULL` \| `LEAN` | Overrides the auto-detected autobuild density. It does not bypass a guard |
| `budget.warn` | e.g. `30` | USD threshold for the first spend notice. Advisory |
| `budget.block` | e.g. `100` | USD threshold for the over-budget notice. Nothing is stopped |
| `budget.cap` | e.g. `50` | Overrides `budget.block`, lower or higher |

### Core runtime

| Key | Values | Effect |
|-----|--------|--------|
| `tdd` | `true` \| `false` | `true` = strict red-green-refactor (write the failing test first; no hook checks the order); default `false`. `MEOWKIT_TDD=1` in the environment overrides the file |
| `buildVerify.timeoutMs` | milliseconds | Per-command timeout for the build-verify hook |
| `projectContext.maxBytes` | bytes (default `12288`) | `project-context.md` size warn threshold; `0` disables |
| `workflow.telemetry` | `off` \| `community` \| `anonymous` | Workflow telemetry preference |
| `workflow.proactive` | `true` \| `false` | Proactive workflow suggestions |

### Hook controls

`hooks.<name>: false` disables one observer, and the default is `true`. `<name>` is the observer's file base name, for example `build-verify`, `loop-detection`, `pre-completion-check`, `tdd-flag-detector`, `learning-observer` or `budget-tracker`. The config schema lists 23 such keys.

The guards `privacy-block` and `pre-ship` have no config key. An unknown key in `config.yaml` is a validation error, and the guards keep running. A `hooks.<name>` toggle for a handler that no longer exists only warns.

### Environment

| Variable | Values | Effect |
|----------|--------|--------|
| `MEOWKIT_TDD` | `0` \| `1` | Overrides `tdd`, at the top of the precedence chain |
| `MEOWKIT_HOOK_PROFILE` | `standard` \| `fast` \| `strict` | Hook profile read by observers such as `learning-observer`. The ship check ignores it. |
| `MEOWKIT_MODEL_HINT` | a model id, for example `claude-opus-5-5` | Names the running model to the harness, which uses it to pick the autobuild density |

### Precedence

```
MEOWKIT_TDD  >  CLI flag / session sentinel  >  .meowkit/config.yaml  >  ~/.meowkit/config.yaml  >  default
```

A malformed `config.yaml` applies no keys. Observers fall back to their own defaults, the guards keep running, and `mewkit doctor` reports the file and the line.
