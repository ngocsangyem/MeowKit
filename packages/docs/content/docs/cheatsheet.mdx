## CLI

The native `mewkit` binary is the only CLI. `mk` is the same binary under a shorter name. See [Installation](/installation).

| Command | What it does |
|---------|-------------|
| `mewkit init` | Install the kit into this project (`--target`, `--profile`, `--dry-run`) |
| `mewkit upgrade` | Move the installed runtimes to a newer kit, keeping your edits |
| `mewkit doctor` | Check the toolchain, the installs and their hooks |
| `mewkit validate` | Check this project's structure and wiring |
| `mewkit setup` | Guided post-scaffold configuration |
| `mewkit versions` | Kits installed, cached and available |
| `mewkit self-update` | Replace this binary with the newest release |

Run `mewkit --help` for the full list.

## Workflow Phases

| Phase | Name | Check | What happens |
|-------|------|-------|-------------|
| 0 | Orient | — | Read memory, load skills, route model tier |
| 1 | Plan | — | Challenge premises, write the plan, agree it with you |
| 2 | Test | — | Write failing tests first (TDD mode `--tdd`/`MEOWKIT_TDD=1`); optional otherwise |
| 3 | Build | — | Implement per plan; in TDD mode, until tests pass |
| 4 | Review | — | 5-dimension audit, written verdict |
| 5 | Ship | Ship check | Lint, related tests and type-check on commit/push/merge/PR; then commit, PR, CI verify, rollback docs |
| 6 | Reflect | — | Update docs, memory, retrospective |

## Execution Modes

| Mode | When | Agents | Ordering |
|------|------|--------|---------------|
| Sequential (default) | All tasks | 1 per phase | Every phase |
| Parallel | COMPLEX + independent subtasks | Up to 3, worktree isolation | Phases stay sequential |
| Party | Architecture decisions | 2-4 deliberation agents | No code, synthesis only |

## Task types

| Type | Use when | Create with |
|------|----------|-------------|
| feature | Adding new functionality | `mewkit task new --type feature` |
| bug-fix | Fixing broken behavior | `mewkit task new --type bug-fix` |
| refactor | Restructuring code | `mewkit task new --type refactor` |
| security | Security review | `mewkit task new --type security` |

### Task status flow
`draft` → `in-progress` → `blocked` → `review` → `done`

### Non-trivial rule
Create a task file for any change affecting > 2 files OR > 30 minutes.

## Settings

Behavior settings live in one committed, schema-validated file: `.meowkit/config.yaml`.
The environment carries credentials, host values and per-invocation handoffs only.
Source of truth for the file's key surface: `crates/mewkit-core/schemas/config-v1.json`.

### Density + budget

| Key | Values | Effect |
|-----|--------|--------|
| `autobuild.mode` | `MINIMAL` \| `FULL` \| `LEAN` | Override auto-detected scaffolding density. Never bypasses a safety hook |
| `budget.warn` | e.g. `30` | USD warn threshold (prints warning, continues) |
| `budget.block` | e.g. `100` | USD hard-block threshold (halts the run, sets `final_status=TIMED_OUT`) |
| `budget.cap` | e.g. `50` | User-set cap; overrides `budget.block` (can be lower OR higher) |

### Core runtime

| Key | Values | Effect |
|-----|--------|--------|
| `tdd` | `true` \| `false` | `true` = strict red-green-refactor (write the failing test first; no hook checks the order); default `false`. `MEOWKIT_TDD=1` in the environment is a supported override and wins over the file |
| `buildVerify.timeoutMs` | milliseconds | Per-command timeout for the build-verify hook |
| `projectContext.maxBytes` | bytes (default `12288`) | `project-context.md` size warn threshold; `0` disables |
| `workflow.telemetry` | `on` \| `off` | Workflow telemetry preference |
| `workflow.proactive` | `on` \| `off` | Proactive workflow suggestions |

### Hook controls

`hooks.<name>: false` disables one observer; the default is `true`. `<name>` is the
observer's own file base name — `build-verify`, `loop-detection`,
`pre-completion-check`, `tdd-flag-detector`, `learning-observer`, `budget-tracker`
and the rest of the 21 in `.claude/hooks/handlers.json`.

Safety hooks cannot be disabled from any config: `privacy-block`,
`pre-ship`, `check-careful`, `check-freeze` and `check-report-path` are
rejected with a validation error, and the hook keeps blocking.

### Environment

| Variable | Values | Effect |
|----------|--------|--------|
| `MEOWKIT_TDD` | `0` \| `1` | Supported override of `tdd`, at the top of the precedence chain |
| `MEOWKIT_HOOK_PROFILE` | `standard` \| `fast` \| `strict` | Hook profile selector, read by `pre-ship.cjs`. Legacy alias `MEOW_HOOK_PROFILE` still accepted; new name wins if both set. No config key — a safety entrypoint reads it, and those read no config file |
| `MEOWKIT_MODEL_HINT` | e.g. `opus-4-6` | Tell the harness which model is running (enables LEAN auto-detect) |

### Precedence reminder

```
MEOWKIT_TDD  >  CLI flag / session sentinel  >  .meowkit/config.yaml  >  ~/.meowkit/config.yaml  >  default
```

A malformed `config.yaml` applies no keys at all: observers fall back to their own
defaults and keep running, safety hooks keep blocking, and `mewkit doctor` reports the
file and the line.
