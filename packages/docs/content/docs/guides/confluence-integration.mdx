MeowKit reads and writes Confluence through the `confluence-as` CLI. If you have already set up [Jira](/guides/jira-integration), most of this is done, because the same Atlassian API token works for both.

## Set it up

Install the CLI into the `confluence` skill's own environment:

```bash
mewkit skill env confluence
```

Then add three values to `.meowkit/.env`:

| Variable | What it is |
|---|---|
| `MEOW_CONFLUENCE_API_TOKEN` | An Atlassian Cloud API token. The same one you use for Jira is fine |
| `MEOW_CONFLUENCE_EMAIL` | The Atlassian account that token belongs to |
| `MEOW_CONFLUENCE_SITE_URL` | Your site, for example `https://your-company.atlassian.net` |

## Rules

- **Cloud only.** The wrapper exits with status 3 on any site URL that does not end in `.atlassian.net`. Server and Data Center do not work through `confluence-as`. Use the Atlassian MCP transport, invoked explicitly. The hub does not fall back on its own.
- **Bulk operations run a dry run first.** With ten or more pages you see the plan before anything changes.
- **The implementation pipeline does not write back.** `mk:cook` reads Confluence specs and does not update Confluence pages when it ships.
- **Spec analysis is read-only on the Confluence side.** `mk:confluence-spec-analyst` writes a report in your repo, not a comment on the page.

## Find the right skill

| What you want to do | Skill |
|---|---|
| Get, create, update, delete, copy, move, or version a page | [`mk:confluence-page`](/reference/skills/confluence-page) |
| Search with CQL, list spaces, export results | [`mk:confluence-search`](/reference/skills/confluence-search) |
| Pull requirements, gaps, and suggested stories out of a spec | [`mk:confluence-spec-analyst`](/reference/skills/confluence-spec-analyst) |
| Label, move, or delete ten or more pages | [`mk:confluence-bulk`](/reference/skills/confluence-bulk) |
| Comments, attachments, labels, watchers | [`mk:confluence-collaborate`](/reference/skills/confluence-collaborate) |

Labels, comments, attachments and watchers belong to `mk:confluence-collaborate`, even when they apply to a single page. `mk:confluence-page` does not handle them.

## When it goes wrong

**The wrapper exits with status 3.** `MEOW_CONFLUENCE_SITE_URL` does not end in `.atlassian.net`. This is the Cloud-only check. Server and Data Center need the MCP transport.

**A page fetch returns something that does not look like the page.** Confluence stores content as ADF and MeowKit converts it to Markdown. Panels, expands, mentions, emoji, media, decisions and task lists convert lossily, and saving a page after an update can flatten them. Fetch the raw page by ID to check what the source holds.

**`mk:planning-engine` will not accept your spec.** It takes `--spec <report-path>` pointing at a spec-analyst report, not at a Confluence URL. Run `mk:confluence-spec-analyst` first, then pass the path it gives you.
