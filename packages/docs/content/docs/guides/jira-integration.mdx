MeowKit talks to Jira through the `jira-as` CLI, not through your browser session or a hosted service. This page covers the one-time setup, the rules for writes, and how to find the skill you want.

## Set it up

Install the CLI into the `jira` skill's own environment. Every `mk:jira-*` skill uses it, and there is no global install:

```bash
mewkit skill env jira
```

That puts `jira-as` at `.meowkit/envs/jira/bin/jira-as`. Then put three values in `.meowkit/.env`, which is gitignored, or in `~/.meowkit/.env` to share them with every project:

| Variable | What it is |
|---|---|
| `MEOW_JIRA_API_TOKEN` | An Atlassian Cloud API token. Create one at [id.atlassian.com](https://id.atlassian.com/manage-profile/security/api-tokens) |
| `MEOW_JIRA_EMAIL` | The Atlassian account that token belongs to |
| `MEOW_JIRA_SITE_URL` | Your site, for example `https://your-company.atlassian.net` |

Start a session. The `jira-env-loader.cjs` hook checks the file and prints `[mk:jira] env OK`, or names the missing key, so you find out at session start rather than mid-task. The wrapper translates `MEOW_JIRA_*` into the native `JIRA_*` variables for each call, so your shell never needs them.

The full variable list is in [Environment Variables](/reference/environment-variables#jira).

## Rules for writes

Read operations run without ceremony. Writes follow these rules:

- **Bulk operations run a dry run first.** Anything touching ten or more issues shows you the plan before it changes anything.
- **No automatic fallback.** If `jira-as` cannot run, the router stops and tells you. It does not switch transport.
- **The router never executes.** `mk:jira` picks a skill and hands off. A leaf skill with its own agent does the work.
- **Your token scope is the limit.** MeowKit can do nothing in Jira that your API token cannot, so a read-only token makes the integration read-only.

If your tenant needs mTLS, or you run multiple Atlassian profiles, `jira-as` will not work. In that case the leaves accept Atlassian MCP as an alternative transport:

```bash
claude mcp add --transport http atlassian https://mcp.atlassian.com/v1/mcp
```

You invoke the leaf with that transport explicitly.

## Find the right skill

Ask for what you want and `mk:jira` routes you, or invoke the skill directly:

| What you want to do | Skill |
|---|---|
| Get, create, update, or delete one issue | [`mk:jira-issue`](/reference/skills/jira-issue) |
| Find issues, export them, work with filters | [`mk:jira-search`](/reference/skills/jira-search) |
| Move an issue through its workflow, assign, resolve | [`mk:jira-lifecycle`](/reference/skills/jira-lifecycle) |
| Comments, attachments, watchers, notifications | [`mk:jira-collaborate`](/reference/skills/jira-collaborate) |
| Links, blockers, dependencies | [`mk:jira-relationships`](/reference/skills/jira-relationships) |
| Worklogs, time tracking, reports | [`mk:jira-time`](/reference/skills/jira-time) |
| Epics, sprints, backlog, story points | [`mk:jira-agile`](/reference/skills/jira-agile) |
| Custom fields: discovery and configuration | [`mk:jira-fields`](/reference/skills/jira-fields) |
| Ten or more issues at once | [`mk:jira-bulk`](/reference/skills/jira-bulk) |
| Service Management: queues, SLAs, customers | [`mk:jira-jsm`](/reference/skills/jira-jsm) |
| Projects, users, groups, schemes | [`mk:jira-admin`](/reference/skills/jira-admin) |
| Branch names, PRs, git integration | [`mk:jira-dev`](/reference/skills/jira-dev) |
| Cache and project-context discovery | [`mk:jira-ops`](/reference/skills/jira-ops) |
| Judge whether a ticket is ready to work on | [`mk:jira-evaluator`](/reference/skills/jira-evaluator) |
| Estimate story points | [`mk:jira-estimator`](/reference/skills/jira-estimator) |
| Analyse a ticket's context and attachments, root-cause it | [`mk:jira-analyst`](/reference/skills/jira-analyst) |

## When it goes wrong

**`[mk:jira] MEOW_JIRA_SITE_URL missing` at session start.** The variable is in none of the places the loader looks: a shell export, `.meowkit/.env`, `.claude/.env` or `~/.meowkit/.env`. The message names the files it found.

**Authentication fails with all three variables set.** Atlassian API tokens are tied to the account that created them. Confirm `MEOW_JIRA_EMAIL` is that account, not a shared or admin address.

**A transition is rejected as invalid.** Jira workflows differ per project, and a status that exists in one may not be reachable from the current one in another. The jira skills fetch the project's real workflow and cache it in `tasks/jira-workflows/`, so check the cached file for the transitions that are valid.

**Everything reads fine but nothing writes.** Usually token scope. Check what the token's account can do in the Jira UI.
