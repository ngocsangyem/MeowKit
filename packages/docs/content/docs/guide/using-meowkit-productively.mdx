---
title: "Using MeowKit Productively"
description: "Hand off checks, stop conditions and triggers to the workflow, and keep the memory store current so each session starts with what the last one learned."
---

The MeowKit workflow is a loop: gather context, act, verify, repeat. You get more from it by handing off parts of that loop than by typing prompts faster. This page lists which part to hand off, what to use for it, and how to keep memory useful.

| You hand off | Use it when | Reach for |
|---|---|---|
| The check | You are exploring or deciding | `mk:verify`, `mk:evaluate`, `mk:review` |
| The stop condition | You know what done looks like | `/goal` with `mk:verify`, `/mk:loop` |
| The trigger | Work happens outside your session | `/loop`, `/schedule` (host runtime) |
| The knowledge | A lesson should outlive the session | `.meowkit/memory/`, `mewkit trace` |

`/goal`, `/loop` and `/schedule` are loop primitives of the host runtime, in recent Claude Code releases. MeowKit supplies the deterministic checks and the recurring jobs that make them useful.

## Size the task first

Do not run the full pipeline when you do not need it.

- A trivial edit (rename, typo, format) is classified TRIVIAL and routed to the cheapest model. Do not invoke `/mk:cook` for a one-line change.
- A bug with a known cause in two files or fewer can take `/mk:fix --quick`, which writes no plan.
- When scale-routing returns `workflow=one-shot` and the blast radius is zero, a separate plan can be skipped. Add your project's safe fast-path domains to `domain-complexity.csv` so routing keeps matching your repository.
- Everything else gets a plan agreed first, which costs less than reworking the wrong build.

## Hand off the stop condition

Phase 3.6 (`mk:verify`) is a deterministic check: build, lint, type-check, tests and coverage pass or they do not. A goal loop can check that without judgment, so the agent keeps going instead of declaring "good enough".

```bash
/goal run /mk:cook for the agreed plan; do not stop until mk:verify
passes with zero failures. Stop after 5 tries.
```

Always set a try cap. Autobuild caps its generator and evaluator loop at 3 rounds before it asks you what to do. For a number such as coverage, bundle size or lint count, use `/mk:loop`. It runs bounded, git-tracked trials and keeps or reverts each change by the measured delta.

## Hand off the trigger

The workflow ends at Phase 5 with a pushed PR, but CI results and review comments arrive on someone else's schedule. Instead of polling:

```bash
/loop 15m check the open PR: address review comments with mk:respond-pr,
fix failing CI. Stop when the PR is merged.
```

`mk:respond-pr` triages each reviewer comment and then accepts it, pushes back or replies, so the loop does not accept every suggestion blindly.

## Schedule recurring maintenance

These jobs are mechanical and measurable, so `/schedule` suits them:

| Job | Command | Cadence |
|---|---|---|
| Propose stale memory entries for removal | `/mk:memory --prune` | Monthly |
| Review the friction backlog | `mewkit trace propose` | Weekly |
| Check that `SKILL.md` bodies stay under 500 lines | Rule 3 in the skill-authoring rules | Quarterly |
| Dead-weight audit (maintainers, source repository) | `/mk:benchmark run --full` and compare | Each model upgrade and quarterly |

Scheduled routines run in a cloud environment that does not inherit your local shell. Check that credentials such as Jira tokens and `MEOWKIT_*` variables are configured there first.

## Write memory while you work

The store is two committed files, `.meowkit/memory/decisions.md` and `gotchas.md` (see [Memory system](/guide/memory-system)). There is no capture hook and no prefix syntax. When you learn something, say so, and the running skill appends the entry.

```md
## Advisory lock, not row lock, for team reassignment   <!-- 2026-11-01 -->
Why: the row lock deadlocked under two concurrent reassigns (seen in CI, 3 runs)
Apply when: adding any concurrent write path to team membership
Source: PR #412
```

- **Write only what the next session cannot derive** from the code, the git log, the plan or the ADR.
- **No secrets and no vulnerability detail.** The store is committed and read back as data. Security findings stay in `mk:cso` reports and review verdicts. `mewkit validate --memory` checks this and a 300-line cap per file.
- **Prune on a schedule.** `/mk:memory --prune` proposes removing entries whose `Source` no longer exists and entries older than 180 days with no recent match, and you approve each one. Agents read stale entries as current.

Reading is one grep, run by `mk:fix`, `mk:investigate`, `mk:review`, `mk:plan-creator` and `mk:cso`:

```bash
grep -rilE "payment|retry|idempotency" .meowkit/memory/
```

If that keeps returning nothing for topics you know were decided, no entries are being written. The fix is the habit.

## Record friction

When a loop stalls or you correct the agent by hand, record it:

```bash
mewkit trace --friction "evaluator passed a build with broken auth flow"
```

`mewkit trace propose` groups friction that repeats (2 or more times) into advisory backlog items. When an item traces back to one skill, that skill's Gotchas section is the place to encode the fix.

## Cadence

| When | Do |
|---|---|
| During a task | Ask for the non-derivable lesson to be written as soon as you learn it |
| After you correct the agent | `mewkit trace --friction "<note>"` |
| Weekly | `mewkit trace propose` |
| Monthly | `/mk:memory --prune` |
| Each model upgrade | Dead-weight audit with `/mk:benchmark` (maintainers) |
