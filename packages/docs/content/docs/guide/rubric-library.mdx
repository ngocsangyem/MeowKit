## What Rubrics Do

Without rubrics, "is this build good?" is a judgment call, and the evaluator drifts toward leniency over a long session. A rubric turns one dimension, such as `functionality`, into graded terms. It states what PASS, WARN and FAIL look like with concrete anchor examples, and it has a default weight. The evaluator loads a composition preset for the project type, grades each rubric independently, and combines the weighted scores into an overall verdict.

If any single rubric reaches its hard-fail threshold, the sprint verdict is FAIL, so averaging cannot cover a broken happy path.

## Anatomy of a Rubric

Every file in `.claude/skills/rubric/rubrics/` follows `schema.md` and contains:

| Section | Purpose |
|---|---|
| YAML frontmatter | `name`, `version`, `weight_default`, `hard_fail_threshold`, `applies_to` |
| `## Intent` | Plain-language goal of the dimension |
| `## Criteria` | Bullet list of what the evaluator checks |
| `## Grading` | PASS / WARN / FAIL definitions |
| `## Anti-patterns` | Fixed list of auto-FAIL signatures (see below) |
| `## Few-Shot Examples` | ≥1 PASS anchor + ≥1 FAIL anchor with reasoning |

Rule 1 of `.claude/skills/rubric/references/rubric-rules.md` requires at least one PASS and one FAIL anchor in every rubric. A rubric with only PASS examples produces an evaluator that defaults to PASS. Rule 5 alternates the anchors, so Example 1 is PASS, Example 2 is FAIL, and so on, which reduces recency bias.

## The 7 Core Rubrics

| Rubric | Default weight | Hard-fail | Applies to |
|---|---|---|---|
| `product-depth` | 0.25 | FAIL | frontend, backend, fullstack, cli |
| `functionality` | 0.25 | FAIL | all project types |
| `design-quality` | 0.15 | FAIL | frontend, fullstack |
| `originality` | 0.15 | FAIL | frontend, fullstack |
| `code-quality` | 0.10 | FAIL | all project types |
| `craft` | 0.05 | WARN | frontend, backend, fullstack, cli |
| `ux-usability` | 0.05 | WARN | frontend, fullstack, cli |

Weights sum to 1.00 when all 7 are loaded. Rule 2 requires every preset to sum to 1.0, within 0.01.

## Composition Presets

Presets assemble rubric subsets appropriate for the project type. Files live at `.claude/skills/rubric/rubrics/composition-presets/`.

| Preset | Loads | Excludes | Use for |
|---|---|---|---|
| `frontend-app` (v2.0.0) | product-depth, functionality, design-quality, originality | code-quality, craft, ux-usability | SPAs, MPAs, framework apps |
| `backend-api` | product-depth, functionality, code-quality | design-quality, originality, craft, ux-usability | Headless APIs, services, workers |
| `cli-tool` | functionality, product-depth, code-quality, ux-usability | design-quality, originality, craft | CLI binaries, npm CLIs |
| `fullstack-product` | All 7 rubrics (ux-usability weighted 3×) | none | End-to-end product builds |

`frontend-app` loads 4 rubrics because `code-quality`, `craft` and `ux-usability` overlap other MeowKit layers: the `mk:review` verdict, `security-rules.md` and the `mk:qa` health score. The three excluded rubrics are opt-in through a custom preset (Rule 8).

## PASS / WARN / FAIL Anchors

Anchor examples show the evaluator what a FAIL actually looks like for that dimension. Rule 4 sets the balance:

- Fewer than 4 anchors: PASS and FAIL counts may differ by one, for example 2 PASS and 1 FAIL.
- 4 or more anchors: the counts must be equal, such as 2 and 2 or 3 and 3.

`validate-rubric.sh` enforces both. The schema notes that balanced examples reduce positive bias by 40 to 60 percent in Anthropic's harness research.

## Hard-Fail Propagation

Under Rule 3, a rubric whose verdict reaches its `hard_fail_threshold` fails the whole sprint, whatever the other rubrics scored. A build can pass every rubric but `functionality`, have a weighted average of 0.85, and still be FAIL. Every rubric today uses `FAIL` as the threshold except `craft` and `ux-usability`, which use `WARN`, so a WARN on those two also fails the sprint.

## Calibration Set and Drift Check

`.claude/skills/rubric/rubrics/calibration-set/` is where gold-standard verdicts for the drift check live. Its README describes the procedure. Rule 6 says that when a new model tier ships, the set is replayed with the new model, and agreement with the stored verdicts must stay within 5 percent per rubric. If drift exceeds 5 percent, recalibrate the anchors or adjust the `hard_fail_threshold`.

## Anti-Slop Anti-Patterns

`originality.md` and `design-quality.md` include fixed anti-pattern lists. Under Rule 7, a match fails the criterion whatever the build scores elsewhere. The lists are fixed so grading does not depend on taste. Examples from `originality.md`:
- Product name = literal feature description (`KanbanApp`, `NoteApp`, `ChatApp`)
- Hero copy: "The modern way to `{feature}`" / "Beautifully simple `{noun}`" / "Built for teams"
- unDraw / Storyset stock illustrations on empty states
- Stripe-clone homepage layout (centered hero, 3-column features, testimonials, CTA)
- Default or missing favicon
- "Built with love by the `{ProductName}` team" footer

## Custom Rubrics

Users can add their own rubric files to `.claude/skills/rubric/rubrics/` (Rule 9). Requirements:

1. Conform to `schema.md`
2. Run `validate-rubric.sh path/to/new-rubric.md`, which checks anchor balance, weights and injection safety
3. Reference the rubric from a composition preset (re-validate weight sum after adding)
4. Add a row to `RUBRICS_INDEX.md`

## Rubric Files Are DATA

Per `injection-rules.md`, the evaluator loads rubric files as data, not instructions. Under Rule 10, `validate-rubric.sh` rejects instruction-like patterns such as "ignore previous instructions" in rubric text.

A poisoned rubric could otherwise inject prompt overrides through the anchor-reasoning sections.
