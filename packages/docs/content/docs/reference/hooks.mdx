MeowKit uses lifecycle hooks for the few checks it enforces (the ship check, sensitive-file protection, the post-write scan) and for observers. Planning and review are not hooks; see [Enforcement & Security](/core-concepts/gates). Some hooks are registered in `.claude/settings.json` (automatic), others are invoked by skills.

## Registered hooks (automatic)

These run automatically via Claude Code's hook system:

| Hook                   | Type        | Trigger     | What it does                                                                              | Blocks?      |
| ---------------------- | ----------- | ----------- | ----------------------------------------------------------------------------------------- | ------------ |
| `post-write.cjs`        | PostToolUse | Edit, Write | Security scan: secrets, `any` type, SQL injection, XSS, destructive patterns              | Yes (exit 2) |
| `learning-observer.cjs` | PostToolUse | Edit, Write | Detect churn patterns (file edited 3+ times); feeds into post-session retroactive capture | No           |
| `post-session.cjs`      | Stop        | Session end | Record session data to `.meowkit/telemetry/`                                                 | No           |
| `tdd-flag-detector.cjs`  | UserPromptSubmit | Prompt submit | Detects `--tdd` flag in user prompts, writes sentinel to `.meowkit/state/tdd-mode`      | No           |
| `privacy-block.cjs`      | PreToolUse     | Read, Edit, Write, Bash | Blocks reads/writes of sensitive files (.env, keys, credentials, SSH) and SSRF-vulnerable web fetches | Yes (exit 2) |
| `pre-ship.cjs`           | PreToolUse     | Bash         | Ship check on `git commit`, `git push`, `git merge` and `gh pr create\|merge`: lint on changed files, their related tests, and a type-check | Yes (exit 2) |
| `project-context-loader.cjs` | SessionStart | Session start | Loads project context, directory listing, tool availability, package scripts, preferences, and agent readiness score | No           |

## Telemetry probes

These hooks are telemetry-only — they log event fires to verify Claude Code supports the corresponding hook event types. They never block and always exit 0. Replace with real handlers once event support is confirmed.

| Probe                         | Event               | Purpose                                                                 |
| ----------------------------- | ------------------- | ----------------------------------------------------------------------- |
| `control-probe.cjs`            | Stop                | Control signal — confirms Stop event fires reliably, providing a baseline for comparing PreCompact/PostToolUseFailure probe fire rates |
| `posttoolfailure-probe.cjs`    | PostToolUseFailure  | Logs PostToolUseFailure hook fires to verify CC supports the event      |

### `precompact-probe.cjs` — safety-baseline re-arm

`precompact-probe.cjs` (PreCompact) is no longer telemetry-only. It still logs the event fire, then appends a re-arm marker to `.meowkit/state/session-sentinels.jsonl` for the active session. Compaction drops the safety-baseline rule text from context but leaves the per-session "verified" marker intact, so the re-arm marker invalidates that cached verification and the next turn re-reads the safety baseline. The cached-skip resumes only once a genuine re-read writes a newer verification. The hook never blocks (exit 0 on all paths) and no-ops when no session id is present.

## Hook runtime profiling

The `MEOWKIT_HOOK_PROFILE` environment variable controls which hooks are active. Set it in your `.env` file or shell before starting a Claude Code session.

| Profile    | Hooks Active                                                                | Use When                              |
| ---------- | --------------------------------------------------------------------------- | ------------------------------------- |
| `strict`   | All hooks                                                                   | COMPLEX tasks, security-critical work |
| `standard` | All except `post-session.cjs`                                                | Default — everyday development        |
| `fast`     | `privacy-block.cjs`, `pre-ship.cjs`, `project-context-loader.cjs` only | Rapid iteration, prototyping          |

```bash
# Set in .env or shell
MEOWKIT_HOOK_PROFILE=fast
```

## Hook configuration

Hooks are registered in `.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node .claude/hooks/handlers/post-write.cjs \"$TOOL_INPUT_FILE_PATH\""
          }
        ]
      },
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node .claude/hooks/handlers/learning-observer.cjs \"$TOOL_INPUT_FILE_PATH\""
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "node .claude/hooks/handlers/post-session.cjs" }
        ]
      }
    ]
  }
}
```

## JSON-on-stdin Convention

All meowkit hooks read input as JSON on stdin (per [Claude Code hook docs](https://code.claude.com/docs/en/hooks)), parsed by the shared reader `lib/parse-stdin.cjs`. It returns `toolName`, `filePath`, `command`, `sessionId`, `eventName`, `transcriptPath` and the raw payload. Write guards use its `readHookInput` form, which also reports *why* input was unreadable so the guard can refuse rather than wave the call through; observers receive the same payload from the dispatcher. Hooks still honour a legacy `$1` positional argument for back-compat — both forms coexist safely.

## Shared Hook Libraries

Node modules in `.claude/hooks/lib/`, loaded with `require()`. They are not hooks themselves.

- `lib/parse-stdin.cjs` is the JSON-on-stdin parser. It reads all of stdin, parses it, and resolves a relative `tool_input.file_path` against the working directory.
- `lib/secret-scrub.cjs` is the shared secret redaction. It covers Anthropic, OpenAI, AWS, GitHub, GitLab, Slack, JWT and PEM patterns, and hooks that persist content (`append-trace.cjs`) call it before writing.

### `lib/core`

`lib/core/` holds the decisions that the write, read and shell guards share across runtimes: `privacy.cjs` (sensitive paths and unsafe fetch targets), `pre-ship.cjs` (the ship-boundary checks) and `completion-check.cjs` (the opt-in completion check). Each module is a pure decision. It reads the project tree but never touches stdin, stdout or the exit code, and returns `{ exit, stdout, stderr }`, where exit 2 is a block. Claude Code's `privacy-block.cjs` and `pre-ship.cjs` wrap these modules, and the Codex and Cursor hook files call the same code, so a change to a decision reaches every runtime that carries it.

### Runtime parity

Codex and Cursor do not run every Claude Code hook. `.claude/hooks/hook-coverage.json` records what each safety behaviour and each handler becomes on the other two runtimes, and a test checks that every one appears there.

| Behavior | Claude Code | Codex | Cursor |
| --- | --- | --- | --- |
| Privacy block | `privacy-block.cjs` | Ported, Bash only: Codex has no file-read hook, so the decision runs on the shell command and the paths it names | Ported: `privacy-read-gate.cjs` on `beforeReadFile` |
| Ship check | `pre-ship.cjs` | Ported: `.codex/hooks/pre-ship.cjs` on `PreToolUse` Bash | Ported: `.cursor/hooks/pre-ship.cjs` on `beforeShellExecution` |
| Session context | `project-context-loader.cjs` | Not ported: `AGENTS.md` carries the standing context | Equivalent: `session-context.cjs`, a short pointer to `.meowkit/` state |

Of the 21 handlers in `handlers.json`, most are Claude Code only. Cursor's `telemetry-observers.cjs` covers `learning-observer`, `post-session`, `precompact-probe` and `posttoolfailure-probe`, and its `stop-followup.cjs` stands in for `pre-completion-check` without blocking. Codex gets the `capability-bootstrap` text through `AGENTS.md` at migrate time.

## Middleware Hooks

### `build-verify` (handler)

Fires on **PostToolUse Edit|Write** via `dispatch.cjs`. Classifies the written file by extension (`ts/tsx` → `tsc --noEmit\|eslint`; `js` → `eslint`; `py` → `ruff check\|mypy`; `go` → `go build ./...`; `rs` → `cargo check`; `rb` → `ruby -c\|rubocop`). On a failure it exits 2 and writes a `@@BUILD_VERIFY_ERROR@@ … @@END_BUILD_VERIFY@@` block to stderr, the PostToolUse form Claude Code shows to the model; the edit itself is already saved. Results cached by file content hash — unchanged files are skipped. Skips `node_modules/`, `vendor/`, `dist/`, `tasks/`, `docs/`, `.claude/`, test files, and map/lock files.

- **Opt-out:** `hooks.build-verify: false`
- **Timeout override:** `buildVerify.timeoutMs` (default 30s for TS; 35s hook registration timeout)
- **Density:** runs in LEAN; skipped in MINIMAL (`autobuild.mode: MINIMAL`)
- **Source:** `handlers/build-verify.cjs` (dispatched via `dispatch.cjs`)

### `loop-detection` (handler)

Fires on **PostToolUse Edit|Write** via `dispatch.cjs`. Counts per-file edits keyed `{session_id}:{realpath}` in `.meowkit/state/edit-counts.json`. Reminds the model at 4 edits, asks it to re-plan at 8, and repeats every 4 edits after, as `hookSpecificOutput.additionalContext` (the model-visible PostToolUse field). Never blocks.

- **Opt-out:** `hooks.loop-detection: false`
- **Timeout:** 3s
- **Source:** `handlers/loop-detection.cjs` (dispatched via `dispatch.cjs`)

### `pre-completion-check.cjs`

Fires on the **Stop** event (not SubagentStop). Opt-in: it does nothing unless `hooks.pre-completion-check: true` is set. When on, a stop with files changed since the session's last passing test, build, lint or type-check run is answered with a `{"decision":"block","reason":"…"}` JSON that Claude Code feeds back as the next turn. After two reminders the session ends with a notice. This is evidence of effort, not proof: a trivial passing command satisfies it.

- **Opt-in:** `hooks.pre-completion-check: true`
- **Timeout:** 5s
- **Source:** `.claude/hooks/handlers/pre-completion-check.cjs`

## Node.js Dispatch System

`dispatch.cjs` is a central Node.js dispatcher registered in `settings.json` alongside the write guards. It reads `handlers.json` at runtime and dispatches to handler modules sequentially for each event.

**Usage in settings.json:**
```
node dispatch.cjs <EventName> [Matcher]
```

**Graceful degradation:** if `handlers.json` is missing or a handler throws, `dispatch.cjs` exits 0 — it never blocks Claude Code.

**Security note:** `privacy-block.cjs` and `pre-ship.cjs` are intentionally outside the dispatcher. They stay as independent entries in `settings.json`.

|---------|------|-------|---------|-------------------|--------|
| model-detector | `handlers/model-detector.cjs` | SessionStart | — | `model` | Writes `.meowkit/state/detected-model.json`; stdout model tier line |
| orientation-ritual | `handlers/orientation-ritual.cjs` | SessionStart | — | — | Resumes from checkpoint if exists |
| build-verify | `handlers/build-verify.cjs` | PostToolUse | Edit\|Write | `tool_input.file_path` | Runs compile/lint; cached by file hash |
| loop-detection | `handlers/loop-detection.cjs` | PostToolUse | Edit\|Write | `tool_input.file_path` | Warns at 4 edits, escalates at 8 |
| budget-tracker | `handlers/budget-tracker.cjs` | PostToolUse | Edit\|Write, Bash | `tool_input`, `tool_response` | Estimates cost; warns $30, blocks $100 |
| auto-checkpoint | `handlers/auto-checkpoint.cjs` | PostToolUse | Edit\|Write | `tool_input.file_path` | Checkpoint every 20 calls |
| checkpoint-writer | `handlers/checkpoint-writer.cjs` | Stop | — | — | Sequenced checkpoint with git state |
| capability-bootstrap | `handlers/capability-bootstrap.cjs` | SessionStart | — | — | Emits the committed capability-resolution guidance; silent when the file is absent |
| jira-env-loader | `handlers/jira-env-loader.cjs` | SessionStart | — | — | Reports whether the Jira credentials are present; never prints or exports them. The only handler that reads the project dotenv |

## Bypasses

Observer switches live in `.meowkit/config.yaml`. The two environment names below
stay environment-only on purpose: `pre-ship.cjs` is a safety entrypoint and reads
no config file, and the density override is read by the sprint-contract step.

| Setting                             | Effect                                                                |
| ----------------------------------- | --------------------------------------------------------------------- |
| `hooks.build-verify: false`         | Skip `build-verify` handler                                            |
| `hooks.loop-detection: false`       | Skip `loop-detection` handler                                          |
| `hooks.pre-completion-check: true`  | Turn on `pre-completion-check.cjs` (off by default)                    |
| `autobuild.mode: MINIMAL`           | Skip BuildVerify                                                      |
| `MEOWKIT_HOOK_PROFILE=fast`         | Skip `post-session`, `learning-observer` (speed); `pre-ship` still runs          |
| `MEOWKIT_AUTOBUILD_MODE=LEAN`       | Autobuild skips the sprint contract (no hook checks it)               |
