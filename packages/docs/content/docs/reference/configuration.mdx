MeowKit reads settings from these places:

| Place | Holds | Committed |
| --- | --- | --- |
| `.claude/rules/` | The six always-on rules | Yes |
| `.meowkit/config.yaml` | Project settings: TDD, budget, density, hook switches | Yes |
| `.claude/settings.json` | Hook registrations | Yes |
| `.meowkit/.env` | API keys and personal overrides | No |
| Shell environment | A few overrides and per-run values | No |

## .claude/rules/

`.claude/rules/` holds the six rules Claude Code loads at session start: `meowkit-core.md`, `security-rules.md`, `injection-rules.md`, `core-behaviors.md`, `development-rules.md` and `agent-conduct.md`. `meowkit-core.md` carries the role, the workflow, the ship check in brief, the boundary between data and instructions, the memory contract and the compaction policy. All other rules load from the `references/` folder of the skill that owns them ([Rules Index](/reference/rules-index) maps each one).

MeowKit installs no root `CLAUDE.md`. A project may keep its own, and the kit never installs, refreshes or overwrites it. Put project conventions in your own `CLAUDE.md` or in `docs/project-context.md`, because `mewkit upgrade` refreshes the kit's rule files. Do not edit the security and injection rules.

## .meowkit/config.yaml

The project config lives in `.meowkit/` with the project's other MeowKit state. The kit ships it with every setting commented out, so the committed file lists only the choices your project makes. The file has two levels of keys with boolean, whole-number or string values. An unknown key is an error, and there is no `gates.` or `paths.` key at any scope.

Resolution order for a key is: environment override (only `MEOWKIT_TDD`), then project config, then user config (`~/.meowkit/config.yaml`), then the default.

Commit this file and `.meowkit/memory/*.md`, since the team memory store is reviewed in the PR diff. Commit `.meowkit/state/ownership/*.json` as well: it records which files the kit installed, and a clone without it cannot tell the kit's files from yours. The rest of `.meowkit/` (`telemetry/`, the other files in `state/`, `cache/`) is machine-written and stays out of git.

```yaml
# .meowkit/config.yaml
tdd: false

budget:
  warn: 30     # USD, prints a warning
  block: 100   # USD, prints an over-budget notice (advisory)

hooks:
  build-verify: false   # switch one observer off
```

### Keys

| Key | Default | Purpose |
| --- | --- | --- |
| `tdd` | `false` | Strict test-first mode. `MEOWKIT_TDD` in the environment outranks it |
| `autobuild.mode` | auto-detected | Scaffolding density for `mk:autobuild`: `MINIMAL`, `FULL` or `LEAN`. It sets scaffolding only. `LEAN` makes the sprint contract optional, and the ship check runs in every mode. `MEOWKIT_AUTOBUILD_MODE` in the environment is also read |
| `budget.warn` | `30` | USD at which the first cost notice prints |
| `budget.block` | `100` | USD at which the over-budget notice prints. Advisory: nothing is stopped |
| `budget.cap` | none | Overrides `budget.block`, lower or higher |
| `buildVerify.timeoutMs` | per language | Timeout for each `build-verify` command, in milliseconds |
| `projectContext.maxBytes` | `12288` | Size above which the project-context file warns; `0` disables the warning |
| `workflow.telemetry` | `off` | `off`, `community` or `anonymous` |
| `workflow.proactive` | none | Whether skills volunteer suggestions |
| `hooks.<name>` | `true` | `false` switches one observer off; see below |

### Hook switches

`hooks.<name>: false` turns one observer off. The name is the handler's file base name (`build-verify`, `loop-detection`, `post-write`, `learning-observer`, `tdd-flag-detector` and the rest of the 23 listed in [Hooks](/reference/hooks)). The default is `true`, except `hooks.pre-completion-check`, which is off until you set it to `true`. These names are rejected in every config scope, and their hooks keep running: `privacy-block`, `pre-ship`, `check-careful`, `check-freeze` and `check-report-path`.

### Model routing

Model routing is set per agent, not in a config block. Each `.claude/agents/*.md` declares a `model:` of `opus`, `sonnet`, `haiku`, `fable` or `inherit`. For Codex and Cursor, `mewkit init` writes a concrete model id for each tier into the agent file. Grok and OMP agent prompts carry no `model`, and Pi has no subagents. [Agent Models](/guide/agent-models) lists the mapping and how to change a pin. There is no `modelRouting` key.

## .claude/settings.json

`settings.json` holds the hook registrations and the `CLAUDE_CODE_FORK_SUBAGENT=1` entry in its `env` block. That variable makes the `mk:jira-*` skills fork into their matching agents; leave it set. [Hooks](/reference/hooks) describes each registration. Every hook runs as `command: node` with an `args` list, so no shell parses the path.

## .meowkit/.env [#dotenv]

`.meowkit/.env` holds project-level secrets such as API keys, without touching your shell profile. No shell sources it and hooks do not load it. Only `jira-env-loader` (SessionStart) reads it, through `lib/load-dotenv.cjs`, and it only checks that the three `MEOW_JIRA_*` keys are present. The Jira wrapper script and the `mk:multimodal` Python scripts read the file themselves.

A variable already in the environment wins: the loader adds only keys that are not set, so `export VAR=x` overrides `.env` for a session. It refuses keys that change how a process launches (`PATH`, `LD_PRELOAD`, `BASH_ENV` and similar).

```bash
cp .meowkit/.env.example .meowkit/.env
# edit .meowkit/.env with your values
```

`.env` is gitignored by default, and the `privacy-block.cjs` hook blocks the agent from reading it. `.meowkit/.env.example` lists every supported variable with a description.

## Environment variables

Set these in your shell profile or per session with `export`.

| Variable | Default | Purpose |
| --- | --- | --- |
| `MEOWKIT_TDD` | off | Strict test-first mode. Truthy values: `1`, `true`, `yes`, `on`, `enable`, `enabled` (any case). Falsy values: `0`, `false`, `no`, `off`, `disable`, `disabled`. An unrecognized value is ignored with a warning. It outranks `tdd` in the config and the `--tdd` prompt flag |
| `MEOWKIT_MODEL_HINT` | none | Model id used for tier detection when SessionStart input has no `model` field. Read after the SessionStart `model` field and before `CLAUDE_MODEL`, `CLAUDE_MODEL_ID` and `ANTHROPIC_MODEL`. A Claude model name behind a non-Anthropic `ANTHROPIC_BASE_URL` is not trusted: the tier is unknown and density is FULL |
| `MEOWKIT_HOOK_PROFILE` | `standard` | `fast` makes `learning-observer`, `post-session` and `pre-task-check` do nothing. `standard` and `strict` behave the same. The legacy alias `MEOW_HOOK_PROFILE` still works, and the new name wins when both are set |
| `MEOWKIT_AUTOBUILD_MODE` | none | Density override for `mk:autobuild`: `MINIMAL`, `FULL` or `LEAN`. Also settable as `autobuild.mode` |
| `MEOWKIT_RUN_ID` | none | A per-run id set by `mk:autobuild` and read by the trace log |
| `MEOWKIT_PM_AUTO` | on | `off` stops the project-manager agent from running silently after a phase; `/mk:status` still works |
| `MEOWKIT_SKIP_SAFETY_SENTINEL` | `on` | `off` makes every turn re-read the safety baseline instead of using the cached-verification marker |
| `HOOK_SESSION_ID` | none | The session id that `mewkit budget --session` reads first, before `.meowkit/state/last-session-id` |

The settings that older releases read from `MEOWKIT_*` variables (budget thresholds, hook switches, the project-context size, `MEOWKIT_GATE1_PRESENCE_ONLY` and others) are read from nowhere now. `mewkit doctor` reports any of those names still exported in your shell and names the config key that replaced it, when there is one.

### Jira

The `mk:jira-*` skills (a router and 16 leaves) use three variables in `.meowkit/.env`. The wrapper `.claude/skills/jira/scripts/jira-as.sh` translates them into the `JIRA_*` names that `jira-as` reads. They keep the `MEOW_` prefix on purpose.

| Variable | Purpose |
| --- | --- |
| `MEOW_JIRA_API_TOKEN` | Atlassian Cloud API token, from [id.atlassian.com](https://id.atlassian.com/manage-profile/security/api-tokens). Required |
| `MEOW_JIRA_EMAIL` | Atlassian account email. Required |
| `MEOW_JIRA_SITE_URL` | For example `https://your-company.atlassian.net`. Required |
| `JIRA_OUTPUT` | Output format for `jira-as`; the wrapper sets `json`. Override per call with `JIRA_OUTPUT=text bash .claude/skills/jira/scripts/jira-as.sh ...` |
| `JIRA_MOCK_MODE` | When `true`, agents mark their output `**[MOCK MODE]**` and the intelligence agents avoid live writes. For sandbox and CI use |

At session start `jira-env-loader` prints `[mk:jira] env OK` or `[mk:jira] <KEY> missing`. To set up:

```bash
mewkit setup               # installs jira-as into .meowkit/envs/jira/
cp .meowkit/.env.example .meowkit/.env
# edit MEOW_JIRA_API_TOKEN, MEOW_JIRA_EMAIL, MEOW_JIRA_SITE_URL
```

### Media keys

`.meowkit/.env.example` also lists the keys and model overrides for `mk:multimodal` and `mk:stitch` (`MEOWKIT_GEMINI_API_KEY`, `MEOWKIT_MINIMAX_API_KEY`, `MEOWKIT_OPENROUTER_API_KEY`, `STITCH_API_KEY`, the `MEOWKIT_*_PROVIDER_CHAIN` and `MEOWKIT_*_MODEL` variables). Read the comments in that file before setting one.

## Examples

A production session with TDD and every hook:

```yaml
# .meowkit/config.yaml
tdd: true
```

A quick prototyping session:

```yaml
# .meowkit/config.yaml
hooks:
  build-verify: false
```

```bash
export MEOWKIT_HOOK_PROFILE=fast
```

A high-budget autobuild run:

```yaml
# .meowkit/config.yaml
budget:
  cap: 200
# autobuild.mode stays unset, so density follows the detected model
```
