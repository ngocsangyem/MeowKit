MeowKit is configured through several files:

## .claude/rules/

The 7 always-on rules Claude Code auto-loads at session start. `meowkit-core.md` carries the
role, the 7-phase workflow, the two gates in brief, the DATA/INSTRUCTIONS boundary, the memory
contract and the compaction policy; the other six are `security-rules.md`,
`injection-rules.md`, `gate-rules.md`, `core-behaviors.md`, `development-rules.md` and
`agent-conduct.md`. Everything else loads just in time from the owning skill's `references/`
(see [Rules Index](/reference/rules-index)).

MeowKit installs no root `CLAUDE.md`. A project may keep its own; it is project-owned and
never installed, refreshed or overwritten by the kit.

**Customize:** project-specific conventions belong in your own `CLAUDE.md` or in
`docs/project-context.md`, not in the kit's rule files — `mewkit upgrade` refreshes those.
**Do not modify:** security rules, gate definitions, the injection boundary.

## .meowkit/config.json

Project configuration generated by `npx mewkit init`. It sits in `.meowkit/` with the rest of
the project's own state, rather than in a provider directory — `.claude/settings.json` and
`.mcp.json` stay under `.claude/` because Claude Code is what reads those.

Commit this file, and commit `memory/*.md` — the team memory store is reviewed in the PR diff.
The other `.meowkit/` subdirectories (`telemetry/`, `state/`, `cache/`) are machine-written and
belong in `.gitignore`.

```json
{
  "$schema": "https://meowkit.dev/schema/config.json",
  "version": "1.0.0",
  "project": { "description": "" },
  "features": { "costTracking": true, "memory": true }
}
```

### Model routing

Model routing is **per agent**, not a central config block — mirroring how each coding
agent selects its own model:

- **Claude Code** — each `.claude/agents/*.md` declares a `model:` in frontmatter (`opus`, `sonnet`, `haiku`, `fable`, or `inherit`).
- **Codex** — each authored agent TOML (`.codex/agents/*.toml`) carries `model_reasoning_effort`, derived from the source Claude tier (opus/fable → `xhigh`, sonnet → `high`, haiku → `medium`; `inherit` agents omit it and inherit Codex's default). `model` is left unset because Codex model ids are deployment-specific — pin one by editing the agent TOML or via a Codex [config profile](https://learn.chatgpt.com/docs/config-file/config-sample).

There is no `modelRouting` config key. When `mewkit migrate` converts a Claude agent whose
tier has no Codex model id, it discloses the source model as a commented hint and the target
inherits its own default. MeowKit never hardcodes target model IDs.

### dispatch.cjs entries (v2.3.0)

The following entries were added in v2.3.0 to route events to `dispatch.cjs`. They run alongside the existing shell hook entries — both shell and Node.js hooks fire on the same events:

```json
{
  "hooks": {
    "SessionStart": [{
      "hooks": [
        { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/dispatch.cjs\" SessionStart", "timeout": 10 }
      ]
    }],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/dispatch.cjs\" PostToolUse \"Edit|Write\"", "timeout": 40 }
        ]
      },
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/dispatch.cjs\" PostToolUse Bash", "timeout": 15 }
        ]
      }
    ],
    "Stop": [{
      "hooks": [
        { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/dispatch.cjs\" Stop", "timeout": 10 }
      ]
    }],
    "UserPromptSubmit": [{
      "hooks": [
        { "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/dispatch.cjs\" UserPromptSubmit", "timeout": 10 }
      ]
    }]
  }
}
```

`PostToolUse Edit|Write` has both `post-write.cjs` (shell, security scan) and `dispatch.cjs` entries. Both fire independently on every file write.

## .meowkit/.env File [#dotenv]

MeowKit loads `.meowkit/.env` automatically at session start. This is the recommended way to set project-level env vars (API keys, config overrides) without polluting your shell profile.

**How it works:**

1. `project-context-loader.cjs` (SessionStart) sources `.meowkit/.env` into the shell environment → all shell hooks inherit it
2. `dispatch.cjs` parses `.meowkit/.env` into `process.env` → all Node.js handlers inherit it
3. `mk:multimodal` Python scripts have their own `.env` loading (predates centralized loader)

**Precedence:** Shell exports (`export VAR=x`) **always win**. `.env` vars only apply when the var is not already set. This means you can override `.env` per-session with `export`.

**Setup:**
```bash
cp .meowkit/.env.example .meowkit/.env
# Edit .meowkit/.env with your values
```

**Security:** `.env` is gitignored by default. Never commit API keys. The `privacy-block.cjs` hook blocks Claude from reading `.env` files directly — the dotenv loader is the only authorized reader.

**Template:** See `.meowkit/.env.example` for all supported variables with descriptions.

## Environment Variables

All `MEOWKIT_*` env vars. Set in your shell profile (`~/.zshrc`, `~/.bashrc`) or per-session via `export`.

### Core

| Variable | Default | Purpose | When to use |
|----------|---------|---------|-------------|
| `MEOWKIT_TDD` | `off` | Enable strict TDD enforcement (RED-phase gate). Values: `1`, `true`, `on`, `enabled` | Production-quality code, payment/auth features. Opt-in — most users leave this off. |
| `MEOWKIT_MODEL_HINT` | *(none)* | Fallback model ID for tier detection when SessionStart stdin lacks `model` field | Only if `model-detector.cjs` shows "not detected". Most users don't need this — stdin auto-detection is primary since v2.3.0. |
| `MEOWKIT_HOOK_PROFILE` | `standard` | Hook execution profile. `standard` = normal, `fast` = skip non-critical hooks (post-session, learning-observer, pre-ship), `strict` = all hooks enabled. Legacy alias `MEOW_HOOK_PROFILE` still works; the new name wins when both are set | `fast` for rapid iteration/spike work. `strict` for production sessions needing the full hook chain. |
| `CLAUDE_CODE_FORK_SUBAGENT` | `1` (set in `settings.json` `env` block by default since v2.8.3) | Enables Claude Code's `context: fork` semantics so the 16 `mk:jira-*` thin skills fork into their matching agents. | Leave default. Unset only when explicitly debugging fork-mode behavior. |

### Jira

The `mk:jira-*` family (router + 16 leaves added in v2.8.3) is driven by three `MEOW_JIRA_*` env vars in `.meowkit/.env` (gitignored). The wrapper script `scripts/jira-as.sh` translates them to `jira-as`'s native `JIRA_*` names per call.

> **Naming exception**: these vars use the legacy `MEOW_*` prefix (one-off exception to the modern `MEOWKIT_*` convention) per migration directive. The upstream `JIRA-Assistant-Skills` README also mentions `JIRA_PROFILE` — that is a plugin-layer concern, NOT consumed by `jira-as` or `mk:jira`.

| Variable | Default | Purpose | Where to set |
|----------|---------|---------|--------------|
| `MEOW_JIRA_API_TOKEN` | *(required)* | Atlassian Cloud API token. Get from [https://id.atlassian.com/manage-profile/security/api-tokens](https://id.atlassian.com/manage-profile/security/api-tokens). | `.meowkit/.env` |
| `MEOW_JIRA_EMAIL` | *(required)* | Atlassian account email. | `.meowkit/.env` |
| `MEOW_JIRA_SITE_URL` | *(required)* | e.g. `https://your-company.atlassian.net`. | `.meowkit/.env` |
| `JIRA_OUTPUT` | `json` (set by wrapper) | Default output format for `jira-as`. | Override per-call: `JIRA_OUTPUT=text bash scripts/jira-as.sh ...` |
| `JIRA_MOCK_MODE` | *(unset)* | When set to `true`, agents surface `**[MOCK MODE]**` in output headers; intelligence agents avoid live writes. | Sandbox / CI testing. |

The SessionStart hook `jira-env-loader.cjs` validates `.meowkit/.env` presence + the 3 required keys. It emits `[mk:jira] env OK` / `[mk:jira] <KEY> missing` to the status line.

**Setup (one-time):**

```bash
npx mewkit setup           # auto-installs jira-as into .claude/skills/.venv
cp .meowkit/.env.example .meowkit/.env
# edit MEOW_JIRA_API_TOKEN, MEOW_JIRA_EMAIL, MEOW_JIRA_SITE_URL
```

### Harness (Autonomous Build Pipeline)

These are keys in `.meowkit/config.yaml`, not environment variables.

| Key | Default | Purpose | When to use |
|-----|---------|---------|-------------|
| `autobuild.mode` | *(auto-detected)* | Override scaffolding density: `MINIMAL` (Haiku), `FULL` (Sonnet/Opus 4.5), `LEAN` (Opus 4.6+) | When auto-detection picks wrong density. Does NOT bypass gates — a project config saying `LEAN` still faces the sprint-contract gate, and `mewkit doctor` says so. |
| `budget.warn` | `30` | USD threshold for budget warning message | Lower for cost-conscious sessions, higher for long research runs. |
| `budget.block` | `100` | USD threshold for hard session block | Emergency brake. Session halts at this amount. |
| `budget.cap` | *(none)* | User override for hard block — can be lower OR higher than `budget.block` | `budget.cap: 200` for intentional high-budget harness runs, `15` for tight budgets. |

`MEOWKIT_RUN_ID` stays in the environment: it is a per-invocation handoff set by
`mk:autobuild` step-00, which a committed file cannot carry.

### Memory

The team memory store is two committed markdown files at `.meowkit/memory/`. The read-set skills grep it when their task needs it; there is no per-turn auto-injection and no capture hook. Pruning is `/mk:memory --prune`, human-approved, with a fixed window and no setting. See [Memory System](/guide/memory-system) for details.

### Hook Controls

`hooks.<name>: false` in `.meowkit/config.yaml` disables one observer; the default is
`true`. The name is the observer's own file base name.

| Key | Purpose | When to use |
|-----|---------|-------------|
| `hooks.build-verify` | Skip post-write compile/lint checks | Bulk file generation where per-file verification is too slow. |
| `hooks.loop-detection` | Skip edit-count loop detection | Intentional multi-pass refactoring. |
| `hooks.pre-completion-check` | Skip the pre-completion verification check | The check blocks session exit incorrectly. |
| `hooks.tdd-flag-detector` | Disable `--tdd` detection in user prompts | `--tdd` in your prompt text triggers TDD unintentionally. |
| `buildVerify.timeoutMs` | Per-command timeout for build-verify, in milliseconds | A slow build needs longer than the per-language default. |

The seven safety names — `gate-enforcement`, `privacy-block`, `pre-ship`,
`gate2-check`, `check-careful`, `check-freeze`, `check-report-path` — are rejected from
every config scope with a validation error, and the hook keeps blocking.

### Examples

**Production session with TDD and strict hooks:**
```yaml
# .meowkit/config.yaml
tdd: true
```
```bash
export MEOWKIT_HOOK_PROFILE=strict
```

**Quick prototyping session:**
```yaml
# .meowkit/config.yaml
hooks:
  build-verify: false
```
```bash
export MEOWKIT_HOOK_PROFILE=fast
```

**High-budget harness run on Opus 4.6:**
```yaml
# .meowkit/config.yaml
budget:
  cap: 200
# autobuild.mode is left unset — it auto-detects LEAN for Opus 4.6
```
