MeowKit reads settings from these places:

| Place | Holds | Committed |
| --- | --- | --- |
| `.claude/rules/` | The six always-on rules | Yes |
| `.meowkit/config.yaml` | Project settings: TDD, budget, density, hook switches | Yes |
| `.claude/settings.json` | Hook registrations | Yes |
| `.meowkit/.env`, `~/.meowkit/.env` | API keys and integration settings, per project or for every project | No |
| Shell environment | Workflow switches and per-run values ([Environment Variables](/reference/environment-variables)) | No |

## .claude/rules/

`.claude/rules/` holds the six rules Claude Code loads at session start: `meowkit-core.md`, `security-rules.md`, `injection-rules.md`, `core-behaviors.md`, `development-rules.md` and `agent-conduct.md`. `meowkit-core.md` carries the role, the workflow, the ship check in brief, the boundary between data and instructions, the memory contract and the compaction policy. All other rules load from the `references/` folder of the skill that owns them ([Rules Index](/reference/rules-index) maps each one).

MeowKit installs no root `CLAUDE.md`. A project may keep its own, and the kit never installs, refreshes or overwrites it. Put project conventions in your own `CLAUDE.md` or in `docs/project-context.md`, because `mewkit upgrade` refreshes the kit's rule files. Do not edit the security and injection rules.

## .meowkit/config.yaml

The project config lives in `.meowkit/` with the project's other MeowKit state. The kit ships it with every setting commented out, so the committed file lists only the choices your project makes. The file has two levels of keys with boolean, whole-number or string values. An unknown key is an error, and there is no `gates.` or `paths.` key at any scope.

Resolution order for a key is: environment override (only `MEOWKIT_TDD`), then project config, then user config (`~/.meowkit/config.yaml`), then the default.

Commit this file and `.meowkit/memory/*.md`, since the team memory store is reviewed in the PR diff. Commit `.meowkit/state/ownership/*.json` as well: it records which files the kit installed, and a clone without it cannot tell the kit's files from yours. The rest of `.meowkit/` (`telemetry/`, the other files in `state/`, `cache/`) is machine-written and stays out of git.

```yaml
# .meowkit/config.yaml
tdd: false

budget:
  warn: 30     # USD, prints a warning
  block: 100   # USD, prints an over-budget notice (advisory)

hooks:
  build-verify: false   # switch one observer off
```

### Keys

| Key | Default | Purpose |
| --- | --- | --- |
| `tdd` | `false` | Strict test-first mode. `MEOWKIT_TDD` in the environment outranks it |
| `autobuild.mode` | auto-detected | Scaffolding density for `mk:autobuild`: `MINIMAL`, `FULL` or `LEAN`. It sets scaffolding only. `LEAN` makes the sprint contract optional, and the ship check runs in every mode. `MEOWKIT_AUTOBUILD_MODE` in the environment is also read |
| `budget.warn` | `30` | USD at which the first cost notice prints |
| `budget.block` | `100` | USD at which the over-budget notice prints. Advisory: nothing is stopped |
| `budget.cap` | none | Overrides `budget.block`, lower or higher |
| `buildVerify.timeoutMs` | per language | Timeout for each `build-verify` command, in milliseconds |
| `projectContext.maxBytes` | `12288` | Size above which the project-context file warns; `0` disables the warning |
| `workflow.telemetry` | `off` | `off`, `community` or `anonymous` |
| `workflow.proactive` | none | Whether skills volunteer suggestions |
| `hooks.<name>` | `true` | `false` switches one observer off; see below |

### Hook switches

`hooks.<name>: false` turns one observer off. The name is the handler's file base name (`build-verify`, `loop-detection`, `post-write`, `learning-observer`, `tdd-flag-detector` and the others listed in [Hooks](/reference/hooks)). The default is `true`, except `hooks.pre-completion-check`, which is off until you set it to `true`. These names are rejected in every config scope, and their hooks keep running: `privacy-block`, `pre-ship`, `check-careful`, `check-freeze` and `check-report-path`. A `hooks.<name>` set to `true` or `false` whose name is not a registered handler, such as the toggle of a handler a release removed, is skipped with a warning instead of rejecting the file: the rest of the file still applies, `mewkit validate` reports the key on its project-config row, and the session-start config block names it.

### Model routing

Model routing is set per agent, not in a config block. Each `.claude/agents/*.md` declares a `model:` of `opus`, `sonnet`, `haiku`, `fable` or `inherit`. For Codex and Cursor, `mewkit init` writes a concrete model id for each tier into the agent file. Grok and OMP agent prompts carry no `model`, and Pi has no subagents. [Agent Models](/guide/agent-models) lists the mapping and how to change a pin. There is no `modelRouting` key.

## .claude/settings.json

`settings.json` holds the hook registrations and the `CLAUDE_CODE_FORK_SUBAGENT=1` entry in its `env` block. That variable makes the `mk:jira-*` skills fork into their matching agents; leave it set. [Hooks](/reference/hooks) describes each registration. Every hook runs as `command: node` with an `args` list, so no shell parses the path.

## .meowkit/.env [#dotenv]

`.meowkit/.env` holds this project's API keys and integration settings, and `~/.meowkit/.env` holds the ones every project shares. A shell export beats both, and the project file beats the user-wide one. Only the scripts that need a key read these files: the Jira and Confluence wrappers, the `jira-env-loader` hook, `mk:docs-finder`, `mk:multimodal` and `mk:stitch`. Workflow switches such as `MEOWKIT_TDD` are read from the shell only.

```bash
cp .meowkit/.env.example .meowkit/.env
```

[Environment Variables](/reference/environment-variables) lists every variable, the order the files are read in and how to set each one up.

## Examples

A production session with TDD and every hook:

```yaml
# .meowkit/config.yaml
tdd: true
```

A quick prototyping session:

```yaml
# .meowkit/config.yaml
hooks:
  build-verify: false
```

```bash
export MEOWKIT_HOOK_PROFILE=fast
```

A high-budget autobuild run:

```yaml
# .meowkit/config.yaml
budget:
  cap: 200
# autobuild.mode stays unset, so density follows the detected model
```
