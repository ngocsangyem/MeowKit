## What it does

mk:jira-collaborate forks the `jira-collaborate` agent ([agent page](/reference/agents/jira-collaborate)) to run `jira-as collaborate` commands. Before posting any comment that could reach a customer, the agent asks whether it is internal (team only) or public (visible to all watchers), and defaults to internal when unsure. The skill is not enabled by default.

## When to use it

Use it for "add comment to PROJ-123", "list comments on PROJ-123", "upload screenshot.png to PROJ-123", "watch PROJ-123", "who watches PROJ-123?" or "notify PROJ-123 watchers".

| Need | Use instead |
|---|---|
| Create, read, update, delete an issue | [`mk:jira-issue`](/reference/skills/jira-issue) |
| Issue links | [`mk:jira-relationships`](/reference/skills/jira-relationships) |
| Transitions | [`mk:jira-lifecycle`](/reference/skills/jira-lifecycle) |

For JSM tickets, [`mk:jira-jsm`](/reference/skills/jira-jsm) covers the internal and public distinction. [`mk:jira-analyst`](/reference/skills/jira-analyst) produces analyses to post as comments.

## Comment format

Markdown is accepted and converted to Atlassian Document Format on the server by `jira-as`. Prefer markdown for multi-line comments with code blocks. `references/comment-formats.md` covers text, markdown and ADF.
