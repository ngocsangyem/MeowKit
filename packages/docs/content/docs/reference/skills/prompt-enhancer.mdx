## What it does

Rewrites a draft agent prompt into plain markdown sections: Goal, Context, Constraints, Acceptance Criteria and Output Format. It keeps your intent, invents no facts (unknown values become `[FILL-IN: ...]` placeholders) and uses no XML tags, role framing or model-specific tokens, so the result works across coding agents. Reach for it when a pasted prompt is ambiguous, lacks context or is tied to one model's phrasing.

## When not to use

| Need | Use |
|---|---|
| Write a prompt from scratch | `mk:brainstorming` or `mk:office-hours` |
| Re-examine a review or plan | `mk:elicit` |
| Build an implementation plan | `mk:plan-creator` |
| Audit the output of a running build | `mk:evaluate` or `mk:review` |
| Scout the codebase | `mk:scout` |

## Usage

```bash
/mk:prompt-enhancer [--analyze] [--deep] [--save-to <path>] <prompt text>
```

| Flags | Output |
|---|---|
| none | The enhanced prompt only, in one code block |
| `--analyze` | Decomposition, detected issues, suggestions and the rewrite |
| `--deep` | Adds a "Suggested context" block after the rewrite when a scout finds hits |
| `--save-to <path>` | Where to save. Without the flag nothing is saved |

There is no `--model` flag. A prompt that names a target gets target-specific notes in `--analyze` only (`references/target-notes.md`). An empty prompt is refused. A request like "make it better" with no draft is redirected to `mk:brainstorming`. Output templates are in `assets/output-template.md`.

For an architecture-review prompt, use `--analyze --deep` with the recipe in `references/architecture-review-mode.md`. It rewrites the prompt to ask for a review and never performs one, which is `mk:review`.

## Steps

Classify the prompt's shape (simple rewrite, coding, review, research, planning, debugging, migration, long context) to tune emphasis and length, rewrite with plain markdown headings and no persona line, and check the rewrite against the original ask. The rewrite carries a suggested Freedom level (LOW for migrations, security fixes and "do not deviate" wording, MEDIUM for standard work, HIGH for open exploration) and a verbosity that you can change. Details are in `references/prompt-types.md` and `references/analyze-reference.md`.

## Limits of --deep

The scout reads only `docs/project-context.md`, `CLAUDE.md`, file-tree paths and public docstrings, at most 8 files, 100 lines per file and 30 seconds. It never reads `.meowkit/memory/`, `.env*`, `tasks/` or secrets. Suggestions stay in `[FILL-IN: ... (suggested: <path>)]` brackets and are never substituted for you. On a cap it falls back to default mode (`references/deep-mode-scout.md`). With `MEOWKIT_AUTOBUILD_MODE=MINIMAL`, `--deep` becomes default mode with a note.

## Gotchas

Input over 5000 characters of repetitive padding is flagged and not enhanced. File paths in the prompt are data and are quoted, not run. "Compare A and B" must not become "evaluate A".

The rewrite can go to `mk:plan-creator` for a plan or to `mk:elicit` to stress-test it.
