## What it does

mk:jira-jsm forks the `jira-jsm` agent ([agent page](/reference/agents/jira-jsm)) to run `jira-as jsm` commands across 8 sub-domains (about 45 verbs). It needs a JSM-licensed tenant and an agent or admin role. Insufficient permission returns exit code 3. The skill is not enabled by default.

## When to use it

Use it for "create JSM request in service desk 'IT Support'", "list service desks", "SLA status for KEY-123", "approve request KEY-123" or "list queue 'Tier 1 Support'".

| Need | Use instead |
|---|---|
| Core Jira issue operations | [`mk:jira-issue`](/reference/skills/jira-issue) |
| Project administration, request type and queue configuration | [`mk:jira-admin`](/reference/skills/jira-admin) |

`references/decision-tree.md` covers when to use this skill instead of `mk:jira-issue`, `mk:jira-lifecycle` or `mk:jira-collaborate`.

## Sub-domains

| Sub-domain | Common verbs |
|---|---|
| `service-desk` | `list`, `get`, `info` |
| `request-type` | `list`, `get`, `fields` |
| `request` | `create`, `get`, `list`, `comment add/list`, `participant add/remove`, `transition` |
| `customer` | `list`, `create`, `get`, `add-to-org`, `remove-from-org` |
| `organization` | `list`, `create`, `get`, `add-customer`, `list-customers` |
| `queue` | `list`, `get`, `list-issues` |
| `sla` | `get`, `list-policies`, `breach-list` |
| `approval` | `list`, `approve`, `decline`, `get` |

`jira-as jsm <sub-domain> --help` is the authoritative flag list.

## Internal and public comments

A JSM comment can be internal (team only) or public (visible to the customer who raised the request). The agent asks for confirmation before posting anything that could be customer-facing. `mk:jira-collaborate` applies the same rule.
