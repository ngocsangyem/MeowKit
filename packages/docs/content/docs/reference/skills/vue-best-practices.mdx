## What it does

`mk:vue-best-practices` extends `mk:vue` with an ordered best-practices workflow and a review mode. It does not activate on `.vue` files by itself. Call it with `/mk:vue-best-practices [concern]`, or ask to review Vue code or recommend improvements. It is worth the cost for a non-trivial feature that uses built-in components, animation, optional features or a performance pass.

It does not repeat the basics (reactivity, props, emits, composable naming, Pinia, routing). Those stay in `mk:vue` references. State management is owned by `mk:vue`.

## When not to use it

| Need | Use |
|---|---|
| Everyday Vue authoring | `mk:vue` |
| Diff or PR review | `mk:review` |
| TypeScript, React, Angular | `mk:typescript`, `mk:react-patterns`, `mk:angular` |
| Visual design | `mk:frontend-design` |
| Vue test design or review | `mk:vue-testing-best-practices` |

## Workflow

1. Confirm the architecture. The default is Vue 3 with the Composition API and `<script setup lang="ts">`. For a larger feature, sketch a component map first: each component's responsibility, its props and emits, and the folder layout.
2. Apply the deltas: `reactivity-advanced`, `component-data-flow-advanced`, `sfc-structure-and-templates` and `composables-organization`.
3. Load optional features only when the requirement exists.
4. Make a performance pass after behaviour is correct, and measure with Vue DevTools first.
5. Self-check: behaviour matches requirements, reactivity is minimal, templates are safe, components are focused, data-flow contracts are typed, and optional features appear only where needed.

All files are in `references/`.

| Topic | Files |
|---|---|
| Built-in components | `component-slots`, `component-fallthrough-attrs`, `component-keep-alive`, `component-teleport`, `component-suspense`, `component-transition`, `component-transition-group` |
| Animation | `animation-class-based`, `animation-state-driven` |
| Less common features | `custom-directives`, `async-components`, `render-functions`, `plugins` |
| Performance | `perf-virtualize-large-lists`, `perf-v-once-v-memo`, `perf-avoid-abstraction-in-lists`, `perf-updated-hook` |

This skill owns Teleport and Suspense authoring. Test setup for them belongs to `mk:vue-testing-best-practices`.

## Review mode

For a review, walk the self-check against the target code and list findings as `[severity: high|med|low] · path:line · issue · fix`. Each finding cites a best practice from this skill or from `mk:vue`. Basics go to `mk:vue`, and structural and security findings go to `mk:review` and the project's security rules. The review ends with one line: ready, changes recommended or changes required.

## Gotchas

- The skill keeps `shallowRef()` for primitives from its upstream source, which differs from the `ref()` rule in `mk:vue`. `references/reactivity-advanced.md` documents the difference.
- `SOURCE.md` records the upstream repository and pinned commit for re-syncing.
