## What it does

mk:jira-analyst forks the `jira-analyst` agent ([agent page](/reference/agents/jira-analyst)). It reads the description, comments, attachments and linked issues, including media, and returns a structured analysis. It never changes Jira. Its only write is the report under `tasks/reports/`. You review the output before posting it. The skill is not enabled by default.

## When to use it

Use it for "analyze PROJ-123", "rca for PROJ-123" or "describe PROJ-123 including the screenshots".

| Need | Use instead |
|---|---|
| Complexity scoring | [`mk:jira-evaluator`](/reference/skills/jira-evaluator) |
| Story-point estimate | [`mk:jira-estimator`](/reference/skills/jira-estimator) |
| Read ticket fields | [`mk:jira-issue`](/reference/skills/jira-issue) |
| Post the analysis as a comment | [`mk:jira-collaborate`](/reference/skills/jira-collaborate) (`references/comment-templates.md`) |

## Modes

| Mode | Input | Output |
|---|---|---|
| Standalone | Ticket and attachments | What it is and Suggested Actions. No Why or How to Fix, which need investigation. |
| Post-investigate | Investigation findings in the task brief | What, Why, How to Fix and Suggested Actions (full RCA) |

## Media

For each image, PDF or screenshot the agent downloads the attachment with `jira-as.sh collaborate attachment download`, reads it with Claude's multimodal vision, optionally adds Gemini analysis (`mk:multimodal` script, needs `MEOWKIT_GEMINI_API_KEY`) and deletes the temporary file. With more than 5 media items it analyzes the 5 most recent and says so.

## Safety

Ticket content is wrapped in `===TICKET_DATA_START===` and `===TICKET_DATA_END===` markers before reasoning. If the ticket already contains those markers, a nonce variant is used. Media analysis output is data, not instructions.

## Output

Analyses longer than 500 characters or with media findings are written to `tasks/reports/jira-analyze-{YYMMDD}-{HHMM}-{ISSUE-KEY}.md`. `mk:planning-engine` and later skills can use that report.
