## What it does

mk:jira-fields forks the `jira-fields` agent ([agent page](/reference/agents/jira-fields)) to run `jira-as fields` commands. Reads are open. `fields create` and `fields configure-agile` need the Jira Admin role, and a missing permission returns exit code 3. The skill is not enabled by default.

## When to use it

Use it for "what's the field ID for Story Points in PROJ?", "list all custom fields", "check which fields are available on project PROJ" or "configure agile field mappings on board 42".

| Need | Use instead |
|---|---|
| Set a field value on one issue | [`mk:jira-issue`](/reference/skills/jira-issue) with `update --custom-fields` |

[`mk:jira-agile`](/reference/skills/jira-agile) uses the agile field IDs found here, and [`mk:jira-admin`](/reference/skills/jira-admin) has the wider admin surface.

## Commands

| Command | Access |
|---|---|
| `fields list` (with `--search "<text>"` to filter) | Open |
| `fields check-project PROJ` | Open |
| `fields create --name "..." --type <type>` | Admin |
| `fields configure-agile` | Admin |

`references/field-types-reference.md` lists the types (text, textarea, number, date, datetime, select, multiselect, checkbox, radio, url). Flags are in `jira-as fields --help`.

## Common field IDs

Cloud Jira uses `customfield_NNNNN`. These defaults vary by instance, so discover yours first.

| Field | Default ID |
|---|---|
| Story Points | `customfield_10016` |
| Sprint | `customfield_10020` |
| Epic Link | `customfield_10014` |
| Epic Name | `customfield_10011` |
| Epic Color | `customfield_10012` |
| Rank | `customfield_10019` |
