## What it does

`mk:typescript` applies strict TypeScript patterns in Phase 3 (Build) and supports the `developer` agent. It activates on `.ts`, `.tsx`, `.js` and `.jsx` files, type errors, ESLint issues and requests such as "fix types". You can also call it with `/mk:typescript [concern]`.

## When not to use it

| Need | Use |
|---|---|
| Vue-specific patterns | `mk:vue` |
| Visual design | `mk:frontend-design` |
| React patterns | `mk:react-patterns` |

## Steps

1. Identify the concern: a type error, new code, a refactor or ESLint config.
2. Load the matching reference.
3. Apply the strict patterns.
4. Run `npx tsc --noEmit`. It must report zero errors.

## Rules

- Use `unknown` with type guards instead of `any` and instead of type assertions (`security-rules.md` blocks `any`).
- Check null explicitly with `=== null || === undefined`, since truthiness also catches `0` and `""`.
- Use `strict: true` and `noUncheckedIndexedAccess: true`.
- Use `import type { X } from 'y'`.
- Prefer named exports and discriminated unions.

| Avoid | Use |
|---|---|
| `as any`, `as unknown as X` | Narrowing with guards |
| `if (value)` as a null check | `if (value !== null && value !== undefined)` |
| `export default` | `export const X`, `export function X` |
| The `Object` type | `Record<string, unknown>` |
| Implicit return types | Explicit return types |
| `enum` | `as const` or union types |

## Failure handling

| Failure | Recovery |
|---|---|
| `tsc --noEmit` fails after changes | Fix the errors before moving on |
| No `tsconfig.json` | Suggest one with a strict config |
| Third-party types missing | `npm install @types/{package}` |

## Gotchas

- `value as User` tells TypeScript to trust you and does no validation. Use a type guard or a parser such as Zod at the boundary.
- `moduleResolution: "bundler"` allows extensionless imports that Node's ESM rejects. Use `nodenext` for backend code or keep one config per target.
- `noUncheckedIndexedAccess` makes `arr[0]` of type `T | undefined`, so existing code errors until each access is guarded.
- A `declare module` block in any `.d.ts` augments that module's types globally. Two conflicting ones cause TS2300 errors far from the source.
- A template literal type such as `` `user_${string}` `` does not accept a plain `string`. Brand values with a parse function at the input boundary.
- Enums are not erased, which hurts tree-shaking. Prefer `as const` for exported enums.
