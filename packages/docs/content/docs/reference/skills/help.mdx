## What it does

mk:help answers "what should I do next?". It collects candidate next steps from the project's state, ranks them, and reports the top three with a one-line rationale and the files each came from. It writes nothing. Backward-looking delivery status stays with `/mk:status`.

## When to use it

Use it at session start, after an interruption, or when the workflow state is unclear. Usage: `/mk:help [--verbose]`.

| Need | Use instead |
|---|---|
| Complexity routing | `mk:scale-routing` |
| Task type to skill suggestions | `mk:agent-detector` |
| Delivery status | `/mk:status` |

| Argument | Effect |
|---|---|
| none | The ranked top three next steps. Rank 1 is the recommended step. |
| `--verbose` | Also the full scan results: plan and review files, test and git status, and which additional sources were present or skipped. |

## What it scans

| # | Source | Used for |
|---|---|---|
| 1 | `.meowkit/state/*-progress.json` | Paused step-file workflows to resume |
| 2 | `tasks/plans/` | Plans without a matching review verdict |
| 3 | `tasks/reviews/` | WARN or FAIL verdicts needing action |
| 4 | `git status` | Uncommitted changes and whether they were reviewed |
| 5 | Nothing found | Clean state: start a task or run `/mk:retro` |
| 6 | `.meowkit/state/checkpoints/checkpoint-latest.json` | Model tier, active plan, branch, budget. Demoted when older than 24 hours. |
| 7 | `.meowkit/state/budget-state.json` | Cost and turn count, advisory only |
| 8 | `.meowkit/state/detected-model.json` | The current session's tier |
| 9 | `tasks/reviews/<slug>-verdict.json` | `decision` and per-dimension verdicts |
| 10 | `docs/development-roadmap.md` | Current phase, when present |

Sources 6 to 10 are skipped silently when absent. A review is blocked when `decision` is `BLOCKED`; the enum is `PASS | PASS_WITH_RISK | BLOCKED`, and `FAIL` exists only per dimension.

## Ranking

1. A blocked phase or a `BLOCKED` verdict comes first, citing the failing dimensions.
2. An in-progress phase comes next, citing the share of checked boxes.
3. An agreed plan with nothing built suggests `mk:cook`.
4. If `warnings_emitted` is above 0 or spend is $30 or more, a budget caution is added to the rank-1 rationale.
5. A clean state falls back to starting a task, `/mk:retro` or asking.

## State to recommendation

| State | Recommendation |
|---|---|
| No plan | `/mk:plan-creator` or describe the task |
| Existing plan | `/mk:plan-creator red-team {path}` or `validate {path}` |
| Completed or cancelled plans | `/mk:plan-creator archive` |
| Plan agreed, no tests | With `--tdd` or `MEOWKIT_TDD=1`, the `tester` agent writes failing tests. Otherwise run `developer` directly. |
| Tests written and failing | `developer` implements to pass them |
| Tests passing, no review | `/mk:review` |
| Review PASS or WARN | `/mk:ship` |
| Shipped | `documenter`, then `/mk:retro` |
| Paused workflow | Resume the skill at its step |
| Several items in progress | Ask which to focus on |

## Fast paths

A simple fix, typo, rename or config tweak goes to `/mk:fix`, where the scope is the plan. A task flagged `one-shot` by scale-routing needs no plan file. `MEOWKIT_HOOK_PROFILE=fast` skips non-critical hooks for rapid iteration, and `strict` enables all hooks including post-session capture. The fast profile does not turn off the ship check (see [Enforcement & Security](/core-concepts/enforcement)).

## Gotchas

- With several in-progress plans, the skill asks which to focus on.
- State files from earlier sessions can be stale. Check timestamps.
- `.meowkit/state/checkpoints/` does not exist until runtime. Its absence is normal.
- Do not source the model tier from `budget-state.json`. Use `detected-model.json`.
- The skill never recommends skipping a phase.
