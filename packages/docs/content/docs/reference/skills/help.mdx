## What it does

mk:help answers "what should I do next?". It reads the project's durable state, ranks the candidates, and reports the top step with up to two alternates with a one-line rationale and the files each came from. It writes nothing. Backward-looking delivery status stays with `/mk:status`.

## When to use it

Use it at session start, after an interruption, or when the workflow state is unclear. Usage: `/mk:help [--verbose]`.

| Need | Use instead |
|---|---|
| Complexity routing | `mk:scale-routing` |
| Task type to skill suggestions | `mk:agent-detector` |
| Delivery status | `/mk:status` |

| Argument | Effect |
|---|---|
| none | The recommended step and up to two alternates. |
| `--verbose` | Also which optional sources were present or skipped. |

## What it reads

| Source | Used for |
|---|---|
| `mewkit orient` | The active durable task, its step and next action |
| `mewkit plan status <plan-dir>` | Checkbox progress for one plan |
| `tasks/reviews/*-verdict.json` | `decision` and per-dimension verdicts |
| `git status` | Uncommitted changes |
| `.meowkit/state/checkpoints/checkpoint-latest.json`, `budget-state.json`, `detected-model.json`, `docs/development-roadmap.md` | Optional: checkpoint, advisory cost, current tier, milestone |

Optional sources are skipped silently when absent. A review is blocked when `decision` is `BLOCKED`; the enum is `PASS | PASS_WITH_RISK | BLOCKED`, and `FAIL` exists only per dimension.

## Ranking

A blocked verdict or phase comes first, then a phase in progress (with the `plan status` counts), then an agreed plan with nothing built, then the clean-state fallback. A budget caution is folded into the rank-1 rationale when `warnings_emitted` is above 0 or spend is $30 or more.

## State to recommendation

| State | Recommendation |
|---|---|
| No plan | `/mk:plan-creator` or describe the task |
| Existing plan | `/mk:plan-creator red-team {path}` or `validate {path}` |
| Completed or cancelled plans | `/mk:plan-creator archive` |
| Plan agreed, no tests | With `--tdd` or `MEOWKIT_TDD=1`, the `tester` agent writes failing tests. Otherwise run `developer` directly. |
| Build green | `/mk:simplify`, then `/mk:verify` |
| Tests written and failing | `developer` implements to pass them |
| Tests passing, no review | `/mk:review` |
| Verdict PASS or PASS_WITH_RISK | `/mk:ship` |
| Shipped | `documenter`, then `/mk:retro` |
| Paused workflow | Resume the skill at its step |
| Several items in progress | Ask which to focus on |

## Fast paths

A simple fix, typo, rename or config tweak goes to `/mk:fix`, where the scope is the plan. A task flagged `one-shot` by scale-routing needs no plan file. `MEOWKIT_HOOK_PROFILE=fast` skips non-critical hooks for rapid iteration, and `strict` enables all hooks including post-session capture. The fast profile does not turn off the ship check (see [Enforcement & Security](/core-concepts/enforcement)).

## Gotchas

- With several in-progress plans, the skill asks which to focus on.
- State files from earlier sessions can be stale. Check timestamps.
- `.meowkit/state/checkpoints/` does not exist until runtime. Its absence is normal.
- Do not source the model tier from `budget-state.json`. Use `detected-model.json`.
- It skips a phase only when the `mk:scale-routing` result or you say to.
