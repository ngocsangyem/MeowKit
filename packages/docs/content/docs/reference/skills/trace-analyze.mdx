## What it does

`mk:trace-analyze` reads `.meowkit/telemetry/trace-log.jsonl`, splits the records into batches, has up to three `researcher` subagents analyse them in parallel, and combines the results into patterns. Every suggested harness change is reviewed by you one at a time, and nothing is applied automatically.

Use it after three or more harness failures on the same task, or on a quarterly audit. Skip it when the log has fewer than 3 records or nothing new has been recorded in the last 24 hours.

## When not to use it

For a sprint retrospective from git history, use `mk:retro`. For a quick answer without subagents, use the `mewkit trace` command:

| Command | Effect |
|---|---|
| `mewkit trace score [--id <run>]` | Trace-quality tier per run |
| `mewkit trace audit` | Entropy, plus counts of orphaned, stale, unverified and repeated-friction items |
| `mewkit trace propose [--commit]` | Groups repeated friction (two or more) and drift into advisory backlog items. Dry run unless `--commit`. |
| `mewkit trace --friction "<note>" [--responsibility <r>]` | Records a friction note |

Use the command for fast recall and this skill when patterns need synthesis across runs.

## Usage

```
/mk:trace-analyze [--runs N] [--pattern <type>]
```

`--runs` defaults to 20. Run the steps through `workflow.md`. Script paths are relative to `${CLAUDE_SKILL_DIR}`.

## Steps

1. Ingest the last N records with `scripts/trace-records.cjs`, which needs no `jq`.
2. Partition by `run_id` into at most 3 batches.
3. Scatter: three `researcher` subagents analyse in parallel.
4. Gather: the main agent combines cross-batch patterns.
5. Draft structured fix suggestions from `references/error-taxonomy.md`.
6. Human review: ask you about each suggestion and write the approved ones to the plan.

A pattern needs at least 3 occurrences before it becomes a suggestion. Trace records are append-only data, and the analyser never changes them.

## Outputs

All under `plans/{date}-trace-analysis/`:

| File | Content |
|---|---|
| `findings.md` | Patterns above the threshold |
| `suggestions-draft.md` | Suggestions before review |
| `suggestions.md` | Approved suggestions |
| `rejected.md` | Rejected suggestions with reasons |
| `analysis.md` | Final summary |

An optional follow-up plan from the approved items can feed `mk:plan-creator --hard`, or `--deep` when findings span five or more module areas.

## Gotchas

- Approve suggestions one by one. Bulk approval is automated overfitting.
- One failed run is not a pattern.
- Cite records by `ts`, `event` and `run_id` instead of pasting them into the plan.
- A log under 3 records gives no signal, and 20 or more is better.
