## What it does

`mk:vue-testing-best-practices` recommends how to test Vue 3 components, composables, Pinia stores, Vue Router, async components, Suspense, Teleport, forms and accessibility, and it audits existing Vitest and Vue Test Utils tests for smells and gaps. It never runs, generates or fixes tests. It does not activate on its own. Call `/mk:vue-testing-best-practices [test file or component]` or ask how to test a Vue component or review your Vue tests.

## When not to use it

| Need | Use |
|---|---|
| Running tests, the TDD loop, non-Vue tests | `mk:testing` |
| Diff review or checking whether a test exists | `mk:review` |
| Mapping coverage to requirements | `mk:nyquist` |
| QA of a running app, with bug fixes | `mk:qa` |
| Generating runnable Playwright specs | `mk:qa-manual` |
| Driving a live browser | `mk:agent-browser` or `mk:playwright-cli` |
| Root cause of a failing test | `mk:investigate` |
| Writing Vue feature code | `mk:vue` or `mk:vue-best-practices` |

The split with `mk:vue-best-practices` is authoring against test setup. How a component uses Teleport or Suspense belongs there. How a test stubs or awaits them (`teleport` stub, `attachTo`, `flushPromises`) belongs here.

## Steps

1. Take the intent and the test files, or the component, composable or store to design tests for.
2. Classify the surface and load the matching reference from `reference/`.
3. Evaluate against `reference/test-smells-rubric.md`: black-box or coupled to internals, async awaited, Pinia configured, Suspense and Teleport set up, snapshot policy, accessible queries, brittle locators.
4. Find missing scenarios and Vue-specific coverage risks.
5. Write the review.

## Output

One Vue Testing Review. Empty sections are omitted.

1. Verdict: `PASS` or `NEEDS-WORK` with one sentence of reason.
2. Test smells: `[severity] · file:line · smell · fix`, with severity `critical`, `high`, `medium` or `low`.
3. Missing scenarios: error, loading, edge and accessibility states.
4. Coverage risks: Teleported content, Suspense fallback, store actions, router guards. This section judges test quality. Whether a test exists is `mk:review`'s job.
5. Tooling recommendations: runner, test library, E2E framework, each with a reason.
6. Handoffs to other skills.

## Gotchas

- `await nextTick()` flushes DOM updates but not pending promises. After an API call use `flushPromises()`, sometimes twice.
- A snapshot checks markup shape, not behaviour. Pair it with assertions on text, role or emitted events.
- `injection Symbol(pinia) not found` means Pinia is missing. Use `createTestingPinia` for component tests and `setActivePinia(createPinia())` for store unit tests.
- `<Teleport>` moves DOM out of the wrapper, so `wrapper.find()` misses it. Stub Teleport, or use `attachTo: document.body` and query the document.
