`mk:chom` studies an external codebase, web app or described idea and produces a Replication Spec: a decision document on whether and how to replicate the feature in your project. It does not write code. Use it for "copy this from X", "port from", "clone how Y does Z" or "compare X with our approach".

## When not to use it

| If you need | Use |
|---|---|
| The current project packed for export or a public API surface | `mk:pack` |
| A one-shot URL to Markdown fetch | `mk:web-to-markdown` |
| Your own codebase explored | `mk:scout` |

## Usage

```bash
/mk:chom https://github.com/vercel/ai --port
/mk:chom "copy the dark mode toggle from linear.app" --compare
/mk:chom ./path/to/local/repo --copy --lean
```

| Flag | Effect |
|---|---|
| `--compare` | Side-by-side analysis only (phases 1 to 3). No decision or hand-off |
| `--copy` | Transplant with minimal changes. Phase 3 focuses on compatibility gaps |
| `--improve` | Replace anti-patterns during the port |
| `--port` | Idiomatic rewrite for your stack |
| `--lean` | Skips the researcher agent's background gathering for freeform text input. No effect for other inputs |
| `--auto` | Runs the mechanical steps without asking |

With no flag, the full workflow runs and the spec does not declare an adaptation depth. chom never picks `--copy`, `--improve` or `--port` for you. Natural wording maps to a suggested flag: "compare" or "vs" to `--compare`, "copy" or "as-is" to `--copy`, "adapt" or "improve" to `--improve`, "port", "rewrite" or "convert" to `--port`.

## What it does

| Phase | Action |
|---|---|
| 1 Recon | Routes the input: git URL is cloned shallow and scouted with `mk:scout`, web URL is fetched with `mk:web-to-markdown` or `mk:agent-browser`, local path is read directly, freeform text goes to the `researcher` agent, an image goes to `mk:multimodal`. Also reads `docs/project-context.md` |
| 2 Map | Maps source components to local equivalents: EXISTS, NEW or CONFLICT |
| 3 Analyze | Traces execution flow, data model, API contracts and UX patterns, with the mode's focus. For `--compare` it writes a Comparison Report and stops. A feature with three or more architectural layers or stateful workflows gets a hand-off note to run `mk:sequential-thinking` first |
| 4 Challenge | Loads `references/challenge-framework.md`, asks 7 questions (necessity, stack fit, data model, dependency cost, effort and value, blast radius, maintenance) and scores risk. 0 to 2 reds is low, 3 to 4 medium, 5 or more high and recommended for rejection. You decide |
| 5 Decision | Go or no-go. Go produces the Replication Spec, no-go a Rejection Report |
| 6 Hand-off | Prints the spec, the risk score, the red-flag summary and the suggested next command, usually `/mk:plan-creator "Replicate [feature] from [source]"` |

Phase 4 always waits for your answer, including with `--lean` and `--auto`.

## Outputs

The Replication Spec has five sections: Source, What to Build, Stack Fit, Risks and Effort, Recommendation. It describes what and why, with no code. The `--compare` report is printed to the conversation and not written to disk unless you ask. chom never starts another skill. You run the next one.

## Gotchas

- Without `docs/project-context.md` the advice is generic.
- An "obvious" copy of an auth flow, data model or API contract hides complexity. The challenge phase is never skipped.
- If the challenge finds a blocker, chom offers `--compare`. A large stack mismatch switches to `--compare` automatically.
- A private, missing or unreachable source stops the run and asks for access or a corrected URL.
