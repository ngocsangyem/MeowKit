## What it does

mk:jira-bulk forks the `jira-bulk` agent ([agent page](/reference/agents/jira-bulk)) to run `jira-as bulk` commands over a JQL result. Every bulk command runs with `--dry-run` first. The agent shows the `would_*` JSON keys and the impacted count, and only after your explicit yes does it run the command without `--dry-run` (or with `--force`). It refuses to skip the dry run. The skill is not enabled by default.

## When to use it

Use it for "bulk update N issues", "mass transition", "transition 50+ issues to Done", "bulk-clone" or "bulk-delete".

| Need | Use instead |
|---|---|
| One issue | [`mk:jira-issue`](/reference/skills/jira-issue), [`mk:jira-lifecycle`](/reference/skills/jira-lifecycle) |
| Bulk link | [`mk:jira-relationships`](/reference/skills/jira-relationships) |
| JQL authoring and `bulk-update` | [`mk:jira-search`](/reference/skills/jira-search), which uses the same dry-run rule |

## Steps

1. Run the command with `--dry-run`.
2. The agent shows what would change and how many issues are affected.
3. After your explicit yes, it re-runs without `--dry-run`.

Example dry run:

```bash
bash $CLAUDE_PROJECT_DIR/.claude/skills/jira/scripts/jira-as.sh bulk transition --jql "<JQL>" --to "Done" --dry-run
```

JQL built from user-derived terms is sanitized first with `scripts/jql-sanitize.sh`. These are Tier 4 operations in the safety framework. Delete is irreversible and needs an extra confirmation.

## Workflow cache

Before a `bulk transition` the agent checks the target status, or the transition ID for `--id`, against `tasks/jira-workflows/<workflow-slug>.md`. A mismatch is rejected before running. If the cache is absent, it runs `jira/scripts/fetch-workflow.sh <KEY>` first. A partial cache (`_partial-<PROJ>.md`, from non-admin discovery) leads to a recommendation for a smaller pilot batch. See `../jira-lifecycle/references/workflow-discovery.md`.
