## What it does

Inspects or clears the local cache of the `jira-as` wrapper and discovers project context such as the default issue type and mandatory fields. It forks the `jira-ops` agent and changes nothing in Jira. Reach for it when the wrapper shows stale field IDs or a renamed status still appears under its old name.

## When not to use

For issue create, read, update or delete use `mk:jira-issue`. For project administration use `mk:jira-admin`.

## Usage

Ask in plain words: "jira cache status", "clear the jira cache, my admin renamed a status", "discover project context for PROJ".

| Operation | Command |
|---|---|
| Cache status | `jira-as.sh ops cache-status` |
| Clear the cache | `jira-as.sh ops cache-clear` |
| Discover a project | `jira-as.sh ops discover-project --project PROJ` |
| Warm the cache | `jira-as.sh ops cache-warm --project PROJ` |

`jira-as.sh` is `.claude/skills/jira/scripts/jira-as.sh`. `cache-warm` is not a trigger phrase of the skill; call it directly when needed. The `jira-as` tool is not part of this repository, so check unfamiliar flags with `--help`.

## Steps

1. The agent runs the operation through the wrapper.
2. For `cache-clear` it re-runs the failing operation afterwards. The cache otherwise expires on its own.
3. It returns cache statistics, project metadata and a recommendation, or the items cleared and a suggested next operation.
