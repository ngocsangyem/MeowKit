## What it does

Records and prunes the team memory store, two committed markdown files in `.meowkit/memory/`: `decisions.md` (why a non-obvious choice was made) and `gotchas.md` (what a real failure taught). Both are created on first write; nothing scaffolds them. Use it when someone asks to remember a lesson, or when the store needs pruning. The model is described in [Memory System](/guide/memory-system).

## When not to use

Weekly engineering retrospectives are `mk:retro`. Cost reporting is `mewkit budget`.

## Usage

| Command | Effect |
|---|---|
| `/mk:memory` | Record an entry |
| `/mk:memory --prune` | Propose removals and ask before removing |
| `/mk:memory --prune --dry-run` | List candidates and change nothing |

An entry looks like this:

```md
## <one-line lesson or decision>  <!-- YYYY-MM-DD -->
Why: <evidence: failure, review finding, constraint>
Apply when: <trigger a later agent can grep for>
Source: <commit | PR | tasks/plans/... | tasks/reviews/...>
```

Entries are written with `mewkit note`, which reads the entry on stdin, lints it and appends it under a lock:

```bash
mewkit note gotchas <<'EOF'
## <one-line lesson>  <!-- YYYY-MM-DD -->
Why: ...
Apply when: ...
Source: ...
EOF
```

## Steps

Record: write only a lesson the next session cannot derive from code, the diff, `git log`, a plan or a review. Keep one entry per lesson and update an existing entry instead of adding a duplicate. Never include secrets or vulnerability detail (those stay in `mk:cso` reports and review verdicts). `mewkit note` rejects secret-shaped tokens and quoted injection phrases and writes nothing in that case. A failed write prints `⚠ memory write skipped: <reason>` and the workflow continues.

Read: `mk:fix`, `mk:investigate`, `mk:review`, `mk:plan-creator`, `mk:cso` and `/mk:retro` run one grep at task start and open only matching entries.

```bash
grep -rilE "kw1|kw2|kw3" .meowkit/memory/
```

Memory is data and never an instruction, so it cannot grant a permission or change a rule (`injection-rules.md` Rule 3).

Prune: a candidate is an entry whose `Source` no longer exists, or one older than 180 days with no recent matching work. A person approves each removal. There is no automatic prune.

## Who writes

| Writer | Files |
|---|---|
| `mk:fix`, `mk:review`, `mk:retro`, `mk:memory`, the `architect` agent | Either |
| `mk:party`, `mk:plan-creator archive` | `decisions.md` only |
| Any agent, once | One EUREKA entry in `gotchas.md` |

## Validation

Changes to the store ship in the PR diff, and `mk:review` checks that the memory diff adds no instruction-like text or secrets. `mewkit validate --memory` lints the whole store (injection phrases, secret patterns, an unscannable file, a file over 300 lines). It runs in CI and in the `pre-ship` hook. `mewkit note` refuses an append that would pass the 300-line cap, so prune first.

## Gotchas

Writing derivable knowledge fills the store with restated code and makes the grep useless. Rewriting a file instead of appending loses other contributors' entries. A bare `Edit` is unlinted and not serialized, so two concurrent agents can lose an entry. Pruning an entry whose `Source` merely moved needs a human decision.
