## What it does

`mk:ui-design-system` is a lookup-driven design reference for building or reviewing UI components, setting up a design system, checking WCAG compliance, picking palettes, typography or chart types, and reviewing responsive layouts. The `ui-ux-designer` agent loads it in Phase 3 (Build), and the `developer` agent uses it for frontend work.

## When not to use it

To design or critique a single screen, use `mk:frontend-design`.

## Steps

1. Establish the product type, audience and style direction.
2. Look up the data (`references/data-lookup.md` explains how).
3. Apply the rules from `references/design-patterns.md` for visual design or `references/accessibility-standards.md` for accessibility.
4. Run `references/quality-checklist.md` before handoff.

## Data

| File | Rows | Content |

| `assets/products.csv` | 161 | Product type with style, landing pattern, dashboard and color focus |
| `assets/ux-guidelines.csv` | 98 | Do and Don't pairs with category and severity |
| `assets/charts.csv` | 25 | Data type with best chart, accessibility grade and library |

## Gotchas

- Check contrast before shipping: 4.5:1 for normal text and 3:1 for large text.
- Design from 320px up, not from desktop down.
- Pair color-only signals such as red and green with an icon or text.
- Look up `colors.csv` first instead of guessing a palette.
- Check `products.csv` for product-specific recommendations. Not every SaaS product needs the same look.
