## What it does

Maps the acceptance criteria in a plan to test files and lists the criteria that have no matching test. It is read-only: it never writes tests, edits the plan or runs tests. It checks that a test exists, not that it is correct. Use it after the first tests are written (Phase 2), as part of review (Phase 4), or before shipping.

## When not to use

To run tests use `mk:testing`. For structural code review use `mk:review`. The `tester` agent writes tests.

## Usage

Ask in plain words: "are all requirements tested?", "check coverage gaps for the onboarding plan", or run `/mk:nyquist`.

## Steps

1. Read `tasks/plans/YYMMDD-name/plan.md` and extract the acceptance criteria.
2. Find test files with the globs `**/*.test.*`, `**/*.spec.*` and `**/test_*.*`.
3. Match each criterion to tests, then list criteria with no match as gaps.
4. Write the report.

| Matching | How |
|---|---|
| Keywords | Key nouns and verbs from the criterion against `describe`, `it` and `test` strings |
| File path | A criterion about "auth" is searched in `**/auth*test*` |
| Fuzzy | Equivalents such as "login" and "authenticate" |
| Manual | With no match, it asks you to confirm the gap is real and not a naming mismatch |

## Output

A report headed `Nyquist Coverage Report: <plan name>` with a table of criterion, test file, test name and status (COVERED or GAP), a summary of total, covered and gap counts, details with a suggested test for each gap, and a recommendation of PASS or WARN.
