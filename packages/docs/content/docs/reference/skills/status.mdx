## What it does

`mk:status` is the foreground way to run the `project-manager` agent. It writes a classified status report to `{plan-dir}/status-reports/{YYMMDD}-status.md` from the plan, review verdicts, the cost log and the git log, and compares against earlier reports to show the change. Use it for an on-demand "where are we" question or when more than one plan is active.

A status report is a report, not an approval.

## When not to use it

To ask what to do next, use `mk:help`. Status looks backward.

## Usage

```
mk:status
mk:status <plan-dir>
mk:status <plan-slug>
```

## Steps

1. Resolve the plan. A path is used directly and a slug is matched with `ls -d tasks/plans/*{slug}*`. A slug with no match prints `Plan not found: {arg}` and stops.
2. With no argument, the skill takes plans in `tasks/plans/*/plan.md` whose `status` is not `completed`, `cancelled` or `archived`. None prints `No active plan` and writes nothing. One is used. With several, it asks which plan to report on and never picks the most recent silently.
3. Delegate to `project-manager` in the foreground, with the template `assets/pm-status-template.md`, taking task counts from `mewkit plan status <plan-dir>`. It creates `status-reports/` if needed.
4. Print the absolute path of the report and its headline, for example `4 of 7 tasks done, 2 blocked, at-risk`.

## Gotchas

- With two or more active plans the skill asks which one; an unrelated plan's report reads as this plan's status.

- The report name carries the date, so a same-day rerun overwrites and earlier days accumulate in the plan's `status-reports/` folder.
- Reports travel with the plan when it is archived.
- `MEOWKIT_PM_AUTO` controls only the silent background runs described in `.claude/skills/cook/references/post-phase-delegation.md`. It never suppresses an explicit `mk:status`.
- The agent has no background mode. To run it asynchronously, ask the agent directly and say so.
