## What it does

`mk:task-queue` records tasks and who owns which files during parallel execution. It is not user-invocable. The orchestrator creates the queue when it splits work, and parallel agents claim tasks through it.

For team-mode coordination rules, see `.claude/skills/team-config/references/team-coordination.md`, which `mk:team-config` loads.

## The queue

The queue is `.meowkit/state/task-queue.json`. Each task has an `id`, `description`, `owner`, `status`, `ownership` (file globs) and `blocked_by`.

```json
{ "id": 1, "description": "Implement API endpoints", "owner": null,
  "status": "pending", "ownership": ["src/api/*"], "blocked_by": [] }
```

A task moves from `pending` to `claimed` to `in_progress` to `completed`, or to `blocked` when a dependency is not met.

## Claiming

1. An agent asks the orchestrator for the next task.
2. The queue returns the lowest-ID task that is `pending` and whose `blocked_by` tasks are all completed.
3. The agent declares its ownership globs.
4. If they overlap an `in_progress` task, the claim is rejected and the conflict goes to the orchestrator.
5. Otherwise the task is assigned and set to `in_progress`.

## Ownership

| Action | File | Result |
|---|---|---|
| Read | Any | Allowed |
| Write or edit | Owned | Allowed |
| Write or edit | Not owned | Stop and report an ownership violation |
| Write or edit | Overlapping | Stop and report the conflict to the orchestrator |

## Gotchas

- Two agents reading the file at once can claim the same task. The orchestrator is the only one who serialises claims.
- `src/api/*` and `src/api/auth/*` overlap. Keep the narrower glob in the same task.
- The orchestrator creates the file before dispatching. If it is missing, agents stop and report rather than creating it.
- Completed tasks stay in the queue as a record until the parallel phase ends. The queue is ephemeral and recreated per run.
