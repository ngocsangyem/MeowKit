## What it does

`mk:vue` is the quick reference for Vue 3 code: `<script setup lang="ts">`, composables, Pinia, Pinia Colada and file-based routing. It activates on `.vue` files and Vue 3 work during Build, and the `developer` agent loads it with `mk:typescript`. You can also call `/mk:vue [concern]`. Follow the repository's own conventions first. The rules below are defaults for when it has none.

| Need | Use |

| Vue test design or review | `mk:vue-testing-best-practices` |

## Default rules

- Use `<script setup lang="ts">`. No Options API and no `defineComponent()` wrapper.
- Use `type` rather than `interface` for object and prop shapes, and arrow functions for methods and callbacks.
- Use named exports. Composables are the exception and use `export default`.
- Name components in PascalCase and files in kebab-case (`UserProfile` in `user-profile.vue`). Composables are camelCase with a `use` prefix. Name from general to specific (`SearchButtonClear.vue`).
- Use Tailwind classes and its color system, not manual CSS or hard-coded colors.
- Use `ref()` for primitives, `reactive()` for complex objects and `computed()` for derived state.
- Never use `v-html` with user-provided content.
- Comments explain why, not what.

When the project depends on `@pinia/colada`, it is the preferred data-fetching layer (`references/pinia-colada.md`). Otherwise use plain Pinia stores and composables.

## Avoid

| Avoid | Use |
|---|---|
| Options API | Composition API with `<script setup>` |
| Vuex or `this.$store` | Pinia setup stores |
| Destructuring store state directly | `storeToRefs(useMyStore())` |
| `v-html` with dynamic content | `v-text` or sanitized rendering |
| `reactive()` for primitives | `ref()` |
| A watcher where `computed` works | `computed()` |
| A global event bus | `provide` and `inject`, or Pinia |

## Gotchas

- Destructuring `reactive()` loses reactivity. Keep the object, or use `toRefs()` or `ref()`.
- Methods destructure directly from a store, but state needs `storeToRefs()`.
- A parent's `childRef.value.method()` returns `undefined` unless the child calls `defineExpose({ method })`.
- Use `:slotted()`, not `:deep()`, to style slotted content in scoped styles.
- A `watchEffect` that starts async work needs `onCleanup`, for example to abort a request, or a fast change leaves stale state.
- Call a Pinia store inside `setup()` or pass the `pinia` instance, or the instance is disconnected from the SSR app.
- A destructured prop needs a getter in `watch(() => count, ...)`.
- `onWatcherCleanup()` throws if called after an `await`. Use the `onCleanup` callback there.
- Pinia Colada query keys must include every variable the query function uses, and a dynamic key needs a getter (`key: () => [...]`).
- `refresh()` reuses in-flight requests and respects `staleTime`, while `refetch()` always fetches.
- Use a named route group such as `pages/(home).vue` instead of `index.vue`, and explicit param names such as `userId`.
