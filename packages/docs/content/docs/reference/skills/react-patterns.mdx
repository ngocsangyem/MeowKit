## What it does

Gives React and Next.js performance rules for writing and reviewing components. Each rule in the reference files has a problem, a solution and a code example. The skill loads automatically in Phase 3 (Build) when a React or Next.js project is detected, and the `developer` agent loads it with `mk:typescript`. Use it when you edit `.tsx` or `.jsx` files, chase re-renders, shrink a bundle, decide between server and client components, or pick a data-fetching pattern.

## When not to use

For type safety use `mk:typescript`. For Vue use `mk:vue`.

## Usage

```bash
/mk:react-patterns [concern]
```

`concern` is optional: waterfall, bundle, server, re-render or rendering.

| Priority | Area | Reference | Rules |
|---|---|---|---|
| Critical | Eliminating waterfalls | `references/async-patterns.md` | Defer await, parallel promises, Suspense boundaries |
| Critical | Bundle size | `references/bundle-optimization.md` | No barrel imports, dynamic imports, defer third-party code |
| High | Server performance | `references/server-patterns.md` | `React.cache()`, LRU cache, parallel fetching, `after()` |
| Medium | Re-renders | `references/rerender-optimization.md` | Derived state, functional `setState`, `memo`, transitions |
| Medium | Rendering | `references/rendering-patterns.md` | `content-visibility`, hoisted JSX, conditional rendering |

## Steps

1. Name the concern: waterfall, bundle, re-render or server.
2. Load the matching reference.
3. Apply its rules.
4. Check the improvement with Lighthouse, a bundle analyzer or React DevTools.

## Gotchas

Measure before optimizing re-renders, using the React DevTools Profiler. Add `useMemo` or `React.memo` only where the profiler shows an expensive re-render. Import from the source file and not from an `index.ts` barrel, which pulls in the whole module.
