## What it does

mk:freeze stores one directory as the session's edit boundary. A `PreToolUse` hook, `check-freeze.cjs`, runs on every Edit and Write and denies any `file_path` outside that directory. It is an intent guardrail, not a security boundary.

## When to use it

Use it when debugging or refactoring one module, working in a monorepo where a change could spill into other packages, or when you say "freeze", "only edit this folder" or "lock down edits". Usage: `/mk:freeze [PATH]`. Without a path the skill asks for one.

| Need | Use instead |
|---|---|
| Warn before destructive shell commands | `mk:careful` |

The two combine: freeze stops stray edits and careful warns on destructive Bash commands.

## What it restricts

| Tool | Restricted |
|---|---|
| Edit, Write | Yes, denied outside the boundary |
| Bash (`sed`, `awk`, `cp`, `mv`) | No |
| Read, Glob, Grep | No |

## Steps

1. You run `/mk:freeze` with a path, or give one when asked.
2. The path is resolved to an absolute directory with a trailing slash. The slash stops `/src` from matching `/src-old`.
3. The boundary is saved to `${CLAUDE_PLUGIN_DATA:-.meowkit/state}/freeze-dir.txt`.
4. On each Edit or Write the hook compares `file_path` with the boundary and returns allow or deny, with a message naming the boundary.

## Ending a freeze

The freeze lasts for the session. Running `/mk:freeze` with another path replaces the boundary. Deleting `freeze-dir.txt` clears it.

## Gotchas

- The hook checks the stated path, not a resolved symlink target. Avoid symlinks inside the frozen directory that point outside it.
- Files outside the boundary, including shared test fixtures, cannot be edited. Move the boundary with `/mk:freeze`.
