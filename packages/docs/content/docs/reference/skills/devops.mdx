## What it does

mk:devops plans and writes infrastructure, container, pipeline, runtime-configuration and observability changes. For each change it records the blast radius, stateful resources, rollback path and the read-only check that proves the change is right. A human, or `mk:ship`, performs the production effect.

## When to use it

Use it for container definitions, local composition, CI pipelines, infrastructure-as-code, deployment safety design, rollback planning and diagnosing a live operational failure.

| Need | Use instead |
|---|---|
| Approve or run a release | `mk:ship` or a human |
| Code root cause behind a symptom | `mk:investigate` |
| Schema semantics | `mk:database` |
| Security verdict | the security audit (`mk:cso`) |

Usage: `/mk:devops [platform or infrastructure change]`

## Secret boundary

The skill never reads, greps, prints or opens a `.env` or `.env.*` file, a keystore, a credential file or a generated config that carries credentials. It never asks for a secret value in conversation and never echoes output that contains one. It reads only committed templates, configuration and infrastructure definitions. When it cannot prove a value is available from a tracked file, it stops at a readiness report naming the missing capability.

## Steps

1. Discover the platform from tracked container, IaC, pipeline and deployment files. If it is not discoverable, ask. No cloud is the default.
2. Classify the work: local container, CI, infrastructure, runtime config, observability, release and rollback, or incident diagnosis.
3. Write the safety design: blast radius, stateful resources, environment contract (names only), rollback or forward recovery, approval point and validation command.
4. Implement the change and produce the read-only plan or diff evidence. The skill does not run or emit a ready-to-run apply, deploy or destroy step.
5. Hand the production effect to `mk:ship` or a human with the evidence, blast radius, rollback path and post-change validation.

## Output

A change plus a safety record: platform evidence, classification, blast radius, stateful resources, environment contract, rollback path, approval point, validation command and the handoff.

## Gotchas

- A plan or diff that was not read is not evidence. Quote the resources it replaces, not only the ones it updates.
- "Replace" on a database, volume, bucket or disk is data loss until a restore is proven.
- A rollback that needs the failing system to be healthy is not a rollback.
- The skill invents no availability target, replica count, timeout, limit or retention period unless the repository states it or the user chose it.
- A missing environment variable is a readiness finding. Report the name and where the template expects it.
- CI credentials live in the platform's secret store. A pipeline change references a secret by name only.
