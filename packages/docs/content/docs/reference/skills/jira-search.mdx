## What it does

Runs JQL queries, validates JQL, builds queries from a description, exports results and manages saved filters. It forks the `jira-search` agent. JQL is positional on `search query` and `search validate`; everything else is a flag.

## When not to use

Use `mk:jira-issue` for one issue by key and `mk:jira-bulk` for bulk writes. Time-related JQL snippets are in `mk:jira-time`.

## Usage

Ask in plain words: "find unresolved bugs in PROJ created in the last 7 days, top 20", "validate this jql: ...", "save a filter named 'My open bugs' with this jql: ...", "export the search to out.csv".

| Operation | Command |
|---|---|
| Query | `jira-as.sh search query "<JQL>" [--max-results N]` |
| Validate | `jira-as.sh search validate "<JQL>"` |
| Build from a description | `jira-as.sh search build` |
| Export | `jira-as.sh search export "<JQL>"` |
| Update by JQL | `jira-as.sh search bulk-update "<JQL>"` (dry run first) |
| Saved filters | `jira-as.sh filter list`, `create`, `update`, `delete` |

`jira-as.sh` is `.claude/skills/jira/scripts/jira-as.sh`. The `jira-as` tool is not part of this repository, so check flags with `--help`.

## Steps

1. Any user-derived term that goes into JQL passes through `.claude/skills/jira/scripts/jql-sanitize.sh`. It strips JQL operators, functions and special characters and quote-wraps the result. Raw user input is never concatenated into JQL, because that allows JQL injection.
2. The agent runs the query. `search query` returns up to about 100 issues per call; larger sets are paged with `--start-at` and `--max-results`, and a truncated result says "showing first N of M".
3. It returns the count and a list of key, summary and status. For `bulk-update` it returns the dry-run summary and the confirm command.
