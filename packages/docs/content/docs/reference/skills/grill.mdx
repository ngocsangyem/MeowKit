## What it does

mk:grill reverses the usual direction: Claude asks and you answer. It works through every unresolved branch of your plan until you share the same understanding, then writes the resolved context to `docs/knowledge/<slug>.md` so a build skill does not have to guess it. It never proposes the solution.

It accepts a doc path (plan, design or spec), which it reads to seed the open branches, or a verbal idea, which starts an empty tree. It never edits the source doc.

## When to use it

Use it when you say "grill me", "stress-test this plan" or "interrogate my design", or before handing a half-formed idea to `mk:skill-creator` or `mk:plan-creator`.

| Need | Use instead |
|---|---|
| Compare technical approaches | `mk:brainstorming` |
| Decide whether to build at all | `mk:office-hours` |
| Claude answers questions about the repo | `mk:ask-me` |
| One-shot review of a plan | `mk:plan-ceo-review` |
| Named reasoning lenses on existing findings | `mk:elicit` |
| Conventions derived from the codebase | `mk:project-context` |
| One recommendation on a decision | `mk:advise` |

## Usage

`/mk:grill [doc path | verbal idea or topic]`

```bash
/mk:grill tasks/plans/260613-1254-payment-retry/plan.md
/mk:grill I want to add a retry queue for failed payment webhooks
```

## The loop

1. Pick the unresolved branch whose answer unblocks the most decisions.
2. Ask exactly one specific question. No batching, no menus. The skill has no `AskUserQuestion` tool for this reason.
3. Wait for your answer and restate it in one line.
4. Write a checkpoint to `docs/knowledge/<slug>.md` before the next question.
5. Re-evaluate the tree. A contradiction with an earlier answer is raised on the spot.

Depth matters, not the count. Five questions or an hour are both valid.

## Gaps and wrap-up

If you cannot answer or say you do not own it, the skill records an Open Gap with the question, why it is unresolved and who to ask. At each checkpoint it shows the remaining open branches. When they drain it proposes wrap-up and waits for you to confirm "done" or "keep going". It then offers three handoffs and does not invoke any itself.

| Handoff | When |
|---|---|
| `mk:skill-creator` | The resolved design is a skill |
| `mk:plan-creator` (or `mk:brainstorming` if approaches are open) | A feature or system to plan |
| `mk:project-context` | Merge the knowledge into the project conventions |

## Output

`docs/knowledge/<slug>.md` is the only file written. If it exists, the skill resumes from it.

```markdown
# Knowledge: <Plan/Design Title>
**Source:** <doc path | "verbal idea">
**Started:** <date>  ·  **Status:** in-progress | wrapped
## Decisions
## Q&A Log
## Highlights
## Open Branches
## Open Gaps
```

## Gotchas

- Two questions mean two turns.
- Suggesting the answer turns the session into `mk:brainstorming`.
- Writing the checkpoint at the end loses everything on a context reset. Write after every answer.
- A guess on something you do not own is worse than a flagged gap.
