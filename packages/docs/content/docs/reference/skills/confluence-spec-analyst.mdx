`mk:confluence-spec-analyst` forks the `confluence-spec-analyst` agent to read a Confluence spec page, follow its children to a depth limit, run gap-detection checks and write a Spec Research Report for you to review. It never writes to Confluence. Its only write is the local report.

The page is fetched as Atlassian Document Format and passed through the macro-aware converter `scripts/adf-to-md.sh`. Panels, decisions, task lists, mentions, expand sections and Smart Link or Figma embeds become explicit Markdown labels (`> [INFO]`, `> [DECISION]`, `- [ ]`, `<details>`, `@name`, `![alt](attachment:<id>)`), and the gap checks use those labels.

## When not to use it

| If you need | Use |
|---|---|
| Raw page create, read or update | [`mk:confluence-page`](/reference/skills/confluence-page) |
| Ticket complexity scoring or sprint planning | [`mk:planning-engine`](/reference/skills/planning-engine) |

## Usage

```bash
analyze PAGE-ID [--include-children N] [--no-images] [--with-commands]
```

Ask in plain words: "analyze spec for 12345", "extract requirements from this confluence page", "what are the gaps in PAGE-ID 12345".

| Argument | Default | Effect |
|---|---|---|
| `PAGE-ID` | required | A numeric page id, or a full Confluence URL that is parsed to an id |
| `--include-children N` | 1 | Child depth. Hard cap of 10 |
| `--no-images` | off | Skip attachment download and multimodal analysis |
| `--with-commands` | off | Append `mk:jira-issue create` suggestions to the report. They are never run for you |

## Report

1. TL;DR (three sentences at most) and headline
2. Source metadata: page id, title, space, version, author, last modified
3. Requirements (`REQ-F-*`, `REQ-NF-*`) with page-anchor citations
4. Acceptance criteria from `taskList` macros and explicit "must" statements
5. Decisions and constraints from `> [DECISION]` blocks
6. Gaps (`GAP-*`), ambiguities (`AMB-*`) and conflicts (`CONFLICT-*`)
7. Open questions, including `[UNHANDLED_NODE: <type>]` entries from the converter
8. Suggested user stories
9. Image and diagram findings, or `[NO_MULTIMODAL]` when `mk:multimodal` is absent
10. A hash of the source page to detect staleness

References: `references/spec-analysis-patterns.md` (gap heuristics, weasel words, macro labels), `references/report-template.md` and `references/integration-with-planning-engine.md`.

## Hand-offs

- `mk:planning-engine` takes `--spec <report-path>`. Run the analyst first, then pass the report path.
- [`mk:intake`](/reference/skills/intake) treats a Confluence URL or page id as a source and recommends this skill for deeper analysis.
- With `--with-commands`, you run the `mk:jira-issue create` commands from the report yourself.

## Gotchas

- Every re-run writes a fresh report. There is no diff mode. The source hash only detects staleness.
- Without `mk:multimodal` the image section is left out and the rest of the analysis continues.
- Raising the child limit is an explicit choice, to stay inside the Confluence Cloud rate limit.

## Agent

[`confluence-spec-analyst`](/reference/agents/confluence-spec-analyst) handles untrusted page content and is read-only on Confluence.
