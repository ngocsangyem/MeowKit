`mk:confluence` is a routing skill. It picks the `mk:confluence-*` leaf that fits a Confluence Cloud task and points at it. The leaves do the work: each forks a dedicated agent from `.claude/agents/` and calls the `confluence-as` CLI through a wrapper script. If you already know the leaf, call it directly.

## Routing

| You want to | Leaf |
|---|---|
| Get, create, update or delete one page or blog post, or copy, move or version it | [`mk:confluence-page`](/reference/skills/confluence-page) |
| Search with CQL, list spaces, export results | [`mk:confluence-search`](/reference/skills/confluence-search) |
| Analyse a spec for requirements, gaps and suggested stories | [`mk:confluence-spec-analyst`](/reference/skills/confluence-spec-analyst) |
| Change 10 or more pages at once (label, move, delete), dry-run required | [`mk:confluence-bulk`](/reference/skills/confluence-bulk) |
| Comments, attachments, labels, watchers | [`mk:confluence-collaborate`](/reference/skills/confluence-collaborate) |

How it decides:

- A skill name said outright routes at once.
- A number plus a verb is a page ID, so the verb picks the leaf.
- A short uppercase token with a read intent is a space key, so it goes to search. CQL syntax (`=`, `AND`, `OR`, `currentUser()`) also goes to search.
- "bulk", "batch", "mass" or 10 or more items go to bulk.
- "requirements", "acceptance criteria" or "analyze the spec" go to the spec analyst.
- Labels, comments, attachments and watchers always go to collaborate, even on a single page.
- If it is still unclear, the skill asks one question.

## Setup

Install, credentials, the Cloud-only limit and troubleshooting are on [Confluence Integration](/guides/confluence-integration). Setup is the one thing the hub does itself: `mewkit skill env confluence` installs `confluence-as` into `.meowkit/envs/confluence/` from `scripts/requirements.txt`, and the three `MEOW_CONFLUENCE_*` variables go in `.meowkit/.env`. `references/install-and-auth.md` walks through it and never echoes the token.

The wrapper exits 3 on a URL that is not `*.atlassian.net`. The hub does not fall back to the Atlassian MCP transport on its own.

## Shared resources

| File | Purpose |
|---|---|
| `scripts/confluence-as.sh` | Wrapper that maps `MEOW_CONFLUENCE_*` to `CONFLUENCE_*`, sets JSON output, refuses a settings.local.json fallback and blocks non-Cloud URLs |
| `scripts/cql-sanitize.sh` | CQL injection guard for user-derived input |
| `scripts/adf-to-md.sh`, `scripts/adf_to_md.py` | Macro-aware ADF to Markdown converter |
| `scripts/requirements.txt` | Pip dependencies read by `mewkit skill env confluence` |
| `scripts/smoke-live.sh` | Manual smoke test with live credentials |
| `references/install-and-auth.md`, `cli-idioms.md`, `safety-framework.md` | Setup, invocation patterns, safety tiers |

## Hand-offs

- `mk:planning-engine` accepts `--spec <report-path>` for a `mk:confluence-spec-analyst` report. Run the analyst first.
- `mk:intake` takes a Confluence URL or page ID as a source and fetches the page through the wrapper. It does not start the spec analyst.
- A spec analyst report pairs with `mk:jira-issue create` to turn stories into tickets. Review is manual.
- `mk:cook` does not write back to Confluence.

## Gotchas

- The binary is `confluence-as`, not `confluence`. The wrapper handles it.
- Converting ADF is lossy for macros (panel, expand, mention, decision, task list, media). The spec analyst uses the macro-aware converter to keep them on the read side.
