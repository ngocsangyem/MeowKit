`mk:autobuild` runs a step-file pipeline (plan, contract, generate, evaluate, iterate or ship, run report) for a green-field product. The amount of scaffolding is chosen from the model tier. Use it for "build me an app" requests that should run for hours without hand-holding.

## When not to use it

| If you need | Use |
|---|---|
| A single feature, bug fix or refactor | `mk:cook` |
| A docs update, an explanation or a review | the matching single-shot skill |

## Usage

```bash
/mk:autobuild build a kanban board with drag-and-drop
/mk:autobuild build a todo app --tier full
/mk:autobuild build a markdown editor --budget 25 --max-iter 2
/mk:autobuild "build payment system" --tdd
/mk:autobuild build a kanban board --advice
```

| Flag | Meaning |
|---|---|
| `--tier auto\|full\|lean\|minimal` | Force a density. `MEOWKIT_AUTOBUILD_MODE` does the same through the environment |
| `--max-iter N` | Generator and evaluator rounds before escalating. Default 3 |
| `--budget USD` | Spend cap. The run stops at this value |
| `--tdd` | Writes `.meowkit/state/tdd-mode`. The developer waits on the tester before each generator iteration |
| `--advice` | Strategic supervision by the [athena](/reference/agents/athena) agent, off by default |

## Steps

| Step | Action |
|---|---|
| 0 Tier detection | `mk:scale-routing` picks MINIMAL, FULL or LEAN |
| 1 Plan | `mk:plan-creator --product-level`, written as user stories rather than file paths |
| 2 Contract | `mk:sprint-contract`: required for FULL, optional for LEAN, skipped for MINIMAL |
| 3 Generate | A developer subagent builds to the contract and hands off |
| 4 Evaluate | `mk:evaluate` drives the running build against rubrics |
| 5 Iterate or ship | PASS goes to the shipper. FAIL loops back to step 3 up to `--max-iter` rounds, then escalates to you |
| 6 Run report | Appends the audit trail |

## Density

| Mode | Tier | Planner | Contract | Iterations |
|---|---|---|---|---|
| MINIMAL | TRIVIAL (Haiku) | Skipped (`--fast`) | Skipped | Skipped |
| FULL | STANDARD (Sonnet), COMPLEX (Opus 4.5) | Required | Required | 1 to 3 rounds |
| LEAN | COMPLEX (Opus 4.6 and later, Fable) | Required | Optional | 0 to 1 rounds |

Density never skips the review of the diff or the verdict before shipping. The full matrix is `references/adaptive-density-matrix.md`.

## Limits

| Limit | Value |
|---|---|
| Budget | `scripts/budget-tracker.sh` warns, then blocks, then honours your `--budget` cap; thresholds come from `.meowkit/config.yaml` |
| Wall clock | 6 hours, with a checkpoint at every step |
| Iterations | 3 rounds by default, then escalates |

If `budget-tracker.sh` says to stop, the run halts even mid-iteration.

## `--advice`

At macro checkpoints the athena agent gives direction at the plan and contract boundary, rescue on a plateau or scope drift, a read of the final evaluator verdict before the ship question, and a recheck after a correction. At most 5 calls per run, so a five-round build makes no more calls than a one-round build. Athena approves nothing: the ship decision stays yours and the evaluator keeps its own verdict. Checkpoints are in `references/advice-checkpoints.md`.

## Outputs

| Artifact | Location |
|---|---|
| Run report | `tasks/autobuild-runs/YYMMDD-{slug}/run.md` |
| Product plan | `tasks/plans/{plan-dir}/plan.md` |
| Sprint contract | `tasks/contracts/{date}-{slug}-sprint-N.md` |
| Evaluator verdict | `tasks/reviews/{slug}-evalverdict.md` |

The run report holds the density decision, per-step artifacts, the budget trail and the final status: PASS, WARN, FAIL, ESCALATED or TIMED_OUT. It is append-only, and a killed run restarts from its `next_step`.

## Gotchas

- Use `mk:cook` for anything smaller than a whole product.
- After round 3 the run escalates instead of iterating further.
- `MEOWKIT_AUTOBUILD_MODE=LEAN` drops the sprint contract, not the review.
