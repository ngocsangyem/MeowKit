## What it does

Generates `llms.txt`, a markdown index of your project documentation in the llmstxt.org format, and optionally `llms-full.txt` with the content inlined. A Python script does the scanning, title extraction and categorising. Claude reviews the preview and improves the descriptions. Use it when you want a docs site to be easy for AI assistants to read, or after a large documentation update.

## When not to use

To fetch current library docs use `mk:docs-finder`. To write the docs themselves use `mk:docs-init` or `mk:document-release`.

## Usage

```bash
/mk:llms [path] [--full] [--output path] [--url base]
```

| Flag | Effect |
|---|---|
| none | Scan `./docs` |
| `path` | Scan that directory |
| `--full` | Also write `llms-full.txt` with inline content |
| `--output path` | Output location (default: project root) |
| `--url base` | Base URL prefix for links |

The script is `scripts/generate-llms-txt.py` and takes `--source`, `--output`, `--base-url`, `--full` and `--json` (preview metadata only). It runs through `node .claude/hooks/lib/skill-python.cjs`. Run `mewkit skill env llms` once from the project root first, and again after upgrading the toolkit.

## Steps

1. Run the script with `--json` to preview metadata.
2. Check the project name, description and file categories.
3. Run it again without `--json` to write `llms.txt`.
4. Read the result and improve descriptions.
5. Check that it has an H1, a blockquote summary, valid links and the Optional section last. With `--full`, check `llms-full.txt` too.

## Output

`llms.txt` has an H1 with the project name, a blockquote summary, H2 sections of `- [Title](url): one-sentence description` entries, and an `## Optional` section. The rules are in `references/llms-txt-spec.md`. A file with no H1 uses its filename as the title and warns. If no `.md` files are found the skill reports it.

The skill only indexes documentation that exists, follows the spec, and keeps each description to one sentence. It is used in Phase 6 (Reflect) or on demand and feeds the `documenter` agent.
