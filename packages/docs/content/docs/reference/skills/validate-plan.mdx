## What it does

`mk:validate-plan` scores a plan from `mk:plan-creator` on eight dimensions and reports a pass, warn or fail for each, so gaps surface before implementation. It reads the plan and changes nothing. If a plan needs an insert or split, the planner makes the change. Run it once the plan is agreed and before Phase 2 (Test). In `/mk:cook` it runs automatically for complex tasks, is optional for standard ones and is skipped for trivial ones.

## When not to use it

| Need | Use |
|---|---|
| Greenfield harness sprints (generator and evaluator loop) | `mk:sprint-contract` |
| A founder-style critique of ambition and scope | `mk:plan-ceo-review` |
| Checking that required plan sections exist | `mewkit plan check --structural` |

The structural check validates plan file structure. This skill judges content quality, and both can run.

## Dimensions

| # | Dimension | Passes when |
|---|---|---|
| 1 | Scope clarity | In-scope and out-of-scope sections are explicit and do not overlap |
| 2 | Acceptance criteria | Every criterion is binary ("response under 200ms", not "feels fast") |
| 3 | Dependencies resolved | External dependencies are listed with a status |
| 4 | Risks identified | At least one risk has a mitigation. A plan with none was not evaluated. |
| 5 | Architecture documented | The approach references existing patterns or an ADR |
| 6 | Test strategy | The tests cover the acceptance criteria and name the edge cases |
| 7 | Security considered | Auth, data access and input validation are addressed, or marked N/A |
| 8 | Effort estimated | An estimate with a confidence level |

## Steps

1. Read `tasks/plans/YYMMDD-name/plan.md`.
2. Check each dimension and write the report: a table of dimension, status (PASS, FAIL or WARN) and a specific finding, then `[N]/8 passed` and the action.
3. Run a whole-plan consistency sweep over `plan.md` and every `phase-*.md`. It looks for stale references to renamed or dropped items and lists them under `sweep_failures` with file and line. Sweep failures do not fail the plan, but you reconcile them before Phase 3. The sweep is skipped when the plan has no phase files.
4. Route the result. All pass means proceed to Phase 2. Any FAIL returns to the planner with specific revisions. A WARN leaves the choice to you.

The skill does not replace your own read of the plan and does not generate tests.
