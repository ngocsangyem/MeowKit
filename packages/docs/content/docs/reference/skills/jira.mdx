## What it does

mk:jira picks the right `mk:jira-*` leaf for a Jira task and points at it. It executes no `jira-as` commands. Each of the 16 leaves runs with `context: fork` against its matching agent in `.claude/agents/`. The skill is not enabled by default (`default_enabled: false`). If you already know the leaf, invoke it directly.

## When to use it

Use it for "jira", "jira ticket" or any Jira request where the leaf is unclear.

## Setup

`mewkit skill env jira` installs `jira-as` into `.meowkit/envs/jira/`. Fill `.meowkit/.env` with the three `MEOW_JIRA_*` variables. Install, authentication, safety rules and troubleshooting are in [Jira integration](/guides/jira-integration) and `references/install-and-auth.md`. The variable list is in [Environment Variables](/reference/environment-variables#jira).

The SessionStart handler `jira-env-loader.cjs` checks the environment, and `scripts/jira-as.sh` translates `MEOW_JIRA_*` into the native `JIRA_*` variables and sets `JIRA_OUTPUT=json`.

## Handoffs

`mk:intake` recommends a leaf from triage. `mk:cook` may call `mk:jira-issue` to create implementation tickets. `mk:ship` may call `mk:jira-dev` for the branch name and PR body. `mk:planning-engine` uses `mk:jira-evaluator` and `mk:jira-estimator` output. `mk:confluence` is the matching router for Confluence.

## Gotchas

- If you are thinking about `jira-as` commands inside this skill, forward to a leaf instead.
- When `jira-as` is unusable (mTLS, multi-profile), the Atlassian MCP can be used directly as `references/install-and-auth.md` describes. The router does not fall back to it.
