## What it does

`mk:session-continuation` carries unfinished work across a context reset. It is not user-invocable. It applies when the runtime reports the context nearing its limit, or when you say "handoff", "save", "pause" or "resume". It adds no state file of its own: the plan files and the `mewkit` task records are the state.

## When not to use it

To record a lesson for the team, use `mk:memory`. This skill stores progress, not knowledge.

## Save

1. Tick the plan checkboxes for finished work, then run `mewkit plan sync <plan-dir>`.
2. If an active durable task exists, run `mewkit task-state update <id> --step "..." --next "..."`.
3. Report what was saved and the next step. Done when `mewkit orient` returns that next step.

## Resume

Run `mewkit orient`, then read the plan it points to with `mewkit plan status <plan-dir>`. Check the result against the live files and git before acting.

## Gotchas

- Saved state can name files that were renamed or deleted since. Check every path before resuming.
- With several active plans, ask which to resume.
- Without `mewkit` on the PATH, update the plan checkboxes by hand and note the next step in the plan.
