## What it does

`mk:session-continuation` saves the state of an unfinished workflow so a later session can pick it up. It is not user-invocable. It runs when the runtime reports that the context is nearly full, when you say "handoff", "save" or "pause", when you say "resume" with a workflow ID, or when a session ends with work incomplete.

## When not to use it

To record a lesson for the team, use `mk:memory`. This skill stores progress, not knowledge.

## Commands

```
workflow:handoff           save state and print resume instructions
workflow:resume AUTH-123   load state and continue from the last phase
workflow:list              list saved workflows
```

## Where state lives

Saved workflows are in `.claude/logs/workflows/`. The active plan is read from `.meowkit/state/active-plan.json` or found by scanning `tasks/plans/`. Nothing is carried between sessions in the environment.

## Steps

1. Detect the trigger: context limit, user command or session end.
2. For a handoff, follow `references/handoff-flow.md` to save the state and write a summary.
3. For a resume, follow `references/resume-and-state.md` to load the state, restore it and continue.
4. For a list, show the workflows saved in `.claude/logs/workflows/`.

## Gotchas

- Saved state can name files that were renamed or deleted since. Check every path in a handoff before resuming.
- Two sessions writing state at once corrupt the TOON file. Use file locking or session-scoped state files.
