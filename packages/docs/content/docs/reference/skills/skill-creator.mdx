## What it does

`mk:skill-creator` creates a skill with the right structure. Python scripts scaffold the folder and validate it, and Claude fills in the content. Use it when you ask to create a skill, adopt an external one or turn a workflow into a skill. It is not tied to a workflow phase.

## When not to use it

For the trust model of a skill that handles untrusted input, use the `mk:skill-template-secure` template. Skill Creator loads it when needed.

## Usage

```
/mk:skill-creator [skill-name] [description]
```

Run the scripts from the project root:

```bash
node .claude/hooks/lib/skill-python.cjs ${CLAUDE_SKILL_DIR}/scripts/init-skill.py mk:my-feature --path .claude/skills
node .claude/hooks/lib/skill-python.cjs ${CLAUDE_SKILL_DIR}/scripts/validate-skill.py .claude/skills/my-feature
```

## Steps

1. Ask what failure or gap prompted the skill and which existing skill was checked. If an existing skill covers it, extend that one.
2. Read the authoring rules that apply (`references/skill-authoring-rules.md`).
3. Gather the intent: what the skill does, when it triggers, when it does not and what it returns.
4. Scaffold with `init-skill.py`, which creates `<path>/<slug>/SKILL.md` (no `mk:` prefix on the directory) with TODO markers.
5. Write the body as goal, outcome and boundaries; move detail into `references/`. Load `mk:skill-template-secure` if the skill reads untrusted input.
6. Check with `mewkit validate --frontmatter` and `mewkit validate --skill-rubric`; `validate-skill.py` is a quick structural pre-check with one pass mark.
7. Try the skill once on a real task, then add a row to `SKILLS_ATTRIBUTION.md` if the project keeps one.

## Checks

`SKILL.md` stays at or under 500 lines and about 5,000 tokens, the name carries the `mk:` prefix, no TODO markers remain, and the description says what the skill does with a `NOT for` clause (the trigger goes in `when_to_use`). A `## Gotchas` section is added once a real failure earns it.

## Gotchas

- The line cap is 500 lines and about 5,000 tokens, and a normal run should read far less.
- A `## Gotchas` section is added with the first real failure, not as a placeholder.
- State that must survive an upgrade goes to the host's stable data location (`${CLAUDE_PLUGIN_DATA}` on Claude Code), not the skill folder. Framework paths such as `.meowkit/memory/` and `.meowkit/state/` are exempt.
- A missing `mk:` prefix on the name is added; a duplicate name gets an alternative or an update to the existing skill.
