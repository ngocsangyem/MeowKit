## What it does

`mk:skill-creator` creates a skill with the right structure. Python scripts scaffold the folder and validate it, and Claude fills in the content. Use it when you ask to create a skill, adopt an external one or turn a workflow into a skill. It is not tied to a workflow phase.

## When not to use it

For the trust model of a skill that handles untrusted input, use the `mk:skill-template-secure` template. Skill Creator loads it when needed.

## Usage

```
/mk:skill-creator [skill-name] [description]
```

Run the scripts from the project root:

```bash
node .claude/hooks/lib/skill-python.cjs ${CLAUDE_SKILL_DIR}/scripts/init-skill.py mk:my-feature --path .claude/skills
node .claude/hooks/lib/skill-python.cjs ${CLAUDE_SKILL_DIR}/scripts/validate-skill.py .claude/skills/my-feature
```

## Steps

1. Read `references/skill-authoring-rules.md`. It holds the ten authoring rules, such as the mandatory `## Gotchas` section, `${CLAUDE_PLUGIN_DATA}` for persistent state and the 500-line cap.
2. Gather the intent: what the skill does, when it triggers and what it outputs.
3. Scaffold with `init-skill.py`, which creates the folder and a template `SKILL.md` with TODO markers.
4. Fill each TODO. Move detail into `references/` when the body passes about 100 lines.
5. Load `mk:skill-template-secure` if the skill needs a trust model.
6. Validate with `validate-skill.py`. A score below 7 of 8 means fix the failing items first.
7. Add a row to `SKILLS_ATTRIBUTION.md`.
8. Report the directory, files, compliance score and registration.

## Compliance checks

| Check |
|---|
| The name has the `mk:` prefix |
| A workflow phase (0 to 6) is stated |
| A handoff names the next agent |
| The output format is a template with placeholders |
| Failure handling covers the known failure modes |
| `SKILL.md` is 500 lines or fewer (step-file skills with a `workflow.md` pass automatically) |
| A `## Gotchas` section exists (a placeholder is fine on day one) |
| It does not conflict with `.claude/rules/` |

## Gotchas

- The `## Gotchas` header is mandatory because `validate-skill.py` checks it. A day-one placeholder is allowed.
- The line cap is 500.
- State that must survive a plugin upgrade goes to `${CLAUDE_PLUGIN_DATA}`, not the skill folder. Framework paths such as `.meowkit/memory/` and `.meowkit/state/` are exempt.
- A missing `mk:` prefix is added with a warning, and a duplicate name gets an alternative or an update to the existing skill.
