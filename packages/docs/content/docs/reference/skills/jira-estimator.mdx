## What it does

mk:jira-estimator forks the `jira-estimator` agent ([agent page](/reference/agents/jira-estimator)). It estimates from the ticket description and historical comparison, and returns a suggested value, a range, a confidence level and reasoning. If an earlier `mk:jira-evaluator` report exists at `tasks/reports/jira-evaluate-*-{KEY}.md`, it reads that report and uses its complexity signals. The skill is not enabled by default.

## When to use it

Use it for "estimate PROJ-123", "story points for PROJ-123" or "how complex is PROJ-123 in points".

| Need | Use instead |
|---|---|
| Complexity analysis only | [`mk:jira-evaluator`](/reference/skills/jira-evaluator), which is best run first |
| Full ticket synthesis or RCA | [`mk:jira-analyst`](/reference/skills/jira-analyst) |
| Size pasted stories before tickets exist | `mk:story-sizer` |

## Story points field

The agent first checks the per-instance field ID:

```bash
bash $CLAUDE_PROJECT_DIR/.claude/skills/jira/scripts/jira-as.sh fields list --search "Story Points" \
  | jq '.[] | select(.name == "Story Points") | .id'
```

`customfield_10016` is the documented default. If the discovered ID differs, the discovered one is used. [`mk:jira-fields`](/reference/skills/jira-fields) covers field discovery.

## Output

```markdown
## Estimation: {ISSUE-KEY}
**Suggested Points:** {N} (range: {low-high})
**Confidence:** {High|Medium|Low}
### Reasoning
### To apply:
jira-as.sh issue update {ISSUE-KEY} --custom-fields '{"customfield_10016": {N}}'
```

Applying the estimate is a separate step through [`mk:jira-issue`](/reference/skills/jira-issue). The report is saved to `tasks/reports/jira-estimate-{YYMMDD}-{HHMM}-{ISSUE-KEY}.md`, and `mk:planning-engine` can use it.

## Escalation

The agent flags the ticket for human estimation when the range spans more than one Fibonacci step, the project has no precedent for this work, the ticket names unfamiliar technology, or the description is vague (under 30 words and no acceptance criteria).
