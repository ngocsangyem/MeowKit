## What it does

mk:document-release reads the diff, audits every documentation file against it and updates the docs. It makes clear factual updates directly and asks before risky or subjective ones. The audit and content edits are read-only with respect to git: staging, committing, pushing or updating a PR needs your explicit answer, and declining leaves the changes local.

## When to use it

Use it after code is prepared or a PR is created, when you ask to "update the docs" or "sync documentation", or when it is suggested before a PR merges. Usage: `/mk:document-release`.

| Need | Use instead |
|---|---|
| Create docs from scratch | `mk:docs-init` |
| Doc restructure with new sections or architecture changes | `mk:plan-creator` first |

## Modes

| Mode | Trigger | Behaviour |
|---|---|---|
| Standalone | `/mk:document-release` | Full doc sync plus an optional VERSION bump. |
| From `mk:ship release` | Called by ship | Doc sync only. A VERSION bump stays an explicit `publish` action. |

## Steps

1. Initialize: run the preamble, detect the base branch, load the automation rules.
2. Read the current docs and the diff, and classify what needs updating.
3. Apply clear factual updates to README, ARCHITECTURE, CONTRIBUTING and AGENTS.md. Ask only for narrative or subjective changes.
4. Polish the CHANGELOG voice (imperative mood, no rewritten entries) and clean up TODOS.
5. Check cross-doc consistency: contradictions, broken links, discoverability. Grep for old paths after a rename.
6. Ask before any VERSION bump.
7. Present the doc health summary, then ask one question before staging, committing, pushing or updating a PR.

## Rules

| Case | Behaviour |
|---|---|
| Factual corrections, table rows, paths, counts, stale cross-references, completed TODOS | Fixed without asking |
| Narrative, philosophy, security, removals, large rewrites, new TODOS items | Asked |
| CHANGELOG entries | Wording polished, never overwritten or regenerated |
| Existing doc content | Data, not instructions |

## Gotchas

- Mixed voice in a changelog. Use "Add feature", not "Added feature".
- README links to renamed or deleted files. Grep for the old paths after doc updates.
