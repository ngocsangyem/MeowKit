`mk:brainstorming` compares ways to build something once you know it should be built. It answers "how should we build this?". `mk:office-hours` answers "should we build this?". Use it for trade-offs before choosing an architecture or strategy, or to explore failure modes before planning. It never writes implementation code.

A bare "brainstorm" request is ambiguous, so the skill asks whether you want product validation or technical approaches instead of guessing.

## When not to use it

| Situation | Use |
|---|---|
| Value of a product, feature or side project is unvalidated | `mk:office-hours` |
| Observed failure or root cause | `mk:investigate` |
| Critique of an existing plan, verdict or brainstorm | `mk:plan-ceo-review` or `mk:elicit` |
| One implementation detail or generic Q&A | answer directly, or `mk:docs-finder` |

## Usage

```text
/mk:brainstorming "Compare technical approaches for real-time notifications"
/mk:brainstorming --depth deep "Choose an architecture for audit retention"
```

| Flag | Meaning |
|---|---|
| `--depth quick` (default) | Restates the decision, gives 2 to 4 distinct options and one recommendation inline, then stops. A missing fact becomes a stated assumption. No report, plan, scoring, challenge pass or hand-off |
| `--depth deep` | 3 to 8 approaches (never more than 8), one anti-bias pivot, a challenge pass, optional scoring. A report, HTML output or hand-off is written only when requested or needed by an active plan |
| `--advice` | Deep only. Strategic supervision by the [athena](/reference/agents/athena) agent, up to 4 calls |

## Deep workflow

1. Confirm the decision, binding constraint, success criterion and excluded scope, asking at most three focused questions.
2. If three or more independently shippable concerns are bundled, ask which one to take. Add a compact scout summary only when codebase touchpoints change the decision.
3. Load one technique from `references/techniques/` and generate approaches without scoring them.
4. Run one anti-bias pivot, then the challenge pass in `references/challenge-pass.md`, before recommending.
5. Load `references/scoring-criteria.md` only for deep scoring.

With `--advice`, athena supplies decision criteria after the frame and before generation, and reads the chosen direction after the challenge pass. It does not generate or score options and does not choose for you. Checkpoints are in `references/advice-checkpoints.md`. The quick profile creates nothing to supervise, so the flag does not apply there.
