## What it does

`mk:worktree` manages git worktrees through `scripts/worktree.cjs`. Each parallel agent gets its own worktree so file edits do not collide. The orchestrator (`mk:cook`, `mk:workflow-orchestrator`) calls it when a complex task splits. It is not user-invocable. `references/commands.md` has the full option and JSON reference.

## When not to use it

To plan a whole parallel team with ownership map and task queue, use `mk:team-config`, which calls this skill.

## Actions

Run the commands as `node ${CLAUDE_SKILL_DIR}/scripts/worktree.cjs <action> ... --json`.

| Action | What it does |
|---|---|
| `info` | Reports repository state. Run it before `create`. |
| `create "{agent-name}" --orchestrated` | Creates `.worktrees/{agent-name}` on branch `parallel/{agent-name}-{timestamp}`. Give the returned `worktreePath` to the agent as its working directory. |
| `merge` | `git merge --no-ff {branch}` into the feature branch. On conflict it stops and reports to the orchestrator, with no auto-resolve. After a clean merge, run the full test suite, then delegate a status report to `project-manager` in the background unless `MEOWKIT_PM_AUTO=off`. |
| `remove "{agent-name}"` (cleanup) | Removes a worktree MeowKit created. Release the agent's `mk:task-queue` ownership first. Refuses uncommitted or untracked work unless `--discard-changes`. |
| `list` | Lists worktrees, each with its `owner`. |
| `status` | Shows ahead and behind divergence and dirty state, and the count of active worktrees. |
| `prune --dry-run`, then `prune` | Cleans stale worktree metadata. Dry run first. |
| `review-pr --pr N --remote <name> --session <id>` | Creates a detached worktree pinned to a PR head for assured review. Add `--dry-run` to validate only. |
| `review-pr-cleanup --manifest <path>` | Removes a review worktree. `--sweep --dry-run` finds stale sessions, and `--apply` executes. |

## Where worktrees go

Every worktree lands under `<main checkout>/.worktrees/`, on every runtime, and also when the script runs from inside a linked worktree. `--worktree-root` or the `WORKTREE_ROOT` environment variable moves it, and the script warns when they do. On the first create the script writes `.worktrees/.gitignore` holding `*`, so the directory hides itself from git and ripgrep and your own `.gitignore` is left alone. Test runners that do not read `.gitignore` (some jest and vitest setups) may still scan `.worktrees/`; exclude it in their config.

## Who owns a worktree

Each worktree the script creates gets a `meowkit-owner.json` marker in its private git dir, outside the working tree. `list` and `status` report an `owner` for every worktree:

| Owner | Meaning | `remove` |
|---|---|---|
| `main` | The main checkout | never |
| `kit` | Has the marker | yes |
| `review` | A `review-pr` worktree | no, use `review-pr-cleanup` |
| `legacy` | No marker, directly under `<main>/.worktrees/` | yes, with a warning |
| `foreign` | Anything else, such as another runtime's worktree | never |

A term that matches only `review` or `foreign` worktrees fails with `FOREIGN_WORKTREE`. A worktree with uncommitted or untracked files fails with `WORKTREE_DIRTY` and lists the files; `--discard-changes` deletes them. Ignored files, such as a copied `.env`, are not checked and go with the worktree.

Parallel agents use these worktrees, not a host's own isolation (Claude Code agent frontmatter `isolation: worktree`, OMP and Antigravity task isolation, Codex and Cursor app worktrees). Each host keeps those somewhere else, and MeowKit cannot see or clean them.

`review-pr` fetches `pull/N/head` from the PR's base remote, never a fork. It writes `tasks/reviews/<session>/manifest.json` and a `.mewkit-review.json` back-reference inside the worktree. Cleanup runs only when the manifest's nonce matches that back-reference and the target is a detached `.worktrees/review-pr-*` worktree, so it can never remove the main checkout or a feature worktree. Force is allowed, since review worktrees are dirty after builds.

## Safety rules

- Create worktrees only on feature branches, never on `main` or `master`.
- Keep at most 3 active worktrees.
- Remove worktrees after the merge. Stale ones keep their branches checked out.
- `remove` only deletes worktrees MeowKit created, and keeps uncommitted work unless told otherwise.
- Never force-push from a worktree. It shares `.git` with the main checkout.

## Gotchas

- Creation fails with `BRANCH_CHECKED_OUT` if the branch exists. Timestamps in orchestrated branch names prevent collisions.
- `git worktree remove` fails silently when the directory was already deleted by hand. The script checks existence first.
- Merge conflicts on `SKILL.md` and `CLAUDE.md` are common in parallel runs. Stop and report them.
- On macOS, quote paths that contain `:` from skill names.
