## What it does

Manages links between issues: link, unlink, find blockers and dependencies, clone and bulk-link. It forks the `jira-relationships` agent. Direction matters, because `A blocks B` is not `B blocks A`, so the agent confirms direction when a request is ambiguous.

## When not to use

Epic membership and sprints belong to `mk:jira-agile` (an epic child is added with `agile epic add`). Use `mk:jira-search` to find candidate issues first, and `mk:jira-bulk` for other bulk changes.

## Usage

Ask in plain words: "link PROJ-123 blocks PROJ-456", "what blocks PROJ-123?", "clone PROJ-123 with new summary 'Follow-up'", "unlink PROJ-123 from PROJ-456".

| Operation | Command |
|---|---|
| Link | `jira-as.sh relationships link PROJ-123 --type blocks --to PROJ-456` |
| Unlink | `jira-as.sh relationships unlink ...` |
| Blockers | `jira-as.sh relationships get-blockers PROJ-123 [--recursive --depth N --output tree]` |
| Dependencies | `jira-as.sh relationships get-dependencies PROJ-123 [--output mermaid\|dot]` |
| Clone | `jira-as.sh relationships clone PROJ-123 [--to-project OTHER --include-links --include-subtasks]` |
| Bulk link by JQL | `jira-as.sh relationships bulk-link ...` (the agent runs a dry run first) |

`jira-as.sh` is `.claude/skills/jira/scripts/jira-as.sh`. The `jira-as` tool is not part of this repository, so check flags with `--help`. Common link types are `blocks`, `is blocked by`, `relates to`, `clones`, `duplicates` and `causes`; custom types can exist per project.

## Outputs

The agent returns the link ID, source key, relationship, target key and URL. For bulk-link it returns the dry-run summary, the impacted count and the confirm command.
