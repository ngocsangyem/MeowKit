## What it does

`mk:team-config` prepares the infrastructure for parallel agents. The orchestrator calls it when a complex task splits into independent subtasks. It is not user-invocable.

## When not to use it

To create or clean up a single git worktree, use `mk:worktree`. Team Config calls it for each agent.

## Setup

1. Parse the agreed plan for independent subtasks.
2. Write the ownership map as task entries with file globs, in the format `mk:task-queue` owns.
3. Check that no two ownerships overlap.
4. Create one git worktree per agent through `mk:worktree`.
5. Create `.meowkit/state/task-queue.json` through `mk:task-queue`.

Parallel agents then start claiming tasks.

When team mode activates, the skill reads `references/team-coordination.md`: file ownership per task, no force-push, commits on the worktree branch, actionable completion messages and who owns the docs-impact check. Those rules load only on team activation.

## Constraints

- At most 3 parallel agents, from `.claude/skills/cook/references/parallel-execution-rules.md`.
- Only complex tasks qualify, and the orchestrator decides that.
- All worktrees branch from the current feature branch HEAD.

## Teardown

After all agents finish and the integration test passes, merge the worktree branches into the feature branch, remove the worktrees with `mk:worktree cleanup` and archive `.meowkit/state/task-queue.json`.

## Gotchas

- Two subtasks that need the same file cannot run in parallel. Restructure the split or handle the shared file in a sequential step first.
- Skill names with a colon, such as `mk:review`, need quoting in shell paths.
- Run `git worktree list` before creating new ones, to catch orphans from crashed sessions.
- Run the full test suite after merging all worktrees. Each passed alone, so a failure here points to a conflict between them.
