## What it does

Helps when you are stuck on an approach, not on a cause. It offers seven techniques, each aimed at one way default thinking fails. You match the symptom to a technique, load that technique's reference and apply it. Use it when an implementation keeps spiralling into special cases, a constraint is accepted without evidence, or a system keeps growing.

## When not to use

| Situation | Use |
|---|---|
| Something is broken and needs a fix | `mk:fix` |
| Reasoning about a cause without fix intent | `mk:sequential-thinking` |
| Open exploration before a plan exists | `mk:brainstorming` |
| A known-options trade-off | `mk:party` |
| Re-examining an existing output or verdict | `mk:elicit` |
| A trivial fix with an obvious cause | No skill |

## Usage

Describe the stuck point in words, for example "I've implemented this five ways and it keeps growing special cases". The skill picks a technique. If the symptom is unclear, `references/when-stuck.md` is a dispatch flowchart.

| Stuck symptom | Technique | Reference |
|---|---|---|
| Same thing built five or more ways, special cases growing | Simplification cascades: one insight removes many components | `simplification-cascades.md` |
| Conventional solutions fall short | Collision-zone thinking: force two unrelated domains together | `collision-zone-thinking.md` |
| Same issue across domains | Meta-pattern recognition: a pattern in three or more domains is likely general | `meta-pattern-recognition.md` |
| The solution feels forced | Inversion: flip the core assumption | `inversion-exercise.md` |
| "Should scale fine" with no evidence | Scale game: test at 1000 times bigger and smaller | `scale-game.md` |
| Told it is impossible, or reasoning by analogy | First principles: rebuild from verified basics | `first-principles.md` |
| A bloated system | Via negativa: improve by removing | `via-negativa.md` |

## Steps

1. Match the symptom to one technique.
2. Load only that reference.
3. Apply it, and write down what worked and what did not.
4. Combine techniques only if the first pass fails. Pairs the skill lists are simplification with meta-pattern, collision with inversion, scale with via negativa, and first principles with inversion.

Before writing any Mermaid block, the skill reads `.claude/skills/preview/references/mermaid-essentials.md`.

## Gotchas

| Trap | Detail |
|---|---|
| Stacking techniques | Finish or discard one before adding another. |
| Premature abstraction | A meta-pattern needs three or more domains, not two. |
| Metaphor over-fit | Every metaphor breaks. Record where. |
| Invalid inversion | "Trust all user input" is a security hole. An inversion must work in some real context. |
| Scale game without numbers | Estimate concretely. |
| Via negativa on used features | Confirm usage before removing anything. |
| Null results | If a technique gave nothing, log it and move on. |
