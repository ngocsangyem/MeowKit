`mk:angular` holds Angular v20+ guidance in ten topics and steers code toward signal-based, standalone patterns. It activates in Phase 3 (Build) when the project has `angular.json` or `@angular/core` in `package.json`, and the `developer` agent loads it alongside `mk:typescript`. You can also invoke it as `/mk:angular`.

## When not to use it

For general TypeScript typing and patterns use `mk:typescript`. For Vue use `mk:vue`.

## Defaults it applies

| Do | Not |
|---|---|
| Standalone components | NgModule |
| `input()`, `input.required()`, `output()` | `@Input`, `@Output` |
| `signal()`, `computed()`, `linkedSignal()` | `BehaviorSubject` for component state |
| `inject()` in field initializers | Constructor injection |
| `@if`, `@for` with `track`, `@switch` | `*ngIf`, `*ngFor` |
| `ChangeDetectionStrategy.OnPush` on every component | Default change detection |
| Functional guards, resolvers and interceptors | Class-based ones |
| `resource()` and `httpResource()` | Manual `HttpClient` subscribe for loading data |

## Gotchas

The five most common mistakes are `@Input` and `@Output` decorators, `*ngIf` and `*ngFor`, constructor injection, `BehaviorSubject` for component state, and class-based guards or interceptors. Each has a signal or functional replacement in the table above.
