## What it does

`mk:sequential-thinking` structures analysis as a list of hypotheses, each with evidence for and against, then concludes with a root cause, a confidence level and the scope of the fix. Use it when the cause is not obvious, a decision has several trade-offs, or "I think it's X" needs evidence before anyone acts. `mk:fix` calls it during diagnosis.

## When not to use it

Skip it for trivial fixes (a typo, a lint error) and single-file changes with an obvious cause. For structured problem-solving techniques, use `mk:problem-solving`.

## Steps

1. State what is observed against what is expected.
2. List hypotheses drawn from evidence, each with what would confirm it and what would refute it.
3. Test them with Grep, Read or Bash.
4. Mark each CONFIRMED, REFUTED or INCONCLUSIVE with its evidence.
5. State the root cause, a confidence level and the evidence chain.
6. Scope the fix to the cause, not the symptoms.

When new evidence overturns a conclusion, mark it as `[REVISION of Hypothesis N]: correction and reason`. When two approaches are viable, branch, evaluate both and converge on one.

## Output

The analysis follows `references/hypothesis-testing.md`: a hypotheses table (hypothesis, evidence for, evidence against, status), the root cause with confidence and evidence, and the fix scope.

## Scripts

| Script | Use |
|---|---|
| `scripts/process-thought.js` | Validates and tracks thoughts, branches and revisions (20 thoughts at most). `--summary` prints a short handoff for `mk:fix`. |
| `scripts/format-thought.js` | Formats a thought as box, simple, markdown or json. |

```bash
node scripts/process-thought.js --thought "..." --number 1 --total 5 --next true
node scripts/format-thought.js --thought "..." --number 1 --total 5 --format json
```

## Gotchas

- Test at least two hypotheses before concluding.
- Every hypothesis needs at least one piece of evidence.
- Revise explicitly when evidence contradicts you. The full list is in `references/gotchas.md`.

The usual chain is `mk:investigate`, then this skill, then `mk:fix`.
