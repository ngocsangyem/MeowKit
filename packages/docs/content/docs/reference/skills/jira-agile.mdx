## What it does

mk:jira-agile forks the `jira-agile` agent ([agent page](/reference/agents/jira-agile)) to run `jira-as agile` commands. It resolves a board name to its numeric `--board-id` first. The skill is not enabled by default.

## When to use it

Use it for "list sprints on board X", "add PROJ-123 to sprint 42", "set 5 story points", "rank PROJ-123 before PROJ-456", "velocity for board 42" or "create epic".

| Need | Use instead |
|---|---|
| Issue create, read, update, delete | [`mk:jira-issue`](/reference/skills/jira-issue) |
| Time tracking | [`mk:jira-time`](/reference/skills/jira-time) |
| Story-point estimates for one ticket | [`mk:jira-estimator`](/reference/skills/jira-estimator) |

## Board ID

Sprint operations need the numeric board ID, not the project key. Resolve a board name first:

```bash
bash $CLAUDE_PROJECT_DIR/.claude/skills/jira/scripts/jira-as.sh agile board list --name "Team Alpha"
```

## Sprint operations

| Operation | Safety tier |
|---|---|
| Create a sprint | 2 |
| Add issues to a sprint, move issues to backlog | 2 |
| Start a sprint | 3, shows sprint details first |
| Complete a sprint | 4, dry run first, shows incomplete issues and where they go, then asks you to type a confirmation |
| Bulk move of more than 10 issues | 4, dry run and confirmation |

Velocity is approximated with JQL over closed sprints with status Done, grouped by sprint. The flags of each command are in `references/sprint-operations.md` and `jira-as agile --help`.

## Sprint commitment

If `tasks/contracts/sprint-state-{date}-sprint-{N}.md` exists with `status: active` (Agile context only, governed by `agent-detector/references/agile-sprint-commitment.md`), two operations add a step. With no such file, or a closed one, the steps are skipped.

| Operation | Added step |
|---|---|
| `sprint add` or `sprint remove` after start | Take a `flock` on the sprint-state file, ask you for the reason, append `{ ts, action, ticket, reason }` to `amendments:`, release the lock, then run the call |
| `sprint close` | Read `committed_tickets:`, check each with `mk:jira-issue get`, ask what to do with each non-terminal ticket (carry over, drop, mark not delivered), write `status: closed`, `closed_at`, `delivered` and `carried_over`, then run the call |

Sprint-state files have no validator. The skill, `mk:agent-detector` and `mk:sprint-contract sprint-goal` parse them inline.
