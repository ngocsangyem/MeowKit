## What it does

Logs work, lists worklogs, sets estimates and produces time reports. It forks the `jira-time` agent. Durations look like `30m`, `2h` or `1d 4h`.

## When not to use

Sprint capacity belongs to `mk:jira-agile`, JQL for worklog filters to `mk:jira-search`, and large bulk changes to `mk:jira-bulk`.

## Usage

Ask in plain words: "log 2h on PROJ-123 with comment 'paired with x'", "show worklogs for PROJ-123", "set original estimate 1d, remaining 4h on PROJ-123", "time report for project PROJ from 2026-04-01 to 2026-04-30".

| Operation | Command |
|---|---|
| Log work | `jira-as.sh time log PROJ-123 --time 2h [--adjust-estimate leave]` |
| List worklogs | `jira-as.sh time worklogs PROJ-123` |
| Edit or delete a worklog | `jira-as.sh time update-worklog ...`, `time delete-worklog ...` |
| Set estimates | `jira-as.sh time estimate PROJ-123 --original "1d" --remaining "4h"` |
| Tracking summary | `jira-as.sh time tracking PROJ-123` |
| Report or export | `jira-as.sh time report ...`, `time export ...` |
| Bulk log | `jira-as.sh time bulk-log ...` (dry run first) |

`jira-as.sh` is `.claude/skills/jira/scripts/jira-as.sh`. `time log` takes the issue key positionally and the duration as `--time`. The `jira-as` tool is not part of this repository, so check flags with `--help`.

## Steps

Editing or deleting a worklog overwrites or removes the stored duration, and Jira keeps no history of a deleted worklog. Before either, the agent reads the current worklog, shows the current and proposed values and waits for explicit confirmation. It returns the issue key, the new total logged, the remaining estimate and the URL.
