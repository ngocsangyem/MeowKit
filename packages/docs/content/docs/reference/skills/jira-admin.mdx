## What it does

mk:jira-admin forks the `jira-admin` agent ([agent page](/reference/agents/jira-admin)), which runs `jira-as admin` commands across 11 sub-domains (about 65 verbs). The skill is not enabled by default. It needs the Jira Admin role, and some verbs need Site Admin. Insufficient permission returns exit code 3.

## When to use it

Use it for "create JIRA project", "list users", "delete user", "list permission schemes", "create group" or "enable automation rule X on PROJ".

| Need | Use instead |
|---|---|
| Per-issue operations | [`mk:jira-issue`](/reference/skills/jira-issue), [`mk:jira-lifecycle`](/reference/skills/jira-lifecycle) |
| Service Management admin | [`mk:jira-jsm`](/reference/skills/jira-jsm) |

`mk:jira-fields` overlaps here: `fields create` needs admin. Most users run this skill once per project setup.

## Destructive operations

These are irreversible or affect access globally: `admin project delete` (removes all issues, attachments and history), `admin user delete`, and `admin group delete` for a group with members. The agent shows what will be deleted and asks you to type the literal target (for example the project key `STAGING`) before it runs the command without `--dry-run`. It never runs them on its own.

The agent offers archive first for projects and deactivate first for users, because those keep data and issue attribution.
