## What it does

mk:jira-dev forks the `jira-dev` agent ([agent page](/reference/agents/jira-dev)) to produce developer-side artifacts from a ticket: branch names, PR descriptions, commit parsing for issue keys, and commit or PR links. It generates artifacts only. The skill is not enabled by default.

## When to use it

Use it for "branch name for PROJ-123", "PR description for PROJ-123", "parse commits in main..HEAD for issue keys", "link this commit to PROJ-123" or a "Closes PROJ-123" footer.

| Need | Use instead |
|---|---|
| Run git operations | `mk:ship` |
| Issue create, read, update, delete | [`mk:jira-issue`](/reference/skills/jira-issue) |

The issue must exist before a branch is named. [`mk:jira-lifecycle`](/reference/skills/jira-lifecycle) handles transitions that a smart-commit footer triggers.

## Branch names

The default output is `<type>/<KEY>-<kebab-summary>`, for example `feat/PROJ-123-add-login-rate-limiting`, with the summary capped at about 50 characters.

```bash
bash $CLAUDE_PROJECT_DIR/.claude/skills/jira/scripts/jira-as.sh dev branch-name PROJ-123
```

`references/branch-naming.md` lists the options `--auto-prefix`, `--prefix <name>` and `--output git`.

## PR descriptions

The ticket summary becomes the PR title and an excerpt of the description becomes the body. Acceptance criteria become a checklist, and a "Closes PROJ-123" footer (Atlassian smart-commit format) is added. The output can be piped to `gh pr create`.

## Handoff to mk:ship

`mk:ship` can call `dev branch-name <KEY>` when it creates a branch. This is documented only, with no automatic wiring. You opt in by giving `mk:ship` the Jira key.
