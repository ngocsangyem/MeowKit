`mk:development` holds stack patterns for writing feature code outside a phase pipeline: NestJS and Swift. The `developer` agent reaches for it when it needs stack-specific patterns. It is done when the code compiles or type-checks, the project's existing tests pass and nothing outside the task changed.

## When not to use it

To run a whole feature through the phases, use `mk:cook`. For quality standards on code you are writing, add `mk:clean-code` alongside: patterns define structure, clean-code enforces quality.

## TDD

TDD is opt-in (`--tdd` or `MEOWKIT_TDD=1`). The default skips RED-phase enforcement, which suits prototypes and exploration. The rules live in `mk:cook`'s `references/tdd-rules.md`; `references/tdd-enforcement.md` here only points to them.

Stack patterns in `code-patterns.md`:

| Stack | Patterns |
|---|---|
| NestJS | Module, controller, service and DTO split. Guards on every protected controller. `ValidationPipe` on input. DTOs with validator decorators |
| Swift | MVVM with an `ObservableObject` per screen, `async throws` for I/O, protocols for service dependencies |
| All | Explicit return types on public APIs, no magic strings, prefer immutability, one concern per file |

## Gotchas

- Strict red-green slows exploratory prototyping. Leave TDD off for prototypes.
- Generated files (migrations, schemas) exceed the 200-line guideline by design. Exempt them in the plan's constraints.
