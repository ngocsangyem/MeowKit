The confluence-bulk agent is the executor for `mk:confluence-bulk` and calls Confluence Cloud through `.claude/skills/confluence/scripts/confluence-as.sh`.

It runs on `sonnet`. Tools: `Bash`, `Read`, `Grep`, `Glob`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it for a change across ten or more pages. For one page use [confluence-page](/reference/agents/confluence-page).

## Three-step procedure

1. Run the command with `--dry-run` (and `--max-pages 100`).
2. Show you the `would_*` summary, the impacted count and the first five page titles.
3. After you answer yes and type a confirmation phrase that includes the count, such as `DELETE 47 PAGES`, rerun without `--dry-run` and with `--yes`. A bare "yes" is not enough.

It refuses to skip the dry run even when asked. If the impacted count differs by more than 5% between the dry run and the real run, it raises that as a concern.

## Limits and failures

- The default cap is 100 pages. A higher cap needs an explicit override, and you restate the confirmation phrase after seeing the new count. The server may impose its own limit, typically 200 per request.
- CQL with user-derived terms goes through `cql-sanitize.sh` first.
- Bulk operations are not transactional. On a partial failure the wrapper reports X of N completed, and the fix is a rerun on the remaining set.

A dry run returns the count, the first five titles, the exact confirm command and the typed-token requirement. A real run returns the count changed, the first and last five pages and a CQL search URL.
