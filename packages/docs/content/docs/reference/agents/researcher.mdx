The researcher gathers and compares technical information before a decision. It presents findings and does not decide.

It runs on `sonnet`. Tools: `Read`, `Write`, `Grep`, `Glob`, `Bash`, `WebSearch`, `WebFetch`, `Edit`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Delegate it when a task needs external tools, libraries or patterns understood before implementation, for example "compare Prisma, TypeORM and Drizzle for our API". It works in Phase 0 (unfamiliar technology), Phase 1 (approaches for the planner) and Phase 4 (best practices when the reviewer raises a concern). Skip it when the repo or one doc lookup answers the question.

## Research chain

1. `mk:docs-finder` for library and API docs (Context7, then Context Hub, then llms.txt).
2. Codebase search for existing patterns.
3. `WebSearch`, only when the first two do not answer.

For an external URL outside those, it delegates to `mk:web-to-markdown` with `--wtm-accept-risk`.

## What it returns

The research question, the sources checked, findings per option with pros and cons (what it solves, what it costs, community health, production readiness), a recommendation, a High, Medium or Low confidence level and sources. It marks what is established, emerging or experimental, and flags stale information. It always evaluates alternatives before recommending one.

When the prompt gives a save path, it writes the report there in 150 lines or fewer. Otherwise it returns findings in the response.

## Limits

It writes no source, plans, verdicts or project docs, only a caller-specified research report. It does not expose credentials found during research.
