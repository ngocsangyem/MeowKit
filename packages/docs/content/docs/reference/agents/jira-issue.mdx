The jira-issue agent is the executor for `mk:jira-issue` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`. It never calls the `jira-as` binary directly.

It runs on `haiku`. Tools: `Bash`, `Read`, `Grep`, `Glob`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it to open, edit or delete one Jira issue by key. For ten or more issues use [jira-bulk](/reference/agents/jira-bulk). To read a ticket with its comments and media, use [jira-analyst](/reference/agents/jira-analyst).

## Environment

The `jira-env-loader.cjs` session-start hook has already validated `.meowkit/.env` and the three `MEOW_JIRA_*` keys, so the agent trusts that environment. If a call fails on a missing key it tells you and does not ask for a token.

## Output and failures

After each operation it returns the issue key, the Atlassian URL, a one-line summary and one suggested next step. Exit codes map to actions:

| Exit | Meaning | Action |
|---|---|---|
| 1 | Validation | Check `--help`, fix the flag, retry |
| 2 | Auth | Escalate; you update `.meowkit/.env` |
| 3 | Permission | Report; you lack the Jira permission |
| 4 | Not found | Confirm the issue or project key |
| 5 | Rate limit | Back off and retry once |
| 6 | Conflict | Refresh and retry |
| 7 | Server | Report the Atlassian status and retry |
