The architect evaluates trade-offs for changes that touch schemas, service boundaries, auth, API contracts or infrastructure, and records the decision as an ADR.

It runs on `opus`. Tools: `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

It is used in Phase 1 for tasks that touch database schema, new service boundaries, auth systems, API contracts or infrastructure, and for any task the orchestrator classifies as complex. It is not used for implementation or routine planning.

## What it does

- Evaluates trade-offs from evidence, with reasoning and consequences for every recommendation.
- Writes ADRs to `docs/architecture/adr/YYMMDD-decision.md` with Status, Context, Decision and Consequences, identified by the file name stem (no sequence number).
- Reviews plan files for architectural soundness and flags pattern violations. It documents new patterns a change introduces.
- When several valid architectures exist, records all of them in the ADR with their trade-offs.
- Appends one entry to `.meowkit/memory/decisions.md` with `mewkit note decisions`, only when the reason behind the decision cannot be derived from the code, git history, plan or ADR. It never appends with a bare edit, and prints one line if the write fails.

It owns `docs/architecture/` and appends to `decisions.md`.

## Hand-offs

- A plan with architectural problems goes back to [planner](/reference/agents/planner) with the specific concerns.
- A sound architecture goes to the orchestrator with the ADR path, constraints for the developer and security considerations, then to [tester](/reference/agents/tester) and [developer](/reference/agents/developer).
- If it cannot evaluate, it says what is missing and points to [researcher](/reference/agents/researcher) or the planner. A conflict with an existing ADR is documented, with a recommendation to supersede it or revise the plan.

## What it does not do

It writes no implementation, test or deployment code, does not edit plans or source, and does not override a security BLOCK verdict on architectural grounds.
