The developer writes the production code the plan describes. It exclusively owns production source under `src/`, `lib/` and `app/`.

It runs on `opus`. Tools: `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

It is used in Phase 3 after the plan is agreed. It is not used for planning or shipping.

## What it does

1. Reads `tasks/plans/YYMMDD-name/plan.md` for the technical approach. In an autobuild run it also reads the sprint contract at `tasks/contracts/{date}-{slug}-sprint-{N}.md` (or runs `/mk:sprint-contract propose <slug>` when none exists). In LEAN density (`MEOWKIT_AUTOBUILD_MODE=LEAN`) the contract step is skipped.
2. Checks TDD mode: the `MEOWKIT_TDD` env var first, then `.meowkit/state/tdd-mode` (written by the `tdd-flag-detector.cjs` hook when the prompt has `--tdd`). Otherwise TDD is off.
   - TDD on: confirms failing tests exist from [tester](/reference/agents/tester) before the first source edit, and routes back to tester if not. No hook checks this order.
   - TDD off (default): implements directly. Tests are recommended, not required.
3. Writes type-safe code that follows the codebase patterns. No `any`, no unsafe casts, no new pattern without an ADR from [architect](/reference/agents/architect).
4. Self-heals on test failures up to 3 times, each with a different approach, then escalates to the orchestrator with the failing output, what was tried and the suspected root cause.

## Sprint builds

In a sprint-driven build it works in four steps: understand, design direction, implement one criterion at a time, then verify. Before handing off it must confirm that the code builds, routes match the contract, the schema is applied, the UI renders without console errors, at least one core criterion was smoke-tested by hand, and git status is clean. It then writes `tasks/handoff/{slug}-sprint-{N}.md` and marks the sprint `ready_for_evaluator` in `progress.md`.

Edits stay inside the contract. A criterion that needs to change goes through `/mk:sprint-contract amend`, and out-of-scope fixes become a follow-up plan.

## Beads

When a plan has beads (atomic work units), it processes them in order, one atomic commit each, and tracks progress in `.meowkit/state/build-progress.json` so an interrupted session resumes at the last incomplete bead. A bead is about 150 lines of implementation; a larger one goes back to the planner.

## Hand-offs

After implementation it recommends [tester](/reference/agents/tester) for green-phase verification, then [reviewer](/reference/agents/reviewer). The hand-off lists files changed, test results and plan deviations.

## What it does not do

It does not write or edit tests, docs, plans or review files, and it does not start a non-trivial task without a plan agreed with you.
