The jira-lifecycle agent is the executor for `mk:jira-lifecycle` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`.

It runs on `sonnet`. Tools: `Bash`, `Read`, `Grep`, `Glob`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it to move an issue through its workflow, assign or resolve it, or manage versions and components.

## Workflow discovery

Status names and transition graphs differ per Jira instance, so the agent reads the discovered cache before it suggests a transition: `tasks/jira-workflows/_schemes/<PROJECT_KEY>.md` (project to workflow) and `tasks/jira-workflows/<workflow-slug>.md` (statuses and transitions). If the cache is missing it runs discovery once. Discovery tries the admin path first and falls back to per-state discovery, writing a `_partial-<PROJECT>.md` marked incomplete when it gets a 403. Before executing it checks the cached transition IDs against Jira and asks you to rerun `fetch-workflow.sh` if they differ.

The files under `.claude/skills/jira-lifecycle/references/patterns/` show common workflow shapes for orientation. They are not your project's workflow. Protocol: `.claude/skills/jira-lifecycle/references/workflow-discovery.md`.

## Resolutions

Many workflows need a `--resolution` for Done or Closed. If you leave it out, the agent asks which one. If `transition` fails on a required field, it names the field and offers options.

It returns the issue key, new status, new assignee or resolution, URL and a suggested next step.
