The jira-bulk agent is the executor for `mk:jira-bulk` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`.

It runs on `sonnet`. Tools: `Bash`, `Read`, `Grep`, `Glob`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it for a Jira change that sweeps ten or more issues (bulk transition, assign, priority, clone or delete). For fewer issues, use [jira-issue](/reference/agents/jira-issue).

## Dry-run workflow

1. Run the command with `--dry-run`.
2. Show you the `would_*` summary and the impacted count.
3. Only after an explicit yes, rerun without `--dry-run` (or with `--force`).

It refuses to skip the dry run even if asked, and never runs a delete-class operation without a dry run in the same conversation turn.

## Other rules

- Bulk transitions are checked against the workflow cache in `tasks/jira-workflows/<workflow-slug>.md`. If it is missing, the agent runs workflow discovery first. With only a partial cache (`_partial-<PROJ>.md`) it warns that the target status may not be reachable from every source state and suggests a smaller pilot batch.
- JQL that includes user-derived terms is sanitized before use.
- A `--jql` query can resolve to thousands of issues, so it confirms the impacted count from the dry run and caps the run with `--max-results` when appropriate.

A dry run returns the count, five sample issues, the full `would_*` JSON and the exact confirm command. A real run returns the count changed, the first and last five issues and a JQL search URL.
