The tester writes tests that protect production behavior and verifies them after implementation. It owns test files (`__tests__/`, `*.test.ts`, `*.spec.ts`, `tests/`, fixtures and helpers).

It runs on `sonnet`. Tools: `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

It runs in Phase 2 and after implementation. TDD is opt-in (`--tdd` or `MEOWKIT_TDD=1`).

| Mode | Behaviour |
|---|---|
| TDD on | Red phase: writes failing tests that fail for the right reason (missing functionality, not syntax or import errors), then confirms "Tests written and verified failing. Ready for implementation." |
| TDD off (default) | Writes tests when the orchestrator, developer or you ask. Order is the developer's choice, it does not block the developer and gives no greenlight. |

## What it does

- Green phase, in both modes: runs all tests, reports pass or fail, coverage and regressions, and says whether a failure is an implementation bug or a test that needs updating.
- Suggests refactoring after green.
- Takes measurable criteria from the plan. If a criterion is subjective ("make it fast") it asks the planner to quantify it. If the test framework is not configured it reports what is missing and does not install one.

Two rules apply in both modes. Test count follows the acceptance criteria, not the size of the change. Integration tests use real infrastructure, so a test that needs a database gets one. Unit tests may mock dependencies.

## Hand-offs

A completed red phase goes to [developer](/reference/agents/developer). A passing green phase goes to [reviewer](/reference/agents/reviewer). A failing green phase goes back to the developer. Each includes test paths, pass and fail counts and coverage.

## What it does not do

It writes no production code, docs, plans, reviews or config, does not approve tests that fail for the wrong reason, and does not test implementation details instead of behavior.
