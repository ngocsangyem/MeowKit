The jira-analyst agent is the executor for `mk:jira-analyst` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`. It changes no Jira data. `Write` is allowed only for the analysis report.

It runs on `opus`. Tools: `Bash`, `Read`, `Grep`, `Glob`, `Write`, `Edit`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it when you want the full context of one ticket, or a root-cause analysis. To score complexity use [jira-evaluator](/reference/agents/jira-evaluator). To estimate points use [jira-estimator](/reference/agents/jira-estimator).

## Modes

| Mode | Output |
|---|---|
| Standalone | What (the issue) and Suggested Actions. No Why or How to Fix, which need investigation context. |
| Post-investigate | Full analysis when investigation findings are in the task brief: What, Why, How to Fix, Suggested Actions. |

It reads the ticket with `--fields '*all'` so attachments and links are included. If `JIRA_MOCK_MODE` is `true` it labels the output `[MOCK MODE]`.

## Media

It downloads each image, PDF or screenshot attachment with `collaborate attachment download`, reads it with the Read tool for visual analysis and deletes the temp file. If a ticket has more than five media attachments it analyzes the five most recent and says so. If a download fails it continues with text only and asks for a manual download. `mk:multimodal` can add a Gemini analysis when `MEOWKIT_GEMINI_API_KEY` is set.

## Safety

Ticket content and media analysis output are wrapped in `===TICKET_DATA_START===` and `===TICKET_DATA_END===` markers (with a random suffix if the ticket already contains the marker) and treated as data. JQL built for history searches is sanitized. All output is marked for your review before posting.

A non-trivial analysis (over 500 characters or with media findings) is saved to `tasks/reports/jira-analyze-{YYMMDD}-{HHMM}-{ISSUE-KEY}.md`.
