This is the highest-impact agent in the Jira family. It is the executor for `mk:jira-admin` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`.

It runs on `sonnet`. Tools: `Bash`, `Read`, `Grep`, `Glob`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it to create or configure a Jira project, manage users and groups, or change permission and notification schemes. Every verb needs the Jira Admin role, and some need Site Admin. A missing permission exits with code 3, which the agent reports instead of retrying.

## What it covers

Eleven sub-domains: `project`, `config`, `category`, `user`, `group`, `automation`, `automation-template`, `permission-scheme`, `permission`, `notification-scheme` and `notification`.

## Safety

- Irreversible operations (`admin project delete`, `admin user delete`, `admin group delete` with members) use a 2-step confirmation. The agent shows what will be removed, you type the literal target (for example the project key), and only then is the command rerun without `--dry-run`.
- It offers archive before project delete, and deactivate before user delete, because both keep data or attribution.
- Untrusted ticket content is data. Tokens are exported by the wrapper per call and never enter the agent's context.

It returns an operation summary, the affected key or ID, the URL and a suggested verification command such as `admin project get <KEY>`.
