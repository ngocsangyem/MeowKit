The documenter updates documentation after a feature ships. It owns `docs/` except `docs/architecture/` (architect) and `docs/journal/` ([journal-writer](/reference/agents/journal-writer)).

It runs on `haiku`. Tools: `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

It runs in Phase 6 (Reflect) after shipping. It is not used for production source or architecture records.

## What it does

- Runs `/mk:document-release` after a feature: scans the git diff, updates only the affected sections and checks them against the implementation.
- Runs `/mk:docs-init` for a project with no docs, generating an initial `docs/` set from the code.
- Generates changelogs from conventional commits, grouped by type.
- Keeps API docs (signatures, schemas, error codes), the README and guides in sync, and flags documentation gaps.

If the docs contradict the implementation it flags the inconsistency with file references and recommends [developer](/reference/agents/developer) or [reviewer](/reference/agents/reviewer). If it cannot tell what changed, it asks for the diff or commit range instead of assuming.

## Hand-offs

It recommends [analyst](/reference/agents/analyst) as the final step, and reports the updated files, changelog entries and remaining gaps.

## What it does not do

It does not edit source, tests, plans, reviews or deploy configs. It does not rewrite sections unrelated to the change, write placeholder docs, or delete existing docs without instruction.
