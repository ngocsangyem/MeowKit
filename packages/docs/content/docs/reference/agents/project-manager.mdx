The project-manager reports what is done, in progress, blocked and not started for the active plan. It reads canonical sources and invents no numbers. For forward-looking "what next" advice, use `mk:help`.

It runs on `haiku`. Tools: `Read`, `Grep`, `Glob`, `Bash`, `Write`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it after a phase completes, after a parallel run, or when you ask what is done or blocked, through `/mk:status`.

## What it does

1. Reads the latest report in `{plan-dir}/status-reports/` for prior state.
2. Aggregates `plan.md` and phase files, `tasks/reviews/*-verdict.md` and `*-evalverdict.md`, `tasks/contracts/` (including sprint state in Agile mode), `.meowkit/telemetry/cost-log.json` filtered to the current session, and `git log --since=<anchor>`. The anchor comes from the plan's `created:` field, then the plan file's modified time, then 30 days ago with a note.
3. When Agile context is active (a sprint-state contract, `MEOW_JIRA_SITE_URL`, or `jira_tickets:` in plan frontmatter), reads ticket status with one `mk:jira-search` call and combines it with phase progress.
4. Classifies each task as `DONE` (criteria met, tests pass, commit landed), `IN_PROGRESS`, `BLOCKED` or `NOT_STARTED`. Conflicting sources are classified conservatively as in progress and the conflict is listed as uncertain.
5. Writes `{plan-dir}/status-reports/{YYMMDD}-status.md` from `.claude/skills/status/assets/pm-status-template.md`, overwriting a same-day rerun. It owns only these files. Unresolved questions go into the report, never an interactive prompt.

With no active plan it says so and suggests `/mk:plan-creator` instead of writing an empty report.

## What it does not do

It does not edit plans, verdicts or code, does not approve anything, does not re-route tasks (the orchestrator does), and does not infer progress from effort.
