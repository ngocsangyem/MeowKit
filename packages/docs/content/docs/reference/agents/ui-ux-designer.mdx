The ui-ux-designer creates implementation-ready UI specifications. The developer writes the production source.

It runs on `opus`. Tools: `Read`, `Grep`, `Glob`, `Edit`, `Write`, `AskUserQuestion`, `WebSearch`, `Task`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

It works in Phase 3 beside the developer when `mk:cook` finds frontend work in the plan, when `mk:bootstrap` runs its design phase (all modes except `--fast`), or when you ask for design work. It is not used for implementing production source.

## What it does

1. Reads the plan for design requirements.
2. Loads `mk:ui-design-system`, `mk:frontend-design`, the framework skill that matches the stack (`mk:react-patterns`, `mk:vue` or `mk:angular`), `mk:multimodal` for images and `mk:agent-browser` for screenshots.
3. Creates or updates `docs/design-guidelines.md` and writes component specs to `docs/ui-specs/` and wireframes to `docs/wireframe/`. It owns these three paths.
4. Validates against `mk:ui-design-system/references/quality-checklist.md`.

## Quality standards

- Contrast: WCAG 2.1 AA, 4.5:1 for normal text and 3:1 for large text.
- Touch targets: at least 44 by 44 px with 8 px spacing.
- Responsive: mobile-first from 320 px, tested at 768 px and 1024 px.
- Keyboard: every interactive element reachable by Tab with a visible focus indicator, and hover, active, focus and disabled states.
- Motion: respects `prefers-reduced-motion`, animations 150 to 300 ms.
- Icons are SVG or an icon library, not emoji.

If there are no design guidelines it asks whether to create a baseline. If requirements are unclear it asks one question at a time (audience, style direction, brand colors, reference sites). Without `mk:multimodal` it uses placeholder images and notes that assets need manual creation.

## Hand-offs

It passes the guidelines path, spec list and screenshot evidence to [developer](/reference/agents/developer), or to [reviewer](/reference/agents/reviewer) when no source work remains.

## What it does not do

It does not write tests, edit plans or implement backend logic.
