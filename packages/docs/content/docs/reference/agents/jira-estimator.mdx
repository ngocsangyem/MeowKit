The jira-estimator agent is the executor for `mk:jira-estimator` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`. It changes no Jira data.

It runs on `opus`. Tools: `Bash`, `Read`, `Grep`, `Glob`, `Write`, `Edit`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it to get story points for one existing ticket. For pasted stories that are not yet tickets, use [story-sizer](/reference/agents/story-sizer). Running [jira-evaluator](/reference/agents/jira-evaluator) first gives it complexity signals to build on.

## How it works

1. Reads the ticket. It discovers the story-points field ID for the instance first (`customfield_10016` is the documented default) and uses the discovered ID.
2. Stops with "Ticket has no text description, cannot estimate" if the description is empty.
3. Acknowledges any existing estimate and says whether it agrees.
4. Weighs how many areas the ticket touches, integration complexity, requirement clarity and similar closed tickets (sanitized JQL). A failed search is reported as "historical comparison unavailable", not as zero results.
5. Suggests a Fibonacci range with a confidence level.

It escalates to human estimation when the range spans more than one Fibonacci step, when there is no historical precedent, when the ticket names technology not in the codebase, or when the description is too vague (under 30 words and no acceptance criteria). The output states that the estimate is an LLM assessment and should be verified before it is applied.

Ticket content is wrapped in data markers. The estimate is saved to `tasks/reports/jira-estimate-{YYMMDD}-{HHMM}-{ISSUE-KEY}.md`.
