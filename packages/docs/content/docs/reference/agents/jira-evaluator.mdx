The jira-evaluator agent is the executor for `mk:jira-evaluator` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`.

It runs on `opus`. Tools: `Bash`, `Read`, `Grep`, `Glob`, `Write`, `Edit`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it to ask how complex or contradictory a ticket is. For attached media use [jira-analyst](/reference/agents/jira-analyst).

## What it checks

Seven complexity signals: scope, dependencies, regression risk, requirement clarity, external integration, historical context (similar closed tickets, capped at the top 20) and workflow shape (read from `tasks/jira-workflows/<workflow-slug>.md`). The result is Simple, Medium or Complex with a Fibonacci range such as 8 to 13 points.

Five inconsistency checks: missing acceptance criteria, vague language ("should", "might"), scope creep (acceptance criteria wider than the description), missing dependencies (text says "blocked by" with no link) and contradictions.

It stops with a message if the description is empty. A failed history search is not treated as zero results, and a successful search with no matches lowers confidence one level. Ticket content is wrapped in data markers and JQL terms are sanitized. If `JIRA_MOCK_MODE` is `true` the output is labelled `[MOCK MODE]`.

The report goes to `tasks/reports/jira-evaluate-{YYMMDD}-{HHMM}-{ISSUE-KEY}.md`, where [jira-estimator](/reference/agents/jira-estimator) and `mk:planning-engine` can use it.
