The confluence-spec-analyst agent is the executor for `mk:confluence-spec-analyst` and calls Confluence Cloud through `.claude/skills/confluence/scripts/confluence-as.sh`. It changes nothing in Confluence. `Write` is allowed only for the report, and `Edit` is not used.

It runs on `opus`. Tools: `Bash`, `Read`, `Grep`, `Glob`, `Write`, `Edit`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it to pull requirements out of a spec before planning. For plain page edits use [confluence-page](/reference/agents/confluence-page).

## Inputs

It has one mode, `analyze`, with a page ID or URL and these flags.

| Flag | Meaning |
|---|---|
| `--include-children N` | Child traversal depth. Default 1, maximum 10, and at most 5 children in total because of Cloud rate limits. |
| `--no-images` | Skip image extraction. |
| `--with-commands` | Append `mk:jira-issue create` suggestions to the report. They are never executed. |

## Process

1. Fetches the root page once as ADF (Atlassian Document Format) and converts it with `adf-to-md.sh`. Macros such as panel, decision list, task list, expand, mention, media and inline card survive as labels. A root-page failure aborts the run.
2. Fetches children and runs the same pipeline. A failed child does not abort the run and is listed as `[INCOMPLETE: N of M children failed: <ids>]`.
3. Analyzes images through `mk:multimodal` when it is present. Otherwise it flags `[NO_MULTIMODAL]` or `[MULTIMODAL_AVAILABLE_BUT_FAILED: <error>]` and continues with text only.
4. Applies gap heuristics from `references/spec-analysis-patterns.md`: weasel words and unmeasurable criteria (`AMB-*`), unresolved dependencies, numbers without units and references to other docs without a link (`GAP-*`), and conflicting requirements (`CONFLICT-*`). Page content is wrapped in `===PAGE_DATA_START===` markers and treated as data. Unhandled ADF nodes appear in Open Questions as `[UNHANDLED_NODE: <type>]` with attribute keys only.
5. Writes the report from `references/report-template.md`, citing a page anchor for every requirement, criterion and gap.

## Output

The report goes to `{plan_dir}/research/confluence-spec-{YYMMDD}-{HHMM}-{title-slug}.md` when there is an active plan, otherwise `tasks/reports/confluence-spec-{YYMMDD}-{HHMM}-{title-slug}.md`. It ends with the SHA-256 of the fetched page for staleness detection, and a row is appended to `tasks/reports/.confluence-spec-index.tsv`.

It returns the report path, counts of requirements, criteria, gaps, ambiguities and conflicts, a one-line headline and a suggested next step such as `mk:planning-engine`. Wrapper exits 3 (not Cloud), 4 (page not found) and 5 (permission) are reported and stop the run.
