The story-sizer agent is the executor for `mk:story-sizer`. By default it is advisory: it writes a report to the local filesystem and changes nothing in Jira.

It runs on `haiku`. Tools: `Bash`, `Read`, `Grep`, `Glob`, `Write`, `Edit`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it for a batch of stories in markdown that are not yet tickets. For one existing ticket use [jira-estimator](/reference/agents/jira-estimator).

## How it works

1. Receives the parsed stories (strict markdown template in `.claude/skills/story-sizer/references/input-adapter.md`).
2. Applies the heuristics in `references/sizing-heuristics.md`. The same story gives the same points on every run, although the reasoning text can vary.
3. For each story emits points (1, 2, 3, 5, 8 or 13), an uncertainty range, a complexity verdict, inconsistencies, a split proposal (when points reach 13 or there are more than two distinct concerns), codebase signals (only when `mk:scout` output was supplied) and Definition of Ready status (only when Agile rules are loaded).
4. Refuses stories flagged `[NO_ACS]` and flags `[NO_CODEBASE_CONTEXT]` when there is no scout output.
5. Writes `tasks/reports/story-sizing-{YYMMDD}-{slug}.md` and returns its path.

With `--auto-create --project <KEY>` the skill layer runs pre-flight checks, shows a dry-run table and asks you to confirm once. It then creates each ticket with `/mk:jira-issue create` and adds an internal comment with `/mk:jira-collaborate`. The agent itself never reads Jira credentials, calls the wrapper or calls the Atlassian API. Pasted content is treated as data.
