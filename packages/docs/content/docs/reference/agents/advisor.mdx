The advisor is the executor behind `mk:advise`. It owns no workflow phase and nothing else routes to it. It asks one question per turn, presents a reframed problem for you to confirm, and only then gives a single verdict.

It runs on `fable`. Tools: `Glob`, `Grep`, `Read`, `Write`, `Edit`, `Bash`, `WebFetch`, `WebSearch`, `TaskCreate`, `TaskGet`, `TaskUpdate`, `TaskList`, `SendMessage`, `Task(Explore)`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it through `/mk:advise` when you want a recommendation on a decision, such as "what should I do about our slow build?". If the framing is already settled and only the options are open, use [brainstormer](/reference/agents/brainstormer).

## How it works

1. **Interview.** One question per turn, usually 2 to 6 in a run, each able to change the answer. The agent is respawned every turn and reads `.meowkit/state/<advise-run>/transcript.json` for memory, then writes the checkpoint back before it ends the turn. A run is budgeted at about 6 spawns.
2. **Reframe.** It presents the problem, requirements, goals, non-goals and constraints and returns `NEEDS_CONTEXT`. It gives no verdict until you confirm.
3. **Packet.** After confirmation it returns verified context, the confirmed reframing, the verdict, do and don't lists, cheaper alternatives, benefits, trade-offs, an ordered checklist, success metrics and unresolved questions. "Do nothing" is a valid verdict.

## What it writes

Only the transcript checkpoint under `.meowkit/state/<advise-run>/`, and `tasks/reports/advise-<YYMMDD-HHMM>-<slug>.md` when you asked for the advice to be saved. It refuses to write plans, ADRs, knowledge docs, source or tests, review verdicts or `.meowkit/memory/`, and returns `BLOCKED` naming the owner instead. It never invokes `mk:plan-creator` or `mk:cook`. The tool list is not path-scoped, so this boundary is a convention.

It reads no sensitive data (no `.env`, credentials or keys).
