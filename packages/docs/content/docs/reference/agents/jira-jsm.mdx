The jira-jsm agent is the executor for `mk:jira-jsm` and calls Jira through `.claude/skills/jira/scripts/jira-as.sh`.

It runs on `sonnet`. Tools: `Bash`, `Read`, `Grep`, `Glob`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it for a JSM request, queue or SLA. For project and user administration use [jira-admin](/reference/agents/jira-admin).

## Permissions

It needs a JSM-licensed tenant and at least the Agent role on the service desk, often Admin for queue and SLA changes. Without them every verb exits with code 3, and the agent reports it instead of retrying.

## What it covers

Eight sub-domains: `service-desk`, `request-type`, `request`, `customer`, `organization`, `queue`, `sla` and `approval`.

Before posting a comment on a JSM ticket it asks whether it is `internal` (team only) or `public` (visible to the customer), and defaults to `internal`.

It returns the request key, status, queue, next SLA breach time and URL.
