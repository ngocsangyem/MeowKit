The evaluator runs the built artifact and grades it. It complements [reviewer](/reference/agents/reviewer), which audits code structure. Its default stance is skeptical: it assumes bugs exist and issues no PASS without runtime evidence.

It runs on `opus`. Tools: `Read`, `Grep`, `Glob`, `Bash`, `Write`, `Edit`, `AskUserQuestion`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

It runs in autobuild and harness pipelines and through `/mk:evaluate`. It has two roles.

| Role | When | Job |
|---|---|---|
| Active verifier | After a build | Drive the running build against the rubric criteria and write a graded verdict. |
| Contract reviewer | Before a sprint's code | Check each acceptance criterion in a proposed sprint contract for testability, rubric fit, clear scope and valid form. |

## Active verifier

1. Loads the rubric preset through `mk:rubric`. Frontend builds default to `frontend-app` (product-depth, functionality, design-quality, originality).
2. Drives the build: `mk:agent-browser` or `mk:playwright-cli` for frontends, `curl` or similar for APIs, the binary with real arguments for CLIs.
3. Probes each criterion (at most 15 per session) and records evidence for every finding: an artifact path, log snippet or command output. Narrative-only findings fail `validate-verdict.sh`, and a PASS needs a non-empty `evidence/` directory.
4. Grades against the rubric's PASS and FAIL anchors. When unsure it records WARN, not PASS.
5. Writes `tasks/reviews/YYMMDD-{slug}-evalverdict.md` plus an `*-evalverdict-evidence/` directory, and a one-line fix guidance for each FAIL or WARN.

It hunts stub features, silent feature substitution, verification against mocks, AI-slop design, missing wiring, missing empty, loading and error states, and onboarding walls.

| Verdict | Route |
|---|---|
| PASS | [shipper](/reference/agents/shipper) |
| WARN | Back to the generator with the WARN list, for one more iteration (the harness caps iterations) |
| FAIL | Back to the generator with fix guidance. After 3 iterations it escalates to you. |

If the target is not running or the rubric library is missing it reports `BLOCKED` and invents no verdict. Criteria it could not probe are WARN or FAIL, never skipped.

## Contract reviewer

Invoked by `/mk:sprint-contract review`. It appends specific clarification requests to the contract's Negotiation Log (for example, which mouse buttons and modifier keys an "AC-04 user can drag clips" criterion means). After 2 rounds without agreement it asks you. When the contract is acceptable it runs the `sign` action.

## What it does not do

It does not edit source, tests or plans, does not review code structure, and does not load rubrics outside the active preset unless told. It owns only `*-evalverdict.md` and the evidence directories; `*-verdict.md` belongs to reviewer and `*-security-verdict.md` to [security](/reference/agents/security).
