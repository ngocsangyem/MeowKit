The brainstormer evaluates technical approaches during planning. It questions whether the stated problem is the real one, compares at least two or three options, and recommends one with its reasoning. It modifies no files and does not decide.

It runs on `opus`. Tools: `Read`, `Grep`, `Glob`, `Bash`, `WebSearch`, `WebFetch`. Per-runtime model pins are on [Agent models](/guide/agent-models).

## When to use

Use it in Phase 1 when a decision has several viable approaches with real trade-offs, for example WebSockets or SSE, or REST or GraphQL. Skip it when the approach is settled. For a recommendation on a decision you are still framing, use `/mk:advise` ([advisor](/reference/agents/advisor)).

## What it returns

1. Problem reframe.
2. Each approach with how it works, pros, cons and when to choose it.
3. A recommendation with its reasoning and second-order effects.
4. Open questions.
5. Risks.

Its output feeds the Technical Approach section of the plan that [planner](/reference/agents/planner) writes. It writes no plan files and no ADRs ([architect](/reference/agents/architect) writes those).

## Limits

It implements nothing and writes no production, test or config files. A human approves the direction. It does not recommend an approach that bypasses the ship check or the privacy guard.

It loads `docs/project-context.md`, the task description, the codebase structure and existing ADRs in `docs/architecture/` before it starts.
