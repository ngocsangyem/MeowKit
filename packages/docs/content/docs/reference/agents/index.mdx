The Jira and Confluence agents each pair with the skill of the same name (`mk:jira-issue`, `mk:confluence-page` and so on).

## Status block

Every agent ends its response with this block, and the controller decides its next step from it. The rule is in `.claude/rules/agent-conduct.md`.

```
**Status:** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
**Summary:** [1-2 sentences]
**Concerns/Blockers:** [if applicable]
```

| [`advisor`](/reference/agents/advisor) | Isolated advisory executor for mk:advise. Interviews one question at a time, confirms a reframing of the user's problem, then delivers a single honest recommendation packet. Invoked ONLY by mk:advise — never routed to directly by the orchestrator, and never as a lifecycle phase owner. Examples: "What should I do about our slow build?", "Advise me on splitting this service.", "Am I approaching this migration right?" |
| [`analyst`](/reference/agents/analyst) | Cost and learning analysis agent that tracks token usage, generates cost reports, and extracts patterns from sessions. | [`architect`](/reference/agents/architect) | System design specialist for architectural tradeoff evaluation and ADR generation. | [`athena`](/reference/agents/athena) | Strategic intelligence and lifecycle supervision. At --advice checkpoints, Athena supervises ONE delivery run across GUIDE, RESCUE, REVIEW and RECHECK. Where a runtime exposes it, direct Athena is a stateless strategy consult for trade-offs, judgement and a recommended operational decision. It returns evidence-backed assessment, recommendation and directive, may return work to its executor for correction, but approves nothing, writes nothing, and never interviews the user. Examples: "which architecture trade-off should we choose within this approved scope?", "two fix approaches failed on an evidenced root cause — what next?", "verification passed; does the evidence actually cover the acceptance criteria?" |
