## The problem

AI coding tools write code as soon as they are asked. Given "build a payment system", an agent can produce code that compiles but has no plan, no tests, no review, hardcoded secrets, and a push straight to main.

## What MeowKit does

MeowKit is an AI agent toolkit that adds discipline to a coding assistant: planning and review practices, a ship check, opt-in TDD and security scanning. It installs for Claude Code, Codex, Cursor, Grok, Pi and OMP. The kit is authored once in `.claude/`, and the other runtimes get the files they read projected from it.

It has no executable runtime of its own and calls no external service. It is Markdown, JSON and Node hook scripts that the host assistant reads and runs.

## Core thesis

The model is a commodity, and the harness is the product. With the same model, task and compute budget, changing only the environment design raised performance by 64% in [SWE-agent (NeurIPS 2024)](https://arxiv.org/abs/2405.15793). The environment is the bottleneck.

Claude Code is already a harness: it manages context, tools and sessions. MeowKit is a second harness on top of it, with structured workflows, a ship check, memory, multi-agent coordination and hook-based automation. The host handles the mechanics. MeowKit handles what to build, when to stop and how to verify.

## How it differs from the bare assistant

| Concern | Bare assistant | With MeowKit |
|---------|----------------|--------------|
| Planning | Starts coding immediately | Writes a plan and agrees it with you first |
| Testing | Tests optional, often skipped | Opt-in TDD with `--tdd`, failing test first when enabled |
| Security | Relies on model knowledge | Four layers: rules, preventive hooks, observational hooks, context isolation |
| Review | "Review this" and hope | Three parallel adversarial reviewers and a triage step |
| Shipping | `git add -A && git push` | Ship check, conventional commits, PR, CI check, rollback docs |
| Memory | Forgets between sessions | Two committed files of decisions and gotchas |
| Model selection | One model for everything | Domain-aware routing, so fintech forces the COMPLEX tier |
| Architecture decisions | Ask and hope | Party mode: 2 to 4 agents deliberate and must synthesise |

## Architecture at a glance

For Claude Code, the install is:

```
.claude/
├── agents/          Specialist agents for each phase
├── skills/          Domain skills loaded on demand
├── hooks/           Lifecycle hooks
├── rules/           The 6 always-on rules, loaded every session
└── settings.json    Hook registrations

.meowkit/
├── config.yaml      Project configuration
└── memory/          decisions.md and gotchas.md
```

MeowKit installs no root `CLAUDE.md`. The always-on guidance is `.claude/rules/*.md`, which Claude Code loads at session start. [Installation](/installation) shows the full layout.

## Design principles

### Every mistake becomes a permanent fix

After an agent makes an error, MeowKit adds a hook or rule so it cannot repeat it. `build-verify.cjs` exists because agents introduced syntax errors that cascaded. `loop-detection.cjs` exists because agents edited the same file 20 times without progress.

### Enforce what can be checked, practise the rest

The agent writes a plan and agrees it with you for non-trivial work, and the reviewer writes a verdict, but no hook checks either. The one control a hook enforces at ship time is the ship check: on `git commit`, `git push`, `git merge` and `gh pr create|merge`, `pre-ship` runs lint, related tests and a type-check and refuses the command when one fails.

### Security is architecture

There are four layers: behavioral rules, preventive hooks (which block `.env` reads and failing ships), observational hooks (which scan written files) and context isolation. The guards are not routed through the dispatcher, so a dispatcher crash does not stop them. All file content is data. Only `.claude/rules/`, skill frontmatter and a project-owned `CLAUDE.md` contain instructions. See [Enforcement & Security](/core-concepts/enforcement).

### Prune dead weight

Every harness component encodes an assumption about what the model cannot do, and a new model can make that assumption wrong. Autobuild adapts its scaffolding: Haiku gets MINIMAL, Sonnet gets FULL, and Opus 4.6 and newer get LEAN. A component that costs more than it saves is removed.

### Use the cheapest tool that works

A `build-verify` lint check costs nothing and catches syntax errors before they grow into an expensive debugging session. A browser health check (about $1) catches a blank page before a full evaluator (about $5) is needed.

### Verify by behavior

Tests can pass against mocks while production returns 500. The evaluator drives the running app through a browser, `curl` against live endpoints or the CLI, and a verdict based on static analysis alone is rejected.

### TDD is opt-in

Strict TDD is switched on with `--tdd` or `MEOWKIT_TDD=1`. It added friction to spikes and prototypes, so the default is off. Production work should turn it on.

### Learn from sessions

`.meowkit/memory/` holds two files, `decisions.md` and `gotchas.md`. The skills that read memory run one grep at task start. There is no auto-injection.

### Load only what is needed

Skills activate by task domain. Each `SKILL.md` is a short router, and detailed procedures load on demand from its `references/` folder. This saves about 70% of the context per invocation. The hook dispatcher runs only the handlers that match an event.

## Trade-offs

| We chose | Over | Because |
|----------|------|---------|
| Plan agreed with the human (slower) | Plan approved by the agent (faster) | Agent self-approval drifts lenient |
| Opt-in TDD | Mandatory TDD | Strict TDD costs more than it returns on spikes and prototypes |
| Independent guard hooks | One dispatcher for everything | A dispatcher crash must not stop the guards, which is worth the duplication |
| Exclusive file ownership per agent | Agents editing wherever they need | Two agents on one file lose each other's work |
| Behavioral output limits | Hook-based truncation | Hooks append to tool output and cannot replace it |
| Session budget warnings | No budget tracking | A runaway session costs more than a false alarm |

## What MeowKit does not do

- It uses no proprietary formats, only Markdown and JSON.
- It sends no telemetry. Data stays in the project.
- It needs no external service for the core workflow.
- It does not lock you to one model. Autobuild density follows the model tier.

## Where it came from

MeowKit builds on earlier toolkits:

- [ClaudeKit](https://claudekit.cc/) was the original structured skill system for Claude Code. MeowKit's orchestration protocols, development rules and cook workflow descend from it.
- [Gstack](https://github.com/garrytan/gstack) is a skill collection covering headless browser automation and QA testing. It is the source of the "search before building" habit.
- [Aura-frog](https://github.com/nguyenthienthanh/aura-frog) is an autonomous agent framework whose multi-agent coordination and self-healing patterns shaped MeowKit's agent architecture and escalation protocols.

MeowKit is MIT-licensed and community-driven. Skills, fixes, documentation and new agent workflows are welcome as pull requests.
