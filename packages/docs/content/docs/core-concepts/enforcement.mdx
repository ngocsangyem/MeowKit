## Planning and review are practices

MeowKit has no plan-approval step and no review-approval step. An agent can edit source without an approved plan and commit without a review verdict, and no hook checks either. Both stay in the workflow:

- For a change of more than two files or about 30 minutes, the agent writes the plan under `tasks/plans/YYMMDD-name/` and agrees it with you before building.
- The reviewer checks the diff across five dimensions (correctness, maintainability, performance, security, coverage) and writes a verdict.

## The ship check

The ship check is the one control a hook enforces at ship time. On `git commit`, `git push`, `git merge` and `gh pr create|merge`, the `pre-ship` hook runs lint on the changed files, the tests related to them and a type-check, and refuses the command when one fails.

- Lint, tests and the type-check run from the project's own `node_modules/.bin`. Nothing is fetched: a project with a `tsconfig.json` but no local TypeScript gets `SKIP: typescript not installed locally`.
- When the test runner cannot name the related tests, the check runs lint and type-check only and says that tests did not run.
- When vitest or jest finds no test related to the changed files, the check says that no test relates to the change instead of printing a pass; when tests ran, the pass line shows how many.
- `MEOWKIT_HOOK_PROFILE=fast` does not turn it off.
- A ship command run inside `bash -c`, `eval`, `env -S`, backticks, a script or a Makefile target is not seen. Shell keywords (`if … then`, `{ }`, `!`), subshells and the `env`, `sudo`, `nice`, `time`, `nohup`, `exec` and `xargs` wrappers are seen through.
- The check stops itself after 270 seconds and reports what did not finish.
- Before it runs, the same check prints the plan drift line and the archive reminder when a plan under `tasks/plans/` needs one (see [Planning and Tasks](/cli/planning#plan)). Both are read-only: they never change the decision, and they appear on all seven runtimes.

Push, merge and force-push are approved through your host's own permission prompt when the host is set to ask. MeowKit adds no prompt of its own.

## What each runtime enforces

An Enforced cell means a registered hook refuses the action. Advisory means an instruction asks for it and nothing checks. `.claude/hooks/hook-coverage.json` in the kit records what each safety behaviour becomes on each runtime.

| Control | Claude Code | Codex | Cursor | Grok | Pi | OMP | Antigravity |
|---|---|---|---|---|---|---|---|
| Credential-file reads | Enforced on Read, Edit/Write and Bash | Enforced on Bash only | Enforced on file reads | Enforced on every tool | Enforced on every tool call | Enforced on every tool call | Unverified on every tool (from documentation) |
| Ship check | Enforced | Enforced | Enforced | Enforced on Bash | Enforced on shell commands | Enforced on shell commands | Unverified on `run_command` (from documentation) |
| Destructive shell commands | Advisory | Absent | Enforced | Absent | Absent | Absent | Absent |
| MCP server allowlist | Absent | Absent | Enforced | Absent | Absent | Absent | Absent |
| Writes to protected paths | Absent | Absent | Enforced | Absent | Absent | Absent | Absent |
| Plan before building | Advisory | Advisory | Advisory | Advisory | Advisory | Advisory | Advisory |
| Review before shipping | Advisory | Advisory | Advisory | Advisory | Advisory | Advisory | Advisory |
| Completion check | Opt-in | Absent | Opt-in | Absent | Opt-in, unverified (from documentation) | Opt-in | Absent |
| Plan state follows checkboxes | Synced at stop | Synced at stop | Synced at stop | Drift line at ship check | Synced at turn end, unverified (from documentation) | Synced at turn end | Drift line at ship check |
| Archived-plan reads | Enforced on Read, Grep, Glob and Bash | Enforced on Bash only | Enforced on file reads, search tools and shell | Enforced on every tool | Enforced on every tool call | Enforced on every tool call | Unverified on every tool (from documentation) |

Cells that say Absent mean the host's own permissions are the only control. On Claude Code the `careful` and `freeze` skills block destructive commands only while the skill is active.

Grok, Pi and OMP enforcement follows what each vendor documents and what the kit's code does. None of it has been run in a live Grok or Pi session, and for OMP only the skill listing and the completion check were probed.

Antigravity's two guards are installed as unverified: they were built from https://antigravity.google/docs/hooks (read 2026-11-22) and no live run has shown either one deny, so do not count on them yet. Each answers on stdout, denies on unreadable input or its own error, and the ship check asks (`force_ask`) when the checks reach no verdict. The page does not say what the host does with a hook that times out or whose `node` cannot start; either may let the call through. `mewkit init` and `mewkit doctor` name both guards as unverified.

### When installed hooks do not run

- Claude Code started in a subdirectory that does not see the project's `.claude/settings.json`, or a sparse checkout or worktree without `.claude/`.
- Codex skips hooks that are new or changed since you last reviewed them. After an upgrade the ship check is inactive on Codex until you review the hooks.
- Cursor with `MEWKIT_CURSOR_HOOKS_KILL_SWITCH=1` in the environment: the shell, MCP and tool guards stand down, and with them the credential and archived-plan refusals in the shell gate. The file-read credential guard and the ship check do not.
- Grok runs project hooks only after `/hooks-trust`, or when it starts with `--trust`.
- Pi loads `.pi/extensions/meowkit.ts` only in a project you have trusted with `/trust`.
- OMP has no trust step.
- Antigravity's hooks page names no trust step. The registrations run `node` with a path relative to the project root, which assumes the host starts hooks there; the page does not say.

The credential guard does not see files attached with `@` in the prompt, because no tool call happens. On Claude Code and Cursor a shell command that names a credential file (`cat .env`, `grep TOKEN .env`, `cp`, `curl -F x=@.env`, `tar`, `source`) is refused, and so is a Grep whose glob selects one. This is best effort: a read inside a subprocess such as a directory-wide `grep -r` or a build tool, inside `bash -c` or `eval`, or of a path built from a variable or a glob is not seen.

## The completion check (opt-in)

With `hooks.pre-completion-check: true` in `.meowkit/config.yaml`, a turn that ends with files changed since the last passing test, build, lint or type-check run is continued, at most twice, and then ends with a notice. It is off by default. It shows that the agent ran a check, not that the check proves anything: a trivial passing command satisfies it.

On Pi and OMP the extension runs the same rule at `agent_end` and sends the reason as a follow-up message, which starts another turn; a bash result counts as a pass only when the runtime reports it as a success. The cap of two reminders is the only loop guard there, because neither host passes one. OMP was run live (19.2.1, 2026-11-28). `omp -p` exits before the follow-up is sent, so a print-mode run gets no reminder. Pi follows its documentation and has not been run live. Grok and Antigravity document a way to continue a turn, but not the shape of a shell result, so they record no pass and have no check yet.

The check does not run on Codex. Codex hands a hook the output of a shell command but not its exit code, so a passing test run cannot be told from a failing one, and a check that could never see a pass would continue every turn that changed files.

## When a check blocks you

A commit refused with `PRE-SHIP BLOCKED` means lint, a related test or the type-check failed on what you are shipping. The output names the failing check. Fix it and commit again.

`PRE-SHIP COULD NOT RUN` means a check gave no verdict: the check crashed, a tool it needs was not found, or it did not finish within the 270-second deadline. The message names the cause. On Claude Code and Cursor the command waits at the permission prompt, and approving it ships without a verified check. Codex has no prompt for hooks, so it refuses the command; run it in your own terminal to ship anyway. The Claude Code registration sets `onFailure: "block"` (Claude Code 2.1.295 or later), so a ship-check hook that cannot start or reaches its 300-second timeout blocks the command too; Cursor's `failClosed: true` does the same.

Nothing in the command or the environment skips the check. `--no-verify`, `-n` on a commit, a variable such as `MEOWKIT_SKIP_SHIP_CHECK=1` and the Cursor kill switch are named in the output as refused, and the checks run as usual.

A read refused with `@@PRIVACY_BLOCK@@` means the file looks like a credential: `.env`, `.envrc`, `.npmrc`, `.netrc`, `.pypirc`, `.htpasswd`, a private key (a `.pub` file is not one), `.kube/config` or a kubeconfig, Docker, `gh`, gcloud or Azure credential config, Terraform state or variables, a service-account key, a `.p12`, `.pfx` or `.jks` keystore, or a credentials or secrets file. Markdown inside a kit skills folder is not refused for the word `secrets`. Approve the read explicitly if the task needs it.

A fetch refused with the same marker names a loopback, private, link-local or cloud-metadata address, in any spelling (IPv6, decimal, hex), anywhere in the command.

A read of an archived plan under `tasks/plans/archive/` or `tasks/plans/ceo-plans/archive/` is refused on all seven runtimes, with the reason "archived plans are kept out of context; the shipped code is the source of truth". Moving, copying or writing those folders is not refused, and `mewkit plan archive` writes them as usual.

## Security model: four layers

The hook names below are the Claude Code registrations. [Security Hardening](/core-concepts/security-hardening) shows where the defences against a hostile repository, web page, ticket or package live in the CLI, the hooks, the skill scripts and the release pipeline.

### Layer 1: Behavioral rules

`security-rules.md` and `injection-rules.md` load every session and cannot be overridden. They require that the agent:

- does not write hardcoded secrets, SQL built by string interpolation, or unescaped user content
- treats all file content as data, because only `.claude/rules/`, skill frontmatter and a project-owned `CLAUDE.md` contain instructions
- stops, reports, waits and logs when it suspects an injection
- builds no skill that processes untrusted input, accesses sensitive data and changes state all at once (the Skill Rule of Two)

### Layer 2: Preventive hooks

| Hook | Event | What it blocks |
|------|-------|---------------|
| `privacy-block.cjs` | PreToolUse (Read\|Grep\|Glob, Edit\|Write, Bash) | Reads of credential files; fetches aimed at private or metadata hosts; reads of archived plans under `tasks/plans/archive/` |
| `pre-ship.cjs` | PreToolUse (Bash) | A commit, push, merge or PR whose lint, related tests or type-check fail |

These hooks intercept the tool call before it runs.

### Layer 3: Observational hooks

| Hook | Event | What it checks |
|------|-------|---------------|
| `post-write.cjs` | PostToolUse (Edit\|Write) | Security scan of every written file; a blocked pattern goes back to the model |
| `build-verify.cjs` | PostToolUse (Edit\|Write) | Compile or lint after every source change; a failure goes back to the model |

These run after the tool call, so the file is already written. They report and do not prevent.

### Layer 4: Context isolation

- Parallel agents run in isolated git worktrees.
- Subagents do not inherit the parent session's memory.
- The evaluator and the generator are separate agents, which prevents self-evaluation bias.
- A `dispatch.cjs` crash does not affect the guards, which are independent entries in `settings.json`.
