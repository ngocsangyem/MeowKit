MeowKit has one CLI: the native `mewkit` binary, with `mk` as a short alias. Install it first, then add the kit to each project.

## Prerequisites

- Git, installed and configured.
- At least one supported runtime: Claude Code ([claude.ai/code](https://claude.ai/code)), Codex, Cursor, Grok, Pi, OMP or Antigravity.
- Node.js 24 or later, for the kit's hooks. The `mewkit` binary does not need Node.js.
- Python 3.9 or later, only for the skills that run Python. The core workflow needs none. `mewkit setup` prepares one environment per skill under `.meowkit/envs/<skill>/`.

## Install the CLI

macOS and Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/ngocsangyem/MeowKit/main/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://raw.githubusercontent.com/ngocsangyem/MeowKit/main/install.ps1 | iex
```

The installer checks the archive's size and SHA-256 against the pins it carries, then puts `mewkit` on your PATH with `mk` beside it. `mk` is the same binary, so `mk doctor` and `mewkit doctor` do the same thing.

| Variable | Effect |
|----------|--------|
| `MEWKIT_INSTALL_DIR` | Install somewhere other than the default directory |
| `MEWKIT_VERSION` | Refuse to install unless the pinned version is the one you name |
| `MEWKIT_CHANNEL=beta` | Install the newest prerelease instead of the newest stable release |

Later updates come from `mewkit self-update`. When a newer `mewkit` is out, `init` ends with a one-line note that names it. It checks the release's `binary-manifest.json` and the archive's SHA-256 and size before it replaces the binary, and it keeps the previous binary beside it.

<Callout type="info">
  If an existing `mk` on your PATH is not MeowKit, the installer leaves it alone and reports it. A `mewkit-next` left by the 0.1.0 or 0.1.1 installer is removed by a reinstall or by `mewkit self-update`.
</Callout>

## Add MeowKit to a project

From the project directory:

```bash
mewkit init
```

Without flags, `init` asks which runtimes to set up. The choices are Claude Code, Codex, Cursor, Grok, Pi, OMP and Antigravity; tick one or more. Each runtime gets the files it reads. Those files are projected from the one authored tree in `.claude/`, plus a small overlay for that runtime's hooks and config. An install for a runtime other than Claude Code does not write `.claude/`. In a project that already has `.claude/`, `init` refreshes it and skips the picker. [Portability](/cli/portability) lists where each runtime's files go.

### Flags

| Command | Effect |
|---------|--------|
| `mewkit init --target claude-code` | Claude Code only, no picker |
| `mewkit init --target codex` | Codex only |
| `mewkit init --target cursor` | Cursor only |
| `mewkit init --target grok` | Grok only (project scope) |
| `mewkit init --target pi` | Pi only (project scope) |
| `mewkit init --target omp` | OMP only (project scope) |
| `mewkit init --target antigravity` | Antigravity only (project scope). Installs skills, the instruction block, rule files, agents and the two guards in `.agents/hooks.json`. Each guard is from documentation, unverified: no live run has shown it deny, and `init` and `doctor` say so |
| `mewkit init --target all` | All seven runtimes at project scope. With `--global`, Claude Code, Codex and Cursor |
| `mewkit init --profile core` | Claude Code: install a subset (`core`, `developer`, `product`, `atlassian`, `security`, `research`, `full`) |
| `mewkit init --yes` | Take every default and ask nothing |
| `mewkit init --dry-run` | Show what would change and change nothing |
| `mewkit init --force` | Replace or remove files you edited after the kit installed them |
| `mewkit init --kit-version v2.16.0` | Install exactly this kit release |
| `mewkit init --global` | Act on your home directory instead of the project |

An unrecognized `--target` is refused by name, with the valid values listed.

### Delivery shape

`--target claude-code` has two on-disk shapes, and `--delivery` picks one:

```bash
mewkit init --target claude-code --delivery native  # .claude/, the default
mewkit init --target claude-code --delivery plugin  # plus .claude-plugin/plugin.json
```

Both deliveries carry the same content. `plugin` adds the manifest Claude Code reads to load the kit as a plugin.

`--delivery` applies to `claude-code` only. Codex, Cursor, Grok, Pi, OMP and Antigravity each have one shape, so `--delivery` is refused when Claude Code is not among the runtimes being installed.

### Install from a downloaded zip

To install a kit zip you already have, pass it with `--kit-archive`. Its SHA-256 comes from a `checksums.txt` beside it, or from `--kit-sha256`:

```bash
mewkit init --kit-archive ./meowkit-release.zip
```

A kit release is a zip with a `checksums.txt`. The binary checks the zip against that file before it installs anything.

## What is installed here

```bash
mewkit versions
```

Prints this project's CLI version, kit version, target and delivery, and how the content arrived. It exits non-zero in a directory with no install, so a script can tell "nothing installed" from "installed with an unusual version".

## What gets generated

For Claude Code the install is:

```
.claude/              What Claude Code reads
├── agents/          Specialist agents for each phase
├── skills/          Domain skills with mk: namespace
├── hooks/           Lifecycle hooks, all Node (.cjs)
├── rules/           The 6 always-on rules
├── settings.json    Hook registrations
├── kit-contract.json      Kit version and CLI requirements
├── kit-capabilities.json  How each runtime names Claude Code tools
└── statusline.cjs   Status line

.meowkit/             Your project's own state
├── config.yaml      Project configuration, commit this
├── bin/mewkit       Launcher pinned to the installing CLI version, committed
├── .env             API keys, gitignored, shared by every provider
├── metadata.json    What this install put on disk, and what you have edited since
├── pack-manifest.json  Which packs this release ships
├── harness-inventory.json  Generated registry of .claude/ artifacts
├── memory/          decisions.md + gotchas.md, committed
├── telemetry/       Cost log, trace log
├── state/           Session markers; ownership/*.json is the install record, committed
├── envs/            One Python environment per skill, from `mewkit setup`
├── cache/           Derived caches, rebuildable
└── mcp.json.example Optional MCP server config
```

The split follows ownership: `.claude/` holds what Claude Code itself reads, so `settings.json` and
`.mcp.json` stay there. Everything MeowKit owns lives in `.meowkit/`. `config.yaml` and `memory/*.md`
are meant to be committed; the other state directories are machine-written and belong in
`.gitignore` (`mewkit setup` appends them for you).

You never edit `metadata.json`. It records what the install wrote and what its contents were, which is how `mewkit upgrade` tells a file you edited from one it shipped. Delete it and the next upgrade has no baseline, so it treats every file as untouched.

An install created before these files moved keeps working: readers fall back to the old `.claude/`
locations, and the next `upgrade` migrates each one forward.

## Verify installation

```bash
mewkit doctor
```

`doctor` checks the toolchain (Node.js, Python, Git), the installs in this project, and their hooks.

## Post-install setup

### MCP servers (optional)

`mewkit setup` copies `.meowkit/mcp.json.example` to `.mcp.json` and leaves an existing `.mcp.json`
alone. Run only that step with:

```bash
mewkit setup --only mcp
```

Then edit `.mcp.json` to add the keys for the servers you need.

Available MCP servers: Context7 (docs), Playwright (QA), Sequential Thinking.

### Gemini API key (optional)

For `mk:multimodal` (image, video and audio analysis):

```bash
# Add to .meowkit/.env, gitignored, secrets stay local
echo "MEOWKIT_GEMINI_API_KEY=your-key" >> .meowkit/.env
```

Get a key at [aistudio.google.com/apikey](https://aistudio.google.com/apikey).

## Coming from the npm CLI

If a project still runs the npm CLI, read [Moving from the npm CLI](/migration/from-npx-mewkit) before you change anything. The kit already in the project keeps working.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| `.claude/` already exists | Use `--force` flag or delete manually |
| Hooks not executable | Run `chmod +x .claude/hooks/*` |
| Python scripts fail | Ensure Python 3.9+ is in PATH |
| Claude Code doesn't load `.claude/rules/` | Restart the Claude Code session; `mewkit validate` confirms the always-on rules are present |
| The agent refuses to edit any file | Nothing in MeowKit blocks edits on a missing plan, so check the host's permission prompt. A refused commit means the ship check failed; see [When a check blocks you](/core-concepts/enforcement#when-a-check-blocks-you) |
| `doctor` reports hooks not executable after a fresh clone | Run `chmod +x .claude/hooks/*`; permissions do not survive some archive formats |
| A hook fails to start | Check that Node.js 24+ is on your PATH. The hooks run on Node even though the binary does not |
