A workflow is a playbook for a scenario that has its own starting material. To build, fix, review or ship something in code you already have, use a [guide](/guides/build-a-feature) instead. There is one guide per task and each is shorter.

## Start from what you have

| What is in front of you | What you want out of it | Playbook |
|---|---|---|
| A Jira ticket | A PR ready to merge | [Ticket to Code](/workflows/ticket-to-code) |
| A Jira ticket | To know whether it is ready to work on, and how big it is | [Ticket Evaluation](/workflows/ticket-evaluation) |
| A ticket with screenshots, video, a PDF or a Figma link | Implementation that matches the attachments | [Ticket with Media](/workflows/ticket-with-media) |
| A Confluence spec | A planned sprint | [Spec to Sprint](/workflows/spec-to-sprint) |
| A Confluence spec | A PR, with every step explained | [Spec to PR: Behind the Scenes](/workflows/spec-to-pr-walkthrough) |
| A PRD or a pile of incoming requests | Analysed, triaged, estimated work | [PRD Intake](/workflows/prd-intake) |
| A sprint and a team | Sprint goal, DoR/DoD, retro actions, spike governance | [Agile / Scrum](/workflows/agile-scrum) |
| Commit history | A retrospective people will read | [Sprint Retrospective](/workflows/retrospective) |
| An empty directory | A project with MeowKit installed and a first plan | [Quick Start](/quick-start) |
| Somebody else's undocumented codebase | Enough understanding to change it safely | [Maintaining Old Projects](/workflows/maintenance) |
