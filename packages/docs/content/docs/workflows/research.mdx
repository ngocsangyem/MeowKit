This playbook compares options and fetches current documentation before you commit to a dependency.

**Best for:** Choosing dependencies, evaluating frameworks, gathering docs
**Time estimate:** 15 to 30 minutes
**Skills used:** [mk:docs-finder](/reference/skills/docs-finder), [mk:scout](/reference/skills/scout)
**Agents involved:** researcher, brainstormer

## Overview

The **researcher** agent queries several sources at once (official documentation, GitHub repositories and issues, community posts, Stack Overflow, and patterns already in your codebase) and grades what it finds. The **brainstormer** agent compares the approaches with pros, cons and trade-offs. Both feed the **planner**.

## Step 1: Ask the question

```
"Compare Prisma vs Drizzle for our PostgreSQL project"
```

## Step 2: The researcher gathers findings

Sources are weighted by trust:

| Source | Trust |
|---|---|
| Official documentation | Highest |
| Maintained open-source repositories | High |
| Recent posts (under 12 months, for fast-moving ecosystems) | Medium |
| Stack Overflow answers | Low; cross-reference them |

The findings mark each point as established, emerging or experimental, and state a confidence level:

```
Prisma: established. Strengths: schema-first, migrations. Weaknesses: runtime overhead, limited raw SQL.
Drizzle: newer. Strengths: SQL-like syntax, light. Weaknesses: smaller ecosystem.
Confidence: high (both well documented)
```

## Step 3: The brainstormer compares trade-offs

```
Prisma: choose it if the team values developer experience and generated migrations.
Drizzle: choose it if the team values performance and SQL familiarity.
Second-order effect: Prisma ties you to its schema format; Drizzle stays close to SQL.
```

## Step 4: Fetch the specific docs

```
/mk:docs-finder drizzle PostgreSQL transactions
```

[mk:docs-finder](/reference/skills/docs-finder) fetches current documentation through Context7 or Context Hub, so you do not rely on training data for API signatures.
