The kit has three conditional rule files for Scrum teams. They load only when a session looks Agile, so other sessions carry none of their cost. They add no agents and no hooks, and every prompt they raise is advisory.

**Best for:** Teams running Jira-tracked sprints with the kit
**Time estimate:** Per-sprint ceremonies; no setup beyond the sprint-state file and plan frontmatter
**Skills used:** [mk:plan-creator](/reference/skills/plan-creator), [mk:sprint-contract](/reference/skills/sprint-contract), [mk:retro](/reference/skills/retro), [mk:jira-agile](/reference/skills/jira-agile), [mk:ship](/reference/skills/ship), [mk:agent-detector](/reference/skills/agent-detector)
**Rules:** `agile-story-gates.md`, `agile-sprint-commitment.md` and `agile-feedback-cycle.md`, in `.claude/skills/agent-detector/references/`

## Quick path

```bash
/mk:sprint-contract sprint-goal set "<goal>" --sprint 42   # at sprint start
/mk:jira-agile sprint add PROJ-125 --sprint 42             # during
/mk:jira-agile sprint close --sprint 42                    # at sprint end
/mk:retro                                                  # after
```

## What the rules cover

- Definition of Ready: a Phase 1 advisory on each Jira ticket a plan lists.
- Definition of Done: three prompts when a review verdict is PASS or WARN.
- Sprint goal: kept in a file, so it survives across sessions.
- Mid-sprint amendments: scope changes are logged with a reason, not made silently.
- Sprint close: a disposition prompt for each ticket that is not finished, and a closure summary.
- Retro actions: each surfaced item becomes tracked work or a recorded "no action".
- Spikes: time-boxed investigations with a findings document.

## Activation

`mk:agent-detector` loads the three rules at orient time when any one of these is true:

| Trigger | Detection |
|---|---|
| Sprint-state file present | `tasks/contracts/sprint-state-*-sprint-*.md` matches at least one file |
| Plan frontmatter | `jira_tickets:` is non-empty in the active plan |
| Environment | `MEOW_JIRA_SITE_URL` is set |
| Prompt | The last user message matches `[A-Z]{2,10}-\d+` |

If `references/agile-story-gates.md` is missing beside the skill, the load is skipped silently.

## Sprint setup

### Create the sprint-state file

```bash
/mk:sprint-contract sprint-goal set "Reduce p99 checkout latency below 800ms" --sprint 42
```

This writes `tasks/contracts/sprint-state-{YYMMDD}-sprint-42.md` (the goal is one line, 120 characters at most):

```yaml
---
sprint_id: 42
sprint_goal: "Reduce p99 checkout latency below 800ms"
start_date: 2026-05-13
end_date: 2026-05-27
committed_tickets: []
amendments: []
status: active
---
```

`sprint-goal show --sprint 42` prints the goal, and `sprint-goal align --plan <path>` compares a plan's goal with it. Writers take a `flock` on the file before changing it.

### Trace plans to Jira

In `tasks/plans/{slug}/plan.md` frontmatter:

```yaml
jira_tickets: [PROJ-123, PROJ-124]
sprint_id: 42
```

`mk:plan-creator` then runs the Definition of Ready advisory, and `mk:ship` raises the Definition of Done prompts.

## Per-sprint ceremonies

### Definition of Ready

On a plan with `jira_tickets:`, `/mk:plan-creator` checks each ticket for:

1. Acceptance criteria text.
2. A non-zero story point estimate.
3. Sprint linkage, if `sprint_id:` is set.
4. A `mk:jira-evaluator` report from the last 14 days.
5. No open `is blocked by` link to a ticket that is not Done.

The output lists the gaps and asks whether to proceed or fix them first. It never blocks.

### Mid-sprint scope change

```bash
/mk:jira-agile sprint add PROJ-125 --sprint 42
```

If the sprint is active, the skill locks the sprint-state file, asks for the reason for the change (free text, required), appends `{ ts, action, ticket, reason }` to `amendments:` and then makes the Jira call. In a harness FULL run, `mk:sprint-contract amend` is used instead.

### Definition of Done

Once the verdict has a non-empty `jira_tickets:` and a status of PASS or WARN, `/mk:ship` offers three actions, each cancel-safe and each with a Jira-offline fallback (`deferred`):

1. Post the verdict summary to the ticket as a comment.
2. Transition the ticket to Done.
3. Confirm each business acceptance criterion, taken from the Jira AC field or, if that fails, from the plan's `## Acceptance Criteria`.

Without `jira_tickets:` the whole block is skipped.

### Sprint close

```bash
/mk:jira-agile sprint close --sprint 42
```

The skill reads `committed_tickets:`, checks each ticket's status, asks what to do with each one that is not finished (carry over, drop, mark not delivered), and writes `status: closed`, `closed_at`, `delivered` and `carried_over` to the sprint-state file.

### Retro action items

After `/mk:retro` writes its narrative in an Agile context, it asks about each item under `## 3 Things to Improve` and `## 3 Habits for Next Week`:

| Option | Effect |
|---|---|
| Create Jira story now | `mk:jira-issue create` with the body pre-filled; you review before it submits |
| Add to plan TODO | Appends to the active plan |
| Document as no-action | Records the reason in `tasks/reports/retros/{date}-decisions.md` |
| Defer to next retro | Carries the item forward |

The retro is complete when every item has a disposition. See [Sprint Retrospective](/workflows/retrospective).

### Spikes

```bash
/mk:plan-creator --spike --timebox 2d "Investigate JWT refresh strategy options"
```

`--spike` requires `--timebox`. It writes a two-phase plan from `assets/spike-plan-template.md`: investigate (inside the timebox) and document findings (up to 25 percent of the timebox). The frontmatter has `spike: true`, `timebox:` and `findings_doc:`. There is no test phase and no ship phase. Above 5 story points, the plan warns that it is probably two spikes.

<Callout title="Spikes and autobuild" type="warn">

A spike plan skips the test and ship phases, so it does not fit `mk:autobuild` in FULL density, and `mk:plan-creator` rejects the combination. Run it through `mk:cook` or `mk:plan-creator --fast`.

</Callout>

At the end of a spike you are asked whether to convert the findings into a delivery story, keep them as research only, or defer.

## Design

- The plan is the source of truth. Jira receives projections (a verdict comment, a status change) and is never authoritative.
- Every action surfaces a prompt. Nothing creates tickets silently.
- Sprint-state files use a `sprint-state-` prefix, so they do not collide with per-story sprint contract files.
- Sprint-state files have no validator script. The skills that read them parse the YAML.

Out of scope: WIP limits, async standup cadence, PO acceptance ceremony, velocity hygiene and two-way Jira sync.
