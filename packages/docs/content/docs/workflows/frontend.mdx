Three skills carry the frontend conventions, and each activates on the files or task it covers.

**Best for:** UI features, component development, styling
**Time estimate:** 15 to 60 minutes
**Skills used:** [mk:vue](/reference/skills/vue), [mk:typescript](/reference/skills/typescript), [mk:frontend-design](/reference/skills/frontend-design)
**Agents involved:** developer, tester, reviewer

## Which skill activates

| Skill | Activates on | Covers |
|---|---|---|
| `mk:vue` | `.vue` files, Composition API, Pinia | `<script setup lang="ts">`, Pinia, routing, forms |
| `mk:typescript` | `.ts`, `.tsx`, `.js`, `.jsx` files and type errors | Strict null handling, type guards, type-safety fixes |
| `mk:frontend-design` | Design and styling tasks | Typography, color, layout, accessibility, the anti-slop checklist |

The skills apply these as defaults. Where the repository already has a convention, that one wins.

## Vue components

With `mk:vue`, the defaults are:

| Default | Detail |
|---|---|
| `<script setup lang="ts">` only | No Options API and no `defineComponent()` wrapper |
| `type` over `interface` | For object and prop shapes |
| `ref()` for primitives | `reactive()` only for complex objects, `computed()` for derived state |
| `storeToRefs()` | Required when destructuring Pinia state; methods are destructured directly |
| No `v-html` with user content | It is an XSS vector, and `security-rules.md` blocks it |
| PascalCase components, kebab-case files | `UserProfile` in `user-profile.vue`; composables are `useX` |
| Named exports | Composables use `export default` |
| Tailwind classes | No manual CSS and no hard-coded colors |

## TypeScript

With `mk:typescript`:

| Rule | Example |
|---|---|
| No `any` | Use `unknown` with type guards |
| No type assertions | Narrow with a guard instead of `as` |
| No implicit truthiness for null checks | `user !== null`, not `if (user)` |
| Type-only imports | `import type { User } from './types'` |
| Named exports over default | `export const X` |
| Discriminated unions | `{ ok: true; data: T } \| { ok: false; error: string }` |

## Design quality

Before delivering UI, `mk:frontend-design` runs its anti-slop checklist. Examples from it:

| Check | Fails when | Do instead |
|---|---|---|
| Typography | All text has one size and weight | Set a hierarchy: display, heading, body, caption |
| Color | Unrelated colors, or contrast that was never checked | One primary, one accent and neutrals, with readable contrast |
| Layout | Everything centered, equal card grids | Asymmetry and varied whitespace |
| Spacing | Default padding everywhere | A consistent scale on a 4px base |
| Content | Lorem ipsum or "John Doe" in the final output | Realistic content |
| Accessibility | Contrast below 4.5:1 | Meet WCAG 2.1 AA |

## Review

The **reviewer** agent's performance dimension covers frontend concerns: unnecessary re-renders, unbounded data fetches and blocking calls in async code.
