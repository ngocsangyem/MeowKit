---
title: "Sprint Retrospective"
description: "Run a team-aware engineering retrospective from commit history, with a saved snapshot for trend tracking."
---

`mk:retro` reads your git history and writes a retrospective: what shipped, how the team worked and how it compares with earlier runs.

**Best for:** End of a sprint or week
**Time estimate:** 10 to 15 minutes
**Skills used:** [mk:retro](/reference/skills/retro)

## Run it

```
/mk:retro
```

The default window is the last 7 days. The skill accepts `24h`, `14d`, `30d`, `compare` and `global`.

## What it analyzes

- Commit counts and a percentage breakdown by conventional commit type (feat, fix, refactor, test, chore, docs).
- Lines of code, test lines and a test ratio.
- Per-person breakdowns for every contributor, each with specific praise anchored in commits and one growth suggestion. You get the deepest section.
- Time patterns, session counts and hotspot files.
- Weekly trends when the window is 14 days or longer, and commit streaks for the team and for you.

## Trend tracking

Each run saves a JSON snapshot to `tasks/reports/retros/`, and the narrative goes there too. The next run loads earlier snapshots to compare. `compare` mode compares the current window with the previous one, and `global` mode runs the retro across repositories.

## Memory

`mk:retro` appends one entry to `.meowkit/memory/gotchas.md` (or `decisions.md` for a decision) through `mewkit note`, and only when the lesson cannot be read from the code, the diff or `git log`.

## Agile action items

In an Agile context (a sprint-state file, `MEOW_JIRA_SITE_URL`, `jira_tickets:` in plans, or a Jira key in the prompt), `mk:retro` also asks about each item under `## 3 Things to Improve` and `## 3 Habits for Next Week`:

| Option | Effect |
|---|---|
| Create Jira story now | Runs `mk:jira-issue create` with the body pre-filled; you review before it submits |
| Add to plan TODO | Appends to the active plan |
| Document as no-action | Records the reason in `tasks/reports/retros/` |
| Defer to next retro | Carries the item forward |

The retro is complete when every item has a disposition. It never creates Jira stories on its own. Outside an Agile context this step does nothing. The rule is `agile-feedback-cycle.md`; [Agile / Scrum](/workflows/agile-scrum) covers the rest of the sprint ceremonies.

## Sprint data

`mk:retro` uses git history only. It does not read Jira sprint velocity or ticket metrics.
