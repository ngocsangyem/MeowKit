Two skills cover QA. `mk:qa-manual` tests from a spec and writes either a report or Playwright code. `mk:qa` tests a running site, fixes the bugs it finds and re-verifies.

**Best for:** Pre-release testing, E2E automation
**Time estimate:** 15 to 45 minutes
**Skills used:** [mk:qa-manual](/reference/skills/qa-manual), [mk:qa](/reference/skills/qa)
**Browser skills:** [mk:agent-browser](/reference/skills/agent-browser), [mk:playwright-cli](/reference/skills/playwright-cli)

## Manual QA report

```
/mk:qa-manual tasks/plans/260327-auth/plan.md --report
```

The skill acts like a human tester and sends each action to the browser skill that suits it:

| Action | Tool |
|---|---|
| DOM interaction | `mk:playwright-cli`, which also generates Playwright code as a side effect |
| Login and session flows | `mk:agent-browser`, which keeps sessions |
| Visual checks | `mk:agent-browser`, with annotated screenshots |

### Credentials

At a login page the skill stops and asks you for the credentials. It never guesses them. You can answer `skip` to skip the flow or `abort` to stop testing.

### The report

```markdown
## QA Manual Test Report
Spec: tasks/plans/260327-auth/plan.md

| Flow | Steps | Passed | Failed | Status |
|------|-------|--------|--------|--------|
| Login | 5 | 5 | 0 | PASS |
| Password reset | 4 | 3 | 1 | FAIL |

Failed: Password reset, step 3
Expected: "Reset email sent" message
Actual: 500 Internal Server Error
```

## E2E code generation

```
/mk:qa-manual tasks/plans/260327-checkout/plan.md --generate
```

It navigates the same way and writes `.spec.ts` files with role-based locators (`getByRole`, `getByLabel`) and test-ID locators where the project has them. [Writing Tests](/workflows/writing-tests) shows the folder layout. Pass a URL instead of a spec to explore and test from the page.

## Test, fix and verify

```
/mk:qa https://app.example.com
```

[mk:qa](/reference/skills/qa) tests the app as a user would. For each bug it can fix, it applies a minimal fix, makes an atomic commit and retests the page. It scores the app's health before and after, in Quick, Standard or Exhaustive tiers, and writes a report with the before and after evidence. It commits in your project, and the ship check applies to those commits like any others.
