---
title: "Step 10: After merge, close the loop"
description: "Transition the ticket, comment the outcome, and add a footer comment to the source spec page so readers can trace each requirement to a ticket and PR."
---

When the PR merges:

```bash
/mk:jira-lifecycle transition AUTH-201 --to "Done" --resolution Fixed
/mk:jira-collaborate add comment to AUTH-201: "Shipped in PR #142. Spec §R1, AC1-AC3 satisfied. AC2 dashboard target is /app/dashboard (confirmed with PM)."
/mk:confluence-collaborate add a footer comment to page 12345: "AUTH-201 (Google OAuth) shipped in PR #142."
```

Check the status names first. `mk:jira-lifecycle` reads them from the workflow cache in `tasks/jira-workflows/` and asks for a resolution when the transition to Done requires one.

The footer comment on the spec page is the second write to Confluence in this walkthrough, after the questions in [Step 2](/workflows/spec-to-pr-walkthrough/step-02-open-questions). It tells future readers which ticket and PR delivered each requirement.
