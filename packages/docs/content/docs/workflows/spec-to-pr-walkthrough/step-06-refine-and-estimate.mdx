---
title: "Step 6: Refine and estimate"
description: "mk:jira-evaluator rates a ticket's complexity and flags inconsistencies. mk:jira-estimator suggests story points and reads the evaluator's report when one exists. Neither changes Jira."
---

## Prompt

```bash
/mk:jira-evaluator AUTH-201
/mk:jira-estimator AUTH-201
```

## What happens

`mk:jira-evaluator` reads the ticket with its comments, attachments and links, and compares it with similar closed tickets found by a capped JQL search.

| Output | Content |
| --- | --- |
| Complexity | Simple, Medium or Complex, with a likely Fibonacci range |
| Confidence | High, Medium or Low |
| Signals | Scope, dependencies, regression risk, requirement clarity, external integration and historical precedent |
| Issues detected | Missing acceptance criteria, vague wording, scope creep, missing dependency links and contradictions |
| Report | `tasks/reports/jira-evaluate-{YYMMDD}-{HHMM}-{KEY}.md` |

`mk:jira-estimator` reads that report if it exists and writes `tasks/reports/jira-estimate-{YYMMDD}-{HHMM}-{KEY}.md`.

| Output | Content |
| --- | --- |
| Suggested points | One number with a range |
| Confidence and reasoning | Why that number |
| Escalation | A recommendation for human estimation when the range spans more than one Fibonacci step, there is no precedent, the ticket names technology absent from the codebase, or the description is too vague |
| Apply command | A `jira-as issue update --custom-fields` command you can run to write the points. The skill does not run it. |

Both skills write only a local report. The estimator checks the instance's Story Points field ID before it suggests a write, because it differs between Jira instances.

Both give suggestions. The team still estimates together and decides the points.
