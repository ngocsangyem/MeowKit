title: "Step 5: Group into an epic and rank"
description: "Add the tickets to an epic, rank the backlog and declare blocking links. You declare every ordering decision; the skills do not infer one."
---

## Prompt

```bash
/mk:jira-agile add AUTH-201, AUTH-202, AUTH-203 to epic AUTH-200
/mk:jira-agile rank AUTH-202 before AUTH-201 in the backlog   # session expiry comes first
/mk:jira-relationships link AUTH-201 blocks AUTH-203
```

These skills take plain-language requests. Link direction matters, so `mk:jira-relationships` confirms it when the request is ambiguous.

## What happens

| Skill | Request | Effect |
| --- | --- | --- |
| `mk:jira-agile` | Add issues to an epic | Adds each issue to the epic. |
| `mk:jira-agile` | Rank | Moves an issue before or after another in the backlog. |
| `mk:jira-relationships` | Link | Creates an issue link such as `blocks`, visible on both tickets. |

## Decision point

You supply the dependencies and the order. The spec analyst can suggest dependencies in its report, but the skills do not read "blocks" from the spec and do not reorder the backlog on their own.
