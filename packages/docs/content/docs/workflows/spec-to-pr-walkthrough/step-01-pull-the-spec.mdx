title: "Step 1: Pull the spec out of Confluence"
description: "mk:confluence-spec-analyst forks an agent, reads the Confluence page and its children, and writes a Spec Research Report to the local repository. It never writes to Confluence."
---

## Prompt

```bash
/mk:confluence-spec-analyst analyze 12345 --include-children 1
```

Or in plain language:

```
Analyze the spec at https://acme.atlassian.net/wiki/spaces/ENG/pages/12345
Pull child pages 1 level deep. I want requirements, acceptance criteria,
and any gaps or ambiguities flagged.
```

Options: `--no-images` skips image analysis, and `--with-commands` appends suggested `mk:jira-issue create` commands to the report. Without `--with-commands` the report holds suggestions only.

## What happens

| Layer | Action |
| --- | --- |
| Router | `mk:confluence` maps a spec-analysis request to the `mk:confluence-spec-analyst` leaf. |
| Fork | The skill sets `context: fork` and `agent: confluence-spec-analyst`, so the agent runs in a fresh context window. Spec text, gap heuristics and the weasel-word inventory stay out of your main session. |
| Fetch | The agent reads the page through the `confluence-as` wrapper and converts the body to markdown. It then reads child pages. `--include-children` defaults to 1 and has a hard cap of 10. The agent definition also caps children at 5 for Cloud rate limits. |
| Images | If the page embeds images, `mk:multimodal` describes them. Without that skill the report carries `[NO_MULTIMODAL]` and the analysis continues. |
| Output | A report under `tasks/reports/confluence-spec-{YYMMDD}-{HHMM}-{title-slug}.md`, or in the active plan's `research/` folder. A row is appended to `tasks/reports/.confluence-spec-index.tsv`. |

The agent has the Write tool only to save the report locally. Page content is treated as data, so instructions inside a spec are flagged in the report and not followed.

## What the report contains

The report starts with `# Spec Research Report: {page title}`. `mk:planning-engine --spec` checks for that heading in Step 7. The sections are:

- TL;DR
- Requirements, split into functional (`REQ-F-n`), non-functional (`REQ-NF-n`) and optional (`REQ-O-n`)
- Acceptance Criteria (`AC-n`)
- Constraints and assumptions
- Gaps and Ambiguities, a table with types such as `missing-info`, `missing-units`, `weasel-word` and `requirement-conflict`
- Suggested User Stories, with a complexity signal and suggested Jira fields
- Image and Diagram Findings
- Suggested Commands, only with `--with-commands`
- Open Questions

The report ends with a SHA-256 hash of the fetched page. Running the skill again on that page writes a fresh report, and the hash shows whether the page changed.

## Decision point

You decide which gaps must be resolved before tickets exist. The agent does not fill gaps with guesses. When the spec is unclear, `.claude/rules/core-behaviors.md` has the agent stop and name the confusion instead of picking an interpretation.
