title: "Step 2: Send open questions back to the PM"
description: "A footer comment on the Confluence page carries the spec's ambiguities to the PM. The walkthrough pauses here, before any ticket exists."
---

## Prompt

```bash
/mk:confluence-collaborate add a footer comment to page 12345: "Three open questions from spec analysis: (1) Google scopes? (2) Session expiry style, sliding or hard? (3) Can OAuth users add a password later?"
```

## What happens

| Layer | Action |
| --- | --- |
| Comment type | `mk:confluence-collaborate` posts footer comments by default. Inline comments attach to a text selection, so the agent asks you before posting one. |
| Format | Comment bodies are markdown, which the `confluence-as` wrapper converts. |
| Notification | The PM gets a Confluence notification. Their reply appears as a comment thread on the page. |
| Workflow | You stop here until the PM answers. |

## Why the walkthrough pauses

Settling the ambiguity before ticket creation avoids two problems:

1. Tickets with vague acceptance criteria get estimates that look more certain than they are.
2. Code ships for one reading of an ambiguous spec, and gets reworked when the other reading turns up.
