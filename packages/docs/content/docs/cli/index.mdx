MeowKit has one CLI, the native `mewkit` binary, with `mk` as a short alias. `mk doctor` and `mewkit doctor` run the same binary; this reference uses the long form. [Installation](/installation#install-the-cli) shows how to get it. Run project commands from the project root.

## Get started

```bash
# 1. Install the kit into your project
cd your-project
mewkit init

# 2. Configure environment
mewkit setup

# 3. Verify installation
mewkit doctor

# 4. Create your first task
mewkit task new --type feature "Add user authentication"
```

## Runtimes and scopes

`init` writes each runtime's files in the format that runtime reads. The runtimes other than Claude Code are projected from `.claude/` plus a small overlay for their hooks and config.

| Runtime | `--target` | Project install | `--global` install |
| --- | --- | --- | --- |
| Claude Code | `claude-code` | `.claude/` | `~/.claude/` (or `CLAUDE_CONFIG_DIR`) |
| Codex | `codex` | `.codex/`, `.agents/skills/`, a block in `AGENTS.md` | `~/.codex/` (or `CODEX_HOME`), `~/.agents/skills/` |
| Cursor | `cursor` | `.cursor/` | `~/.cursor/` |
| Grok | `grok` | `.grok/`, `AGENTS.md` | not available |
| Pi | `pi` | `.pi/`, `.agents/skills/`, `AGENTS.md` | not available |
| OMP | `omp` | `.omp/`, `.agents/skills/`, `AGENTS.md` | not available |

`--target` takes a comma-separated list or `all`. Where a runtime's skills, agents and rules go depends on which runtimes are installed together, because some runtimes also read each other's folders. The [runtime surface table](https://github.com/ngocsangyem/MeowKit/blob/main/crates/mewkit-adapters/runtime-surface-table.md) lists the placement for each set. [Portability](/cli/portability) lists what each install writes.

The CLI keeps its own state (ownership indexes, lock, kit cache) in `.meowkit/` for a project and in `~/.mewkit/state/` for a global install. Files you already had are merged, not replaced: hook files handler by handler, Markdown by a marked block, JSON and TOML by key. The ownership index for each runtime sits at `.meowkit/state/ownership/<runtime>.json` (`~/.mewkit/state/ownership/<runtime>.json` globally). `upgrade` and `uninstall` act only on what it records.

## How hooks reach `mewkit`

For Claude Code at project scope, `init` writes a small launcher at `.meowkit/bin/mewkit` and commits it, with a `.claude/runtime.json` that points the hooks at it.

- The launcher resolves the CLI and runs it. It runs the `mewkit` binary (or `mk`) when one is on `PATH`, in `MEWKIT_INSTALL_DIR` or in `~/.local/bin` and reports a compatible version. A project whose kit the retired npm CLI installed keeps running the copy in its own `node_modules` until you move it ([Moving from the npm CLI](/migration/from-npx-mewkit)).
- The launcher makes no network request. When no CLI is available it says so, names `mewkit doctor` and exits 127.
- Hooks do not depend on your shell. They run the launcher through `.claude/runtime.json`, which is re-validated on every read and refuses any executable outside the project.
- The SessionStart hook puts the launcher's directory first on `PATH`, so plain `mewkit` commands work in the agent's shell. That directory contains only `mewkit`, so nothing else on your `PATH` changes. On Windows PowerShell the bare form is unavailable and the hook prints the `mewkit doctor` hint instead.
- A teammate who clones the repository gets the launcher with it. They still need the binary on their machine.

The binary needs no Node.js. The kit's hooks are Node scripts and need Node.js 24 or later; `mewkit doctor` fails below it and names the version it found.

## Exit codes and help

| Code | Meaning |
| --- | --- |
| `0` | The command ran and succeeded |
| `1` | The command ran and failed; a lifecycle command leaves nothing half-applied |
| `2` | The invocation was wrong: unknown command, unknown subcommand, or a missing subcommand on a command that requires one |
| `3` | A lifecycle dry run found changes to make, `--force` had no terminal and no `--yes` to confirm it, or `self-update --check` found an update |
| `6` | `init`, `upgrade` or `uninstall` kept files you edited; `--force` replaces or removes them |
| `127` | The committed launcher found no CLI to run |

A code `2` names what was wrong and what you could have typed. `mewkit <command> --help` and `mewkit <command> <subcommand> --help` print usage and run nothing.
