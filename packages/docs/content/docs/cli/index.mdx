MeowKit ships one CLI package, `mewkit`. Run it from your project root; there is nothing to
install globally — the install writes a committed launcher that makes the bare `mewkit` form
resolve inside the project.

## Get started

```bash
# 1. Scaffold MeowKit into your project
cd your-project
npx mewkit init

# 2. Configure environment
mewkit setup

# 3. Verify installation
mewkit doctor

# 4. Create your first task
mewkit task new --type feature "Add user authentication"
```

## How `mewkit` resolves after the install

The first command is `npx mewkit init`, because at that point the project has nothing in it
to run. Everything after it is written as plain `mewkit …`, and the install is what makes
that name resolve:

- `init` writes a small launcher at `.meowkit/bin/mewkit`, **pinned** to the CLI version that
  installed the kit, and commits it. It is a resolver, not a copy of the CLI: it finds the
  pinned version — in the project's own `node_modules` first, then from this machine's record
  of that version — and runs it.
- The launcher never reaches the network. If the pinned version is not available it says so
  and names `mewkit doctor`, rather than fetching mid-session.
- Hooks do not depend on your shell: they execute the launcher through the install-written
  `.claude/runtime.json`, which is re-validated on every read and refuses any executable
  outside the project.
- For your own shell commands, the SessionStart hook puts the launcher's directory first on
  `PATH`, so plain `mewkit …` works. That directory contains only `mewkit`, so nothing else
  on your `PATH` changes. On Windows PowerShell the bare form is unavailable and the hook
  prints the `mewkit doctor` hint instead.
- A teammate who clones the repository gets the launcher with it and needs no install step.

Requires **Node.js 24+** — the same floor `engines.node` enforces and the version the test
matrix runs. `mewkit doctor` fails below it and names the version it found.

## Exit codes and help

Every command answers with one of three codes:

| Code | Meaning |
| --- | --- |
| `0` | the command ran and succeeded |
| `1` | the command ran and failed |
| `2` | the invocation was wrong — unknown command, unknown subcommand, or a missing subcommand on a command that requires one |

A code `2` always prints the valid subcommands, so a typo tells you what you could have
typed. `mewkit <command> <subcommand> --help` prints that subcommand's own usage and runs
nothing at all; `mewkit <command> --help` does the same for the command.

## Two things worth knowing up front

`npx mewkit init` both scaffolds and updates. The first run opens a toolkit picker (Claude Code, Codex, Cursor, with Claude Code preselected) and copies the full system into `.claude/` for each provider you choose; `--target <provider>` skips the picker. Later runs are a smart update: unchanged core files are overwritten, files you edited are left alone, new files are added, and there is no picker.

Everything else is a runtime toolbox for daily use. None of it is required to run MeowKit, and none of it changes your project unless the command says it does.
