MeowKit is authored for Claude Code. Codex and Cursor each get a maintained bundle that is written by hand for that tool. You install a bundle with `mewkit init --target`. The `.claude/` kit is not converted.

## Install for Codex or Cursor

```bash
mewkit init --target codex
mewkit init --target cursor
```

`--target` skips the toolkit picker and creates one toolkit. Each bundle is a set of files for that tool, plus `AGENTS.md`, which both tools read as the project instruction file.

| Tool | What the bundle installs |
| --- | --- |
| Codex | `AGENTS.md`, agents as `.codex/agents/*.toml`, skills as `.agents/skills/*/SKILL.md`, hooks in `.codex/hooks.json`, and `.codex/config.toml` |
| Cursor | `AGENTS.md`, agents as `.cursor/agents/*.md`, skills under `.cursor/skills/`, rules as `.cursor/rules/*.mdc`, and hooks in `.cursor/hooks.json` |

A `--target` install does not need a `.claude/` directory. Cursor also accepts `--mcp-profiles <name>` to merge MCP profiles into `.cursor/mcp.json`. Applying a profile to a repository with a git remote also needs `--allow-cloud-mcp`.

`--dry-run` prints what would be written without writing it.

## Keep an install current

`mewkit upgrade` refreshes each installed bundle from the ledger that the install wrote. If the project also has `.claude/`, the upgrade updates that too, so the installs move together.

Some projects still carry a `.cursor/` or `.codex/` directory from the retired `migrate` command. Those directories have no ledger. `upgrade` leaves them alone and prints a notice. To switch to the maintained bundle, run:

```bash
mewkit init --target cursor    # or: mewkit init --target codex
```

## Legacy memory

Neither bundle imports the memory store that older releases kept under `.claude/`. If you still need content from it, copy the parts you need into `.meowkit/memory/`.

## What each tool supports

The table shows what each bundle ships. ✓ included · — not included.

| Tool | Agents | Skills | Rules | Hooks | Config |
| --- | :---: | :---: | :---: | :---: | :---: |
| Cursor | ✓ | ✓ | ✓ | ✓ | MCP profiles |
| Codex | ✓ | ✓ | `AGENTS.md` | ✓ | ✓ |

**Notes:**

- The bundles ship the toolkit's own agents, skills and hooks. Your custom agents, commands and hooks in `.claude/` are not converted. Port them by hand.
- Codex agents are written as TOML. Each agent file sets `model_reasoning_effort`, and leaves `model` unset because Codex model ids depend on the deployment. Pin a model by editing the agent file or through a Codex config profile.

## providers

Show provider support (level, role, surfaces). Pass a provider name to see one. With `--lifecycle`, show the capability-adapter view instead: the four support levels, repo-context acquisition tools, storage boundary, and the per-lifecycle-event matrix (which events a provider fires and which it can actually gate/deny on).

```bash
mewkit providers [<provider>] [--json]
mewkit providers --lifecycle              # event × provider matrix (proven-gate markers)
mewkit providers <provider> --lifecycle   # one provider: levels, acquisition, lifecycle, evidence
```

| Flag          | Description                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| `--lifecycle` | Capability-adapter view: support levels + acquisition + lifecycle-event support. A `gate` is claimed only where a runtime hook can deny/block (never for version-gated or observe-only events). |
| `--json`      | Machine-readable output.                                                                                      |

Per-provider output also reports `--advice` supervision support. The harness and the direct
strategy consult are tracked as **separate capabilities**: a runtime can expose one and not
the other, so one proving out says nothing about the other. Each carries a state
(`supported`, `degraded`, `unverified`, `unavailable`), what the state rests on, and what
would move it up a rung.

Structural evidence never produces a `supported` claim: the files existing is not the same
as a runtime having done the thing. A capability leaves `unverified` only from a recorded
live run. Codex additionally reports its mutation ban as `degraded (behavioral)`, because a
Codex agent definition carries no per-agent tool field to enforce one. Claude Code and
Cursor enforce theirs structurally.

## pack

Manage optional capability packs layered over the base kit.

```bash
mewkit pack list [--json]
mewkit pack add <pack>… [--yes] [--beta]
mewkit pack remove <pack>…
```
