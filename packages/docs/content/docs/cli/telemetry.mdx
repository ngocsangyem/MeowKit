These commands read logs and manifests that the harness already writes. They change no project state, except `trace --friction`, which appends one note to the trace log, and `eval run`, which writes a report under `.meowkit/telemetry/eval/`.

## budget

`budget` reports token usage and estimated cost from the cost log.

```bash
mewkit budget [--monthly] [--session [id]] [--day [YYYY-MM-DD]]
```

| Flag | Description |
| --- | --- |
| `--monthly` | Aggregate by month instead of showing the last 10 entries |
| `--session` | Filter to the current session |
| `--session <id>` | Filter to a specific session id from `cost-log.json` |
| `--day` | Filter to today |
| `--day <date>` | Filter to a specific day, as `YYYY-MM-DD` |

- Without filters, `budget` shows the latest 10 rows and the all-time token total.
- `--session` finds the current session from `HOOK_SESSION_ID`, then from `.meowkit/state/last-session-id`.
- Filters combine, so `--session --day` reports the intersection.

```bash
mewkit budget
mewkit budget --monthly
mewkit budget --session
mewkit budget --session 9adf6a6b-9fbf-45ca-b36b-b0dd55356ac1
mewkit budget --day 2026-05-01
mewkit budget --session --day 2026-05-01
```

### budget context

`budget context` estimates how many tokens a profile loads from `.claude/`. CI uses it as a context-size guard. It needs `.meowkit/pack-manifest.json`, and an unknown profile name prints the available ones.

```bash
mewkit budget context [--profile <name>] [--fail-over N] [--json]
```

Without `--profile` it reports every profile. `--fail-over N` exits non-zero when a profile's estimate exceeds `N` tokens.

## trace

`trace` reads the append-only trace log for entropy and repeated friction, and records friction notes so later sessions can recall them. It is advisory and always exits 0.

```bash
mewkit trace audit            # orphaned, stale, unverified and repeated-friction signals
mewkit trace propose          # group friction seen at least twice into advisory backlog items
mewkit trace score            # entropy score
mewkit trace --friction "<note>" [--responsibility <r>] [--id <run-id>]
```

`propose --commit` appends the proposed items to the advisory backlog. `--id` filters `score` to one run and attributes a `--friction` note to a run. `--json` prints JSON.

## eval

`eval` measures the kit. `eval run` drives a runtime headlessly over a suite of cases and writes a JSON report; `eval compare` compares two reports of the same suite. Runs are opt-in: nothing starts one from a hook or an install.

```bash
mewkit eval run --suite baseline --dry-run
mewkit eval run --suite baseline --runtime claude-code --model <pinned-model> --max-cost-usd 5 --max-runs 40 --kit-archive meowkit-release.zip
mewkit eval compare <base.json> <new.json> [--json]
```

- Each run happens in a fresh copy of the case's fixture with the kit archive installed by `mewkit init`, never in your project. Use a release `meowkit-release.zip`, or build one from a checkout to measure your own changes. For a paired case, the "skill off" side deletes every installed copy of the skill under test.
- The runtime gets an empty config home and only the environment it needs: `PATH`, locale, and its own login variable (`CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` for Claude Code, `CODEX_API_KEY` or `OPENAI_API_KEY` for Codex). No login file is copied.
- `--model`, `--max-cost-usd`, `--max-runs` and `--kit-archive` are required to run cases. The cost ceiling is shared by every eval run in the project at the same time.
- A run that times out, is rate-limited or ends without a result is retried twice and then recorded as an error, kept out of every rate. A report is incomplete when errors pass 5% of runs, when a case ran other than planned, or when a case was skipped.
- `compare` refuses incomplete reports and reports that differ in runtime, model, case set or case list, and exits 1.
- Cases live in `<skill>/eval/*.yaml` under `.claude/skills`. `--case-root` reads another folder and needs `--trust-cases`, because its cases run model turns.
- The `baseline` suite (trigger cases for the 20 most-referenced skills, paired cases for `cook`, `plan-creator`, `fix` and `investigate`, and parachute briefs with controls) lives in the MeowKit repository; an install does not carry `eval/` folders. Paired assertions are `skillLoaded`, `skillNotLoaded`, `fileExists`, `fileContains`, `outputMatches`, `outputNotMatches`, `toolBefore` and `modelGraded`; a `fileExists` or `fileContains` path may use `*` within a segment (`tasks/plans/*/plan.md`).

## capabilities

`capabilities` inspects and resolves the capability manifest, the map of installed skills, agents, commands and hooks plus the authored tool and context services. The manifest is only a lookup surface and is never injected into a model session. The CLI reads the live `.claude/` install when there is one. A project with only a Codex install falls back to the validated `.codex/capabilities.json` snapshot.

```bash
mewkit capabilities list [--json]
mewkit capabilities explain <id> [--json]
mewkit capabilities resolve --intent "implement this feature" [--provider <id>] [--json]
mewkit capabilities view          # render the trigger-registry table from the manifest
mewkit capabilities bootstrap [--provider <id>] [--write]
mewkit capabilities projections [--json]
```

| Subcommand | Purpose |
| --- | --- |
| `list` | All capabilities with kind, owner, install state and intents |
| `explain <id>` | One capability's requirements, support levels, verification and provenance |
| `resolve` | Ranks capabilities for an `--intent`. With `--provider` it also reports whether the host has the capability, the safe invocation, any repo-context requirement and how that provider acquires it, and the adapter and evidence behind the claim |
| `view` | Renders the capabilities table (the generated part of the trigger registry) |
| `bootstrap` | Prints the bounded, brand-neutral discovery bootstrap for a provider. `--write` writes the generated file instead of printing it |
| `projections` | Per-provider discovery projection and the four support levels: `discoverable`, `selectable`, `invocable`, `enforceable` |
