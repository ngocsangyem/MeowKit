Everything that touches the shape of the project itself: installing the kit, configuring it, checking it is sound, and moving it to a newer kit. Which runtime gets which files, and where, is under [Runtimes and scopes](/cli#runtimes-and-scopes).

`init`, `upgrade` and `uninstall` all take `--json` (print one JSON document), `--force` (replace or remove files you edited) and `--global` (act on your home directory). With no terminal to confirm in (CI, a pipe, a hook), `init --force` and `upgrade --force` only show their plan and exit 3 unless `--yes` is also passed. Before any of them changes anything, it copies every file it is about to change or remove into a new directory under `.meowkit/backups/` (`~/.mewkit/state/backups/` globally); `mewkit backups list` and `mewkit backups restore` read them back.

## init

```bash
mewkit init                                   # picker: Claude Code, Codex, Cursor
mewkit init --target claude-code,cursor
mewkit init --target claude-code --delivery plugin
mewkit init --global --target all
mewkit init --target codex --dry-run
```

Downloads the newest kit release (`--beta` allows a prerelease; `--kit-version v2.16.0` pins one), checks it against the release's `checksums.txt` and its `kit-contract.json`, and writes it for each runtime. `--offline` uses the newest kit already in the cache; `--kit-archive <zip>` installs a local `meowkit-release.zip`, checked against `--kit-sha256` or a `checksums.txt` beside it. `--allow-unverified-kit` accepts a kit that has no checksum or no `kit-contract.json`; leave it off unless you built the kit yourself.

Without `--target`, a terminal shows a picker with Claude Code preselected. With no terminal, `--yes` or an existing `.claude/` means Claude Code, and otherwise the command exits 2 naming `--target`. An unrecognized `--target` is refused by name.

| Flag | Runtime | Effect |
| --- | --- | --- |
| `--profile <name>` | Claude Code | Install a subset: `core`, `developer`, `product`, `atlassian`, `security`, `research`, `full`. Running `init` again with a narrower profile removes what it no longer includes, unless you edited it |
| `--delivery native\|plugin` | Claude Code | The on-disk shape: the host's own directory, or the same content plus a plugin manifest. Refused with the other runtimes |
| `--skill-packs <packs>` | Codex, Cursor | Comma-separated skill packs, or `all`. Omitted installs every skill; an empty value installs the default pack only |
| `--mcp-profiles <names\|all>` | Cursor | Merge MCP servers into `.cursor/mcp.json`; your own servers win. A project with a git remote also needs `--allow-cloud-mcp` |

For Claude Code at project scope, `init` also writes the committed launcher `.meowkit/bin/mewkit` and the `.claude/runtime.json` that points the hooks at it ([how hooks reach mewkit](/cli#how-hooks-reach-mewkit)). In the MeowKit source repository itself, `init` refuses unless you pass `--allow-kit-source`, because `.claude/` there is the kit's authored source.

### Taking over an npm install

If the retired npm `mewkit` CLI installed a runtime in this project, `init --target <runtime>` adopts it. The npm CLI's install record becomes the starting ownership index, kit files are refreshed, files the kit no longer ships are removed when they still match what the record says was installed, and files you edited are kept. Adoption works at project scope only, and only when you ask for it with `init`. `upgrade` never adopts: on a runtime with an npm install record and no ownership index, it names the `init` command to run. [Moving from the npm CLI](/migration/from-npx-mewkit) walks through it.

## upgrade

```bash
mewkit upgrade
mewkit upgrade --target cursor --dry-run
mewkit upgrade --check
mewkit upgrade --list
```

Moves the runtimes installed here to the newest kit, with the packs they were installed with. It takes the same kit-source flags as `init`. A file you edited after the kit wrote it is kept and named, and the command exits 6; `--force` replaces it. `--check` compares each installed runtime with the newest release (`--beta` for the prerelease channel) and `--list` shows the recent releases; neither changes anything, and with `--offline` both read the kits in the cache instead of GitHub. `--no-cleanup` is accepted for scripts written for the npm CLI: a downloaded kit always stays in the cache.

## uninstall

```bash
mewkit uninstall            # shows what would go
mewkit uninstall --yes
mewkit uninstall --global --target codex --yes
```

Removes exactly what the kit installed: owned files, merged hook handlers, blocks and keys. Your own content in shared files stays. An edited file is kept unless `--force`.

## setup

Guided post-scaffold configuration. Each step is idempotent.

```bash
mewkit setup [--only=<step>]
```

| Step        | What it does                                                    |
| ----------- | --------------------------------------------------------------- |
| `skill-envs` | Prepares the per-skill Python environments under `.meowkit/envs/<skill>/` |
| `mcp`       | Copies `mcp.json.example` → `.mcp.json`                         |
| `env`       | Creates `.meowkit/.env` for your API keys                       |
| `gitignore` | Appends MeowKit entries to `.gitignore`                         |
| `project-context` | Prints the `/mk:project-context` command to run in your first session (it writes `docs/project-context.md`) |

```bash
mewkit setup              # Run all steps
mewkit setup --only=env   # Run single step
```

## doctor

```bash
mewkit doctor
mewkit doctor --global --json
mewkit doctor provenance --explain
mewkit doctor --hard-gates
```

Without flags it changes nothing. Checks Node.js (the kit's hooks need 24+), both scopes' installs (owned files present or edited), that every kit hook script a hook file names exists, Codex project trust, and which kit hook behaviours a runtime does not carry. Exits 1 when a check fails.

| Flag | Effect |
| --- | --- |
| `--report` | Append a shareable report block |
| `--providers` | Add what each runtime's adapter can enforce |
| `--state` | Add the state taxonomy |
| `--hard-gates` | Run the kit's plan, privacy, injection and ship hooks in a scratch project and report which ones block |
| `--explain` | With `provenance`: name the files behind each count |
| `--adopt` | Rebuild the npm CLI's ownership baseline (`.meowkit/metadata.json`) from the local kit cache, or refuse |
| `--target`, `--global`, `--json` | Narrow to some runtimes, check your home directory, print JSON |

`mewkit doctor provenance` classifies each installed file against the install baseline and says what local evidence can and cannot prove.

## providers

```bash
mewkit providers --target codex
mewkit providers --lifecycle
mewkit providers codex --lifecycle
```

What each runtime would get from the kit at this scope: files, skills, hooks, and the gaps, without installing anything. `providers <runtime>` is the same as `--target <runtime>`. `--lifecycle` shows instead which lifecycle events each runtime fires and which of them can block; with one runtime it adds support levels, invocation shapes and enforcement gaps.

## validate

Verify `.claude/` structure integrity.

```bash
mewkit validate
```

**Checks:** `agents/` and `hooks/` present, the 7 always-on rules present, config validity, hooks executable, docs references resolve, plugin namespace, the team-memory store. In the MeowKit authoring checkout, the full sweep also reports provider-specific vocabulary found in generic skill bodies as advisory portability WARNs; `--strict` promotes WARNs to errors. Run a focused suite with any of the flags below (no flag = the full sweep).

| Flag | Description |
| --- | --- |
| `--packs` | Pack-manifest coherence + the exact-path safety invariant. |
| `--workflow` | Workflow drift-check (always-on rules / phase docs vs `workflow.yaml`). |
| `--ownership` | Artifact ownership coverage. |
| `--substrate` | Substrate-view freshness + responsibility coverage. |
| `--rules` | Routing-table breadth. |
| `--portable` | Portable-migration manifest checks. |
| `--strict` | Promote recommended-field WARNs to errors. |

## versions

```bash
mewkit versions
mewkit versions --offline
```

The kits installed here, the kits in the cache, the kits available on GitHub (`--beta` includes prereleases, `--offline` skips GitHub), and the kit contract range this binary supports.

## self-update

```bash
mewkit self-update --check
mewkit self-update
mewkit self-update --channel beta
```

Fetches the newest binary release's `binary-manifest.json`, refuses an older version, checks the archive's SHA-256 and size, and replaces itself, keeping the previous binary beside it with an `.old` suffix. `--check` only reports, and exits 3 when an update exists. When the running version has been withdrawn, it says so.
