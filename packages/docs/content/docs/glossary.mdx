Each term below means one specific thing in MeowKit. Where a term also has a general meaning in software, the definition here is the narrower one.

## The pipeline

**Workflow**: the path a task takes from description to shipped code. There is one workflow, and it has seven phases.

**Phase**: one of the seven numbered steps: Orient, Plan, Test, Build, Review, Ship, Reflect. Every task passes through all of them. See [The Workflow](/core-concepts/workflow).

**Stage**: a step inside a phase. Simplify and Verify are stages of Build. A stage has no plan or verdict of its own.

**Ship check**: the one control a hook enforces at ship time. On `git commit`, `git push`, `git merge` and `gh pr create|merge`, the `pre-ship` hook runs lint on the changed files, their related tests and a type-check, and refuses the command when one fails. Planning and review are practices and nothing refuses a command on them. See [Enforcement & Security](/core-concepts/enforcement).

**Exception**: a documented case where a phase is skipped, such as a one-line fix that needs no separate plan.

**Execution mode**: how the phases run: one at a time (the default), in parallel across isolated worktrees, or as a party that deliberates an architecture question. A mode changes the shape of the work and leaves the ship check as it is.

## The pieces

**Runtime**: a coding assistant the kit installs into: Claude Code, Codex, Cursor, Grok, Pi or OMP. The kit is authored once in `.claude/`, and each other runtime gets the files it reads projected from that tree.

**Agent**: a specialist with its own context, prompt and file ownership, spawned to do one job: planner, developer, reviewer, shipper. Agents do not share a context window, so the developer cannot talk the reviewer round.

**Skill**: a packaged procedure the agent loads when the task needs it, addressed as `mk:name`. Skills are the instructions and agents are who follow them. A skill loads on demand, which keeps the context budget small.

**Hook**: a script the host runs at a lifecycle event. On Claude Code, hooks are registered in `.claude/settings.json`. A hook can refuse an action where a rule can only ask: `pre-ship.cjs` refuses a commit whose lint fails.

## How the docs are organised

**Canonical source**: the one place a fact lives. Other pages link to it. When two pages state the same fact, one of them goes stale, so each fact has an owner and the docs link to it.

**Hub**: a skill that routes instead of acting. `mk:jira` decides which Jira operation you want and forwards to the skill that does it.

**Leaf**: a skill a hub forwards to, which does one operation. Leaves carry the operation detail, and the hub carries the routing and the safety rules.
