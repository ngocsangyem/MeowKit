This guide gets you from zero to your first MeowKit-managed task in 5 minutes.

## Step 1: Install MeowKit

Install the `mewkit` binary, then add the kit to your project:

```bash
curl -fsSL https://raw.githubusercontent.com/ngocsangyem/MeowKit/main/install.sh | sh   # macOS and Linux
cd your-project
mewkit init
```

On Windows, use `irm https://raw.githubusercontent.com/ngocsangyem/MeowKit/main/install.ps1 | iex` in PowerShell.

`mewkit init` walks you through a short set of prompts. Every one after the runtime picker is skippable. See [Installation](/installation) for the full list and the flags that skip them. Takes ~30 seconds.

Pick the on-disk shape with `mewkit init --target claude-code --delivery plugin`, and check what landed with `mewkit versions`.

After scaffolding completes, run setup and verify:

```bash
mewkit setup
mewkit doctor
```

## Step 2: Create your first task

```bash
mewkit task new --type feature "Add user authentication with JWT"
```

This writes a task file to `tasks/active/` with the fields for that task type already in its frontmatter. If your project keeps its own template, such as `tasks/templates/feature-implementation.md`, the command uses that instead. Open it and fill in the acceptance criteria. They are what the plan and the review are both measured against, so vague criteria produce a vague plan.

## Step 3: Start a Claude Code session

Open your terminal in the project directory and start Claude Code:

```bash
claude
```

Claude Code auto-loads `.claude/rules/`, the 7 always-on rules, plus MeowKit's agents and
skills. MeowKit installs no root `CLAUDE.md`. If your project keeps one, it stays yours.

## Step 4: Run your first command

Plan the task you just created:

```
/mk:plan-creator add user authentication with JWT
```

MeowKit will:
1. Route to the **planner** agent
2. Challenge your premises (do you really need JWT?)
3. Create a structured plan at `tasks/plans/YYMMDD-auth/plan.md`
4. Agree the plan with you before building

## Step 5: See the full pipeline

Once you are happy with the plan, try the full cook pipeline:

```
/mk:cook
```

This runs the complete workflow. Each phase activates the appropriate agent, and the ship check runs lint, related tests and a type-check before any commit, push or PR. See [Workflow Phases](/core-concepts/workflow) for what each one does.

## Step 6: Explore more commands

| Command | What it does |
|---------|-------------|
| `/mk:fix [bug]` | Investigate and fix a bug with root cause analysis |
| `/mk:review` | Run a multi-pass code review with adversarial analysis |
| `/mk:ship` | Full ship pipeline: test → review → commit → PR |
| `/mk:scout [target]` | Parallel codebase exploration |
| `/mk:retro` | Sprint retrospective with trend tracking |

## What happened behind the scenes

When you ran `/mk:plan-creator`, MeowKit:

1. **Phase 0 (Orient):** Read relevant topic files on-demand for past patterns, assigned model tier
2. **Phase 1 (Plan):** Planner agent created a structured plan with product + engineering lens
3. **Agreement:** Proposed the plan for you to agree before building

Nothing blocks an edit without a plan; writing and agreeing it first is the practice, because a wrong plan costs more than the conversation.
