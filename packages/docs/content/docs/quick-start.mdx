This page takes you from an empty install to your first MeowKit task.

## Step 1: Install MeowKit

Install the `mewkit` binary, then add the kit to your project.

macOS and Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/ngocsangyem/MeowKit/main/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://raw.githubusercontent.com/ngocsangyem/MeowKit/main/install.ps1 | iex
```

Then, from your project:

```bash
cd your-project
mewkit init
mewkit setup
mewkit doctor
```

`mewkit init` asks which runtimes to set up: Claude Code, Codex, Cursor, Grok, Pi, OMP or Antigravity. To skip the question, name them with `--target`, for example `mewkit init --target claude-code` or `mewkit init --target codex,cursor`. `--target all` installs all seven at project scope. [Installation](/installation) lists every flag.

`setup` prepares the skill environments and `doctor` checks the toolchain, the installs and their hooks. The rest of this page uses Claude Code.

## Step 2: Create your first task

```bash
mewkit task new --type feature "Add user authentication with JWT"
```

This writes a task file to `tasks/active/` with the fields for that task type in its frontmatter. If your project keeps its own template, such as `tasks/templates/feature-implementation.md`, the command uses that instead. Open the file and fill in the acceptance criteria. The plan and the review are both measured against them, so vague criteria give a vague plan.

## Step 3: Start a session

Open your terminal in the project directory and start Claude Code:

```bash
claude
```

Claude Code loads the six always-on rules in `.claude/rules/` and the kit's agents and skills. MeowKit installs no root `CLAUDE.md`. If your project keeps one, it stays yours.

## Step 4: Plan the task

```
/mk:plan-creator add user authentication with JWT
```

The planner agent challenges your premises (do you need JWT?), writes a plan at `tasks/plans/YYMMDD-auth/plan.md` with one file per phase, and proposes it to you. Nothing blocks an edit without a plan. Writing and agreeing it first is the practice, because a wrong plan costs more than the conversation.

## Step 5: Run the pipeline

Once the plan looks right, run:

```
/mk:cook
```

`cook` runs the full workflow. Each phase uses the agent that owns it. Before any commit, push, merge or PR, the ship check runs lint, related tests and a type-check. [The Workflow](/core-concepts/workflow) describes each phase.

## Step 6: Try other commands

| Command | What it does |
|---------|-------------|
| `/mk:fix [bug]` | Investigate and fix a bug with root cause analysis |
| `/mk:review` | Run a multi-pass code review with adversarial analysis |
| `/mk:ship` | Ship pipeline: test, review, commit, PR |
| `/mk:scout [target]` | Parallel codebase exploration |
| `/mk:retro` | Sprint retrospective with trend tracking |
