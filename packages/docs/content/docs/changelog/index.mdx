## Upgrade

```bash
mewkit upgrade
```

Fresh install: [install the `mewkit` binary](/installation#install-the-cli), then `mewkit init`. See [Releasing](https://github.com/ngocsangyem/MeowKit/blob/main/RELEASING.md) for the full release process. ## 3.1.0 (2026-11-26)

Kit 3.1.0 ships with `mewkit` 0.2.0. Run `mewkit self-update`, then `mewkit upgrade`: the CLI changes below are in the binary.

### Highlights

- Plan state follows the checkboxes. On Claude Code, Codex and Cursor the stop hook brings a changed plan up to date, `mewkit plan sync` does it on demand, and the ship check reminds you to archive a finished plan on every runtime.
- Skills you customise survive upgrades. `mewkit skill overlay`, `fork` and `rollback` keep your version of a kit skill, and a separated edit to a Claude Code skill with eval cases merges with the kit's change.
- The eval harness measures a skill. `mewkit eval run` and `mewkit eval compare` drive Claude Code or Codex over the kit's cases in a checkout of the MeowKit repository.
- Antigravity is a seventh target. Its guards are installed as unverified.
- Every skill was rewritten around its goal. Each `SKILL.md` now opens with what the skill is for, when to use it and when to use a sibling, and states judgment work as outcomes with a done check. Rules that `.claude/rules/`, another skill or the `mewkit` CLI own are pointed to, not restated, and every path, flag, skill and agent a skill names exists in an install.
- One env-file order for every script: a shell export, then `.meowkit/.env`, then `.claude/.env`, then a new user-wide `~/.meowkit/.env`. See [Environment Variables](/reference/environment-variables).

### New Commands

- `mewkit plan sync <dir> [--check] [--json]` derives phase status, the Overview line, the plan.md table and an existing `.plan-state.json` from the Todo List checkboxes. It never ticks a box or archives.
- `mewkit skill status`, `skill overlay`, `skill fork` and `skill rollback`. See [Customising and Upgrading Skills](/guide/customising-skills).
- `mewkit eval run` and `mewkit eval compare`. See [Cost and Telemetry](/cli/telemetry#eval).
- Eval cases gain `toolNotCalled` and `toolInputNotMatches` assertions and a `gitInit` option that starts a run in a one-commit git repository. A `v2` suite (core lifecycle skills) and a `v2-ext` suite (the other rewritten skills) test both lost guidance and over-applied instructions.

### CLI

- `mewkit init --target antigravity` installs skills under `.agents/skills`, the instruction block in `AGENTS.md`, two on-demand rule files, the agents, and the privacy guard and ship check in `.agents/hooks.json`. `init` and `doctor` name the guards as unverified. `mewkit validate --target antigravity` checks the install.
- `mewkit doctor` adds a `skill listing: <runtime>` row per installed runtime, against that runtime's documented budget, and a `skill store` row. `rules: always-on` fails when an always-on rule file is missing or blank.
- `mewkit validate` fails on dead skill file paths and links, unknown slash commands, drifted shared-family files, agents without the A1 status block, and hook registrations that point at a missing file. `--skill-rubric` scores each skill on six mechanical criteria and writes a report; it never fails.
- `mewkit trace --friction --skill <name>` attributes a note to one skill.
- `mewkit validate` and `doctor` report the `hooks.<name>` toggle of a removed handler as a warning instead of rejecting the config.
- The installers and `mewkit self-update` no longer place `mewkit-next`, and remove the one the 0.1.0 and 0.1.1 installers left. Run `mewkit` or `mk`.

### Features

- **Plan state on every runtime.** The stop hook syncs the plans changed in a session and prints one line; `hooks.plan-state-sync: false` switches it off. The ship check prints the plan drift line and the archive reminder, read-only, on all seven runtimes.
- **Archived plans are not read.** Reads of `tasks/plans/archive/` and `tasks/plans/ceo-plans/archive/` are refused on every runtime, through read and search tools and read-type shell commands. Moving or writing those folders is not refused.
- **Skill store.** `mewkit skill status` lists each installed skill as `kit`, `overlaid`, `forked`, `local` or `unverified`, with its digests. Install, upgrade and uninstall keep forked, local, unverified and overlaid skills whole and report them as `kept`; a kept skill does not make `upgrade` exit 6.
- **Overlay and rollback.** `mewkit skill overlay` stores your version of chosen kit files outside the kit's trees; an overlay from a clone places only after this machine approves it. `mewkit skill rollback` restores any recorded digest of a skill.
- **Upgrade merge.** On Claude Code, `upgrade` merges an edit made in place to a project skill with the kit's change when the two edits are separated, the skill has eval cases and the cached previous kit matches the ledger. Otherwise the file is kept and `upgrade` exits 6, as before.
- **Eval harness.** Each run uses a fresh copy of the case's fixture with the kit installed from `--kit-archive`, an empty runtime home and a shared cost ceiling. The baseline suite has 104 cases: 76 trigger, 16 paired and 12 parachute. The `toolInputMatches` assertion checks what a tool was called with, such as the `Goal:` line of a subagent brief.
- **Antigravity target.** Skills, agents, two rule files and the instruction block are built from the vendor's documentation (read 2026-11-22). Nothing was probed live.
- **Skill descriptions on every runtime.** The description written for runtimes without a `when_to_use` field now carries it as "Use when: ...", so their routing sees the trigger text.
- **Delegation brief check.** The `delegation-brief-check` observer notes to the model when a subagent brief has no `Goal:` or `Return:` label. It never blocks. Switch it with `hooks.delegation-brief-check: false`.
- **Trace keys.** Trace records may carry `skill`, `session_id` and a closed-set `signal`. Readers ignore keys they do not know.
- **Skill audit.** `mewkit validate --skill-rubric` and the [Skill Audit](/guide/skill-audit) page publish each skill's scores.
- **Opt-in skills.** A skill whose `SKILL.md` sets `install_default: false` installs only when selected in `.meowkit/state/skill-selection.json`. No shipped skill sets it yet.
- **Verified marker.** The "verified" rule marker is written only when the always-on rules match a session-start digest. `doctor` reports a marker whose digest no longer matches.
- **Skill rewrite.** The shared preamble and protocol text is trimmed to what later steps read. Reference files that nothing loaded, or that repeated another file, are deleted: the `mk:ship` and `mk:document-release` step and boilerplate files, the `mk:fix` workflow files, the `mk:plan-creator` `workflow-fast.md` and persona prompts, the `mk:plan-ceo-review` and `mk:office-hours` phase files, the `mk:retro` and `mk:trace-analyze` step files, the `mk:multimodal` and `mk:docs-finder` workflow pages and eight unloaded `mk:agent-detector` references. New skill scripts: `retro-metrics.cjs` for `mk:retro`, `set-freeze.cjs` for `mk:freeze`, `recompute-score.py` for `mk:evaluate`, and a `detect` subcommand in `trace-records.cjs` for `mk:trace-analyze`.
- **Unified env loader.** `jira-as.sh` and `confluence-as.sh` read `KEY=VALUE` lines instead of sourcing the env files, so shell code in an env file never runs. `mk:docs-finder` and `mk:multimodal` use the same order and no longer keep a per-skill `.env`; `mk:multimodal` no longer needs `python-dotenv`. `mk:stitch` reads the env files too, where it used to read only the shell. The `jira-env-loader` hook accepts keys from any source and names the files it searched. `MEOWKIT_TDD` and the other workflow switches stay shell-only.
- **Confluence pages as ADF.** `confluence-as.sh adf-get <page-id>` reads a page as Atlassian Document Format through the Cloud v2 API, because `page get` in `confluence-as` 0.2.0 has no ADF format. The spec analyst and `adf-to-md.sh` use it, with the v2 metadata fields and `hierarchy descendants --max-depth <N> --limit 5` for children. `mk:intake` reads a page with `page get <id> --body --format markdown`.
- **Pinned Context Hub.** `mk:docs-finder` runs Context Hub as `npx --yes --package=@aisuite/chub@0.1.4 chub`. The bare `npx chub` resolves an unrelated npm package on a machine without a global install.
- **Other runtimes' text.** When `mewkit` installs for Codex, Cursor, Grok, Pi, OMP or Antigravity, skill and agent prose no longer names a Claude-only tool or variable. `AskUserQuestion`, `TodoWrite`, `TaskCreate` and `SendMessage` become plain phrases, and `CLAUDE_*` variables become what they stand for. The change lives in the binary, so an older `mewkit` keeps writing the old names; nothing breaks.

### Improvements

- Installed files do not use the product name. Hook messages, rule headings and skill text say what the step does; paths and commands keep their names. See [Installation](/installation#product-name-in-installed-files).
- The injection scan reports only blocking-class patterns to the model. A long command or a path outside the project no longer adds context.
- Skill listings on Codex, Grok, Pi and OMP were about 15,600 characters against a 12,000 ceiling. Descriptions are shortened and the listing is about 11,600 on each, with the NOT-for routing kept.
- Skill and agent text share one tier vocabulary (TRIVIAL, STANDARD, COMPLEX), one delegation template with `Goal` and `Return` fields, one challenger policy for plan red team and review, and shared sections that `validate` checks for drift.
- The kit's rules now agree on one answer each: a plan is written for a change of more than two files or about 30 minutes; code review is COMPLEX; the only TDD exemption is the micro-task; ADRs are named `docs/architecture/adr/YYMMDD-decision.md`; `mk:cook --fast` skips the plan only for work of two files or fewer and about 30 minutes or less.
- The orchestrator applies when a request's specialist agent or model tier is unclear, not at the start of every task.
- The plan-creator and cook entry files moved their reference tables into `references/`, so both stay under the 5,000-token budget that survives compaction.
- The ship check fails closed. A check that could not run (a crash, a missing tool, or a check stopped at the 270-second deadline) now blocks with a `PRE-SHIP COULD NOT RUN` message naming the cause, separate from `PRE-SHIP BLOCKED` for a failed check. Before, a missing tool counted as a failed check, and a hook the host stopped at its timeout let the command through.
- On Claude Code a check that could not run answers with the permission prompt (`ask`), so you decide; a failed check is still refused. Cursor asks too. Codex has no prompt for hooks, so it refuses and tells you to run the command in your own terminal. The Claude Code registration sets `onFailure: "block"` (Claude Code 2.1.295 or later) and the Cursor entry `failClosed: true`, so a ship-check hook that cannot start or reaches its timeout blocks.
- Nothing in the command or the environment skips the ship check. `--no-verify`, `-n` on a commit, a skip-style variable and `MEWKIT_CURSOR_HOOKS_KILL_SWITCH` are named in the output as refused. The Cursor kill switch no longer stands the ship check down.
- Each ship check writes one `ship_check` trace record: outcome `passed`, `failed` or `could_not_run`, the cause and the action, never the command text.
- `mk:review` only reports. Fixes go through `mk:fix`, or here with `--fix`, which applies the mechanical findings after the verdict. The forced "look harder" pass is gone, so no finding is a valid result.
- `mk:qa-manual` stops at a login page. You sign in in the browser or give it a saved auth state; a password never goes through chat. `mk:qa` follows the same rule, and its test-framework bootstrap (package installs, edits to `CLAUDE.md` and CI) is removed.
- `mk:plan-creator` no longer writes `.plan-state.json`. `mewkit plan sync` only updates one that exists. `mk:validate-plan` no longer claims `mk:cook` runs it.
- `mk:intake` asks before posting a comment to the ticket and goes past the completeness score only at 60 or more and on request.
- `mk:party` writes its decision record only when a decision was reached or you ask. It has no fixed rounds or token caps.
- `mk:freeze` sets its boundary through `scripts/set-freeze.cjs`, which refuses a missing path, a file and the filesystem root, and has `--clear`. Before, a failed `cd` left a `/` boundary that allowed every edit.
- `mk:cook` counts as done only with verify evidence, a review verdict read and every acceptance criterion checked. `--fast` and `quick` are one profile.
- `mk:build-fix` asks before a process kill, an install, a lockfile change or a cache delete. The Jira and Confluence leaves share one confirmation rule: a plain "yes" after a `--dry-run` shows the count, and a typed token is for irreversible deletes only. `mk:jira-issue` and `mk:confluence-page` confirm a delete.
- `mk:agent-browser` and `mk:playwright-cli` take credentials from an env var, a vault or a cookie file, never as a literal in a command.
- Ten skills that had no "NOT for" clause in their description now name the sibling they are not for, so routing can tell `help` from `status`, and `jira-evaluator` from `planning-engine`.
- Example addresses in reference files use `@example.com`, and a trace example no longer carries a personal home path.
- Placeholder `## Gotchas` sections that held only "(none yet)" are removed from 16 `jira-*` skills, and passages that two files stated twice are kept in one.
- Eval fixtures under `.claude/skills/*/evals/` stay in the repository and are no longer part of the release archive.

### Removals

- The `mk:ship` reference `adversarial-review.md`, which nothing read. Adversarial review belongs to `mk:review`.
- The trace events `build_verify_result` and `loop_warning` are no longer documented: nothing writes them.
- The framework and language skills `mk:angular`, `mk:react-patterns`, `mk:vue`, `mk:vue-best-practices`, `mk:vue-testing-best-practices` and `mk:typescript`. Releases outdated them quickly, and each framework and language now ships its own official agent skill; install that one instead. They also leave the `development` skill pack.
- The Vue 3 section of `mk:development`'s `code-patterns.md`. The skill keeps its NestJS and Swift patterns.
- The opt-in eval pack. Releases carry no eval cases or fixtures, `--skill-packs eval` and `mewkit pack add eval` are refused as unknown packs, and `mewkit eval run` reads cases only from a MeowKit checkout. `upgrade` and `uninstall` remove an installed `.meowkit/eval/`, keeping any file edited since install.
- Flags and commands that were never implemented or that named nothing: `mk:autobuild` `--resume` and `--teams`, the `mk:prompt-enhancer` `--score` flag, the `workflow:handoff` and `workflow:resume` triggers of `mk:session-continuation`, and the `--agents N` hint of `mk:team-config`. The `session-continuation` TOON format and auto-save timer are gone; it uses `mewkit plan sync`, `mewkit task-state` and `mewkit orient`.
- The telemetry opt-in prompts, the essay link and the session counter in the shared skill preamble. The local skill-usage line that `mk:retro` reads stays.
- The `mk:skill-creator` `init-skill.py` no longer creates an `mk:` directory; it creates `<slug>/`.

### Bug Fixes

Security fixes from the pre-release audit. Each was reproduced before the fix and replayed after it.

- `mewkit note`, `setup` and the other commands that write project files followed a symlink committed in a cloned repository, so a write could land outside the project (a shell startup file, for one). They now refuse a symlinked target or parent and name it. `init` no longer reads a merge target such as `.claude/settings.json` through a link, which copied the user's global settings into the project.
- A forged `.meowkit/state/mewkit-interrupted.json` could make `init` copy a file from outside the project in, or delete project files. A record whose backup is not a `mewkit` backup, or whose paths leave the install, is ignored with a notice.
- A kit cache entry planted in a repository was installed as if it were the verified release. A cache git tracks is refused, an online run always re-extracts the verified archive, and an offline entry that cannot be re-verified needs `--allow-unverified-kit` and is recorded as unverified.
- `mk:markdown-reader` ran JavaScript front-matter (`---js`) and raw `<script>` from the file it rendered. Front-matter is YAML or JSON only, raw HTML is escaped, and the local server checks the `Host` header, stays inside the project by real path and refuses dotfiles.
- A project env file that set only `MEOW_JIRA_SITE_URL` or `MEOW_CONFLUENCE_SITE_URL` sent the token from `~/.meowkit/.env` to that site. The three connection keys are now one credential (see Migration Notes). The Confluence Cloud check reads the host of the URL; it used to accept `https://example.com/x.atlassian.net`.
- The build check after an edit and the ship check ran `npx tsc` and `npx eslint`. With no terminal attached `npx` installs a missing package without asking, and `npx tsc` resolves to the npm package named `tsc`, not TypeScript. Both checks now run only the project's own `node_modules/.bin` and skip a tool that is not installed.
- The credential guard judged only the file a tool named. It now also refuses a shell command that prints or copies out a credential file (`cat .env`, `grep TOKEN .env`, `curl -F x=@.env`, `tar`, `source`) and a Grep whose glob selects one, and it knows more files: `.netrc`, `.pypirc`, `.htpasswd`, Docker, `gh`, gcloud and Azure config, Terraform state, service-account keys, keystores and SSH keys with a suffix. It no longer refuses a skill's markdown file for having `secrets` in its name.
- The web-fetch address check missed `172.16.0.0/12`, IPv6 loopback and local ranges, `0.0.0.0`, decimal and hex hosts and upper-case `LOCALHOST`, and looked at the first URL only. `mk:web-to-markdown`'s browser mode now applies the address check to every request a page makes, not only to navigations.
- The ship check did not see `git commit` after `if … then`, inside `{ }`, after `!`, or behind `time -p`, `env -u`, `nice -n`, `sudo -u` and `xargs`.
- `mk:worktree` built git commands as shell strings from branch names, so a branch named with `$( )` ran a command. Git is now called with an argument list.
- `mk:review-pr`, `mk:respond-pr`, `mk:story-sizer` and the `jira-analyst` agent put review and ticket text inside a double-quoted shell argument, where a backtick runs. The text goes through a file.
- `mk:agent-browser` gave an ignore pattern that did not match the session-state files its own examples create; the examples save them under `~/.agent-browser/state/`. `mk:docs-finder` sent `CONTEXT7_API_KEY` to the fallback documentation hosts. `mk:stitch` built its output folder from an unchecked screen id.
- `npx playwright-cli` and `npx axe` named packages that are not the intended tools; they are now `@playwright/cli` and `@axe-core/cli`, with versions. `jira-as`, the `mk:multimodal`, `mk:web-to-markdown` and `mk:markdown-reader` dependencies, `repomix` and `agent-browser` are pinned to exact versions.
- `mk:chrome-profile` asks which origins it may act on before it attaches to your signed-in Chrome, and only reads anywhere else.
- `mk:cso`, the `security` agent, the pattern scanner and `mk:build-fix` cover compromised package releases: a release-age window, install scripts, remote code with no pinned version, package-name checks before an install, publish tokens, CI token scope, MCP servers and hidden text in agent files.
- The release workflow publishes only a tag whose commit is on `main`, attests each binary archive (`gh attestation verify`), and pins every action by commit. `scripts/release.sh` no longer replaces an asset of a published release.

- A tool result was priced at the output rate, which overstated the cost estimate about fivefold. It is priced as input now, and the model is detected in one order shared by the hooks.
- A plan whose boxes were ticked still read as `pending` everywhere. `plan sync` and the stop hook bring the status in line with the checkboxes.
- On Windows, `mewkit skill fork` kept the kit's `name:` in a `SKILL.md` checked out with CRLF endings.
- On Windows, the ship check could not start `npm` or `npx`, which are `.cmd` shims. Every ship reported `Not found: npm`, and a failed check exited 0 and let the command through.
- Skill text named 52 `mk:<name>/` file paths, 11 skill-local files and 22 slash commands that do not exist. They now point at real files and commands, and `validate` fails on any that come back.

### Migration Notes

- Jira and Confluence: keep the site URL, email and API token in one env file. A split across the project file and `~/.meowkit/.env` now stops with exit code 78 and names both files.
- A project file that is a symlink (for example a `CLAUDE.md` or `.meowkit/` file linked from elsewhere) is refused by the commands that write it. Replace the link with a real file.
- `--kit-dir` needs `--allow-unverified-kit`, and is refused with `--global` when `--yes` is given or no terminal is attached. A `--kit-version` older than the installed kit needs `--force`.
- The first `--offline` run after this upgrade reports the cached kit as unverified, because older cache entries carry no tree digest. Run `init` or `upgrade` online once.
- A project with a `tsconfig.json` and no local TypeScript no longer gets a type-check at ship time (`SKIP: typescript not installed locally`). Install TypeScript in the project to get it back.
- Re-create a skill environment to pick up the pinned versions: `mewkit skill env jira`, and the same for `multimodal` and `web-to-markdown`.
- `mewkit setup` now writes `# Environment Variables` at the top of `.meowkit/.env` and starts the `.gitignore` block with `# mewkit`; an existing block is left as it is.
- An older `mewkit doctor --hard-gates` run against the 3.1.0 kit reports one false failure on the injection-scan row, because it looks for the old message; upgrade the binary to 0.2.0.
- Installed text changed. A script or hook that matched `MeowKit ship check` or a `# MeowKit` heading needs the new wording: `# MeowKit Core` is now `# Core Rules`, the shared `AGENTS.md` heading is now `# Working rules`, and hook messages drop the prefix (`Ship check: …`, `Injection scan flagged …`). A file you edited keeps your edit, and `upgrade` exits 6 on it, as before.
- An archived plan can no longer be read by an agent on any runtime. The shipped code is the source of truth; the plan is kept for the record.
- The plan threshold is more than two files or about 30 minutes everywhere. `plan-creator` had said one hour.
- Antigravity's guards are unverified. Check them on a live run before you rely on them.
- The first `upgrade` of an install made before skill selections existed writes `.meowkit/state/skill-selection.json` with every installed skill. A smaller default later reaches fresh installs only.
- A `hooks.<name>` key for a handler that a release removed now warns instead of failing the config. Delete the key when you see the warning.
- `upgrade` removes the files of the six removed skills, keeping any file you edited since install; a skill folder with an edited file stays with only that file. Without the old kit in the cache, offline, every file is kept and `upgrade` says so. Until you upgrade, an install keeps its copies. `mewkit` 0.1.1 removes them the same way.
- An older `mewkit` that changes the ownership ledger marks the affected skills `unverified` in the skill store. `mewkit skill rollback <name>` settles one.
- Env files are read in one order: shell, `.meowkit/.env`, `.claude/.env`, `~/.meowkit/.env`, and the first source to set a key wins. `mk:docs-finder` and `mk:multimodal` no longer read a `.env` inside the skill folder; move those keys to `.meowkit/.env` or `~/.meowkit/.env`. `jira-as.sh` and `confluence-as.sh` no longer execute an env file, so a value that relied on shell expansion or a command in the file must be written out. `PATH`, `LD_PRELOAD`, `IFS` and a few similar keys are ignored, and a quoted value keeps a `#`.
- `mewkit upgrade` removes the files of the six removed framework skills when they still match what the old kit installed. A file you edited is kept. Without the old kit in the cache every file is kept and `upgrade` prints a notice. A skill selection file that names a removed skill is ignored.
- A script or note of yours that names a deleted reference file, such as `mk:fix` `references/workflow-quick.md` or `mk:review` `references/adversarial-review.md`, needs the new path. `mewkit validate` fails on a dead skill path.
- A project that relied on `mk:review` editing files must pass `--fix`, or run `mk:fix`.
- The eval baseline case-set hash changed because the `v2` suites were added. A baseline report from before cannot be compared with one from after.

## 3.0.1 (2026-11-21)

Kit 3.0.1 ships with `mewkit` 0.1.1. Run `mewkit self-update`, then `mewkit upgrade`: the fixes below are in the binary.

### Features

- `init` ends with a one-line note when a newer `mewkit` binary is released, naming `mewkit self-update`. It asks GitHub once per run, waits at most 2 seconds, and is skipped with `--offline`, `--kit-archive` or `--kit-dir`.

### Bug Fixes

- `upgrade` and `uninstall` download the installed kit release again when the cache no longer has it. Before, a clone or a project with a cleaned `.meowkit/cache` kept every file the new kit had dropped, because nothing proved the kit had written them.
- `init` in a project that has the kit's files and no install record rebuilds the record from the release those files came from, then removes what the new kit dropped and keeps the files you changed. Before, it wrote the new kit beside the old one. `--adopt-from <tag>` names the release when the files do not.
- `init` refuses to install over 20 or more kit paths that hold other contents when it cannot tell which release they came from. `--force` replaces them, each one backed up first.
- The kit's `.meowkit/.gitignore` no longer ignores `.meowkit/state/ownership/*.json`. Commit those files so a clone carries the install record.

## 3.0.0 (2026-11-20)

Version 3 replaces the npm CLI with one native binary, installs the kit on six runtimes from a single authored tree, and removes the approval gates. Read the Removals and Migration Notes before you upgrade a 2.x project.

### Highlights

- `mewkit` is a native binary, with `mk` as a short alias. The npm package is retired.
- One authored kit installs on Claude Code, Codex, Cursor, Grok, Pi and OMP. The files each runtime loads are projected from `.claude/` at install time.
- The plan-approval and review-approval gates are gone. Planning and review stay in the workflow as practices. The one check a hook still enforces at ship time is the ship check, which now runs on Claude Code, Codex and Cursor.
- The kit is a lean tree. `.claude/` ships agents, hooks, rules, skills, `settings.json`, `statusline.cjs`, `kit-contract.json` and `kit-capabilities.json`. Everything the kit writes at runtime lives under `.meowkit/`.
- Agents are pinned to current models on Claude Code, Codex and Cursor.
- The docs and the landing page use a new identity, Prompt + Cursor.

### Features

**Six runtimes from one source**

- `mewkit init --target` accepts `claude-code`, `codex`, `cursor`, `grok`, `pi`, `omp` or `all`. At project scope, `all` installs all six. Grok, Pi and OMP install at project scope only, so `--global --target all` installs Claude Code, Codex and Cursor. See [Portability](/cli/portability).
- Every runtime other than Claude Code is projected from the authored `.claude/` tree plus a small overlay in `kit/overlays/<runtime>/`. The overlay holds what cannot be derived: hooks, rules and the always-on text. The hand-written Codex and Cursor bundles are removed.
- Grok gets skills in `.grok/skills`, the hook file `.grok/hooks/meowkit.json` and always-on text in `AGENTS.md`. It gets no agent definitions, because Grok documents no file format for them.
- Pi gets skills in `.agents/skills`, one extension at `.pi/extensions/meowkit.ts` and `AGENTS.md`. Pi has no subagents, so it gets no agents.
- OMP gets skills in `.agents/skills`, the kit's agents in `.omp/agents/`, the hook module `.omp/hooks/pre/meowkit.ts` and `AGENTS.md`.

- `init`, `uninstall` and `upgrade` plan again for every installed runtime whose files depend on the set that is changing. Adding a runtime and then removing it leaves the same tree as a fresh install of the runtimes that stay.

**The ship check and the hooks**

- On `git commit`, `git push`, `git merge` and `gh pr create|merge`, the ship check runs lint on the changed files, the tests related to them and a type-check, and refuses the command when one fails. It ignores `MEOWKIT_HOOK_PROFILE=fast`. When the test runner cannot name related tests, it runs lint and type-check only and says that tests did not run.
- On Codex the ship check is a new hook in `.codex/hooks.json`. Codex also gets a privacy guard on Bash commands that touch `.env*`, key or credential files.
- The privacy, ship-check and completion-check decisions live in `hooks/lib/core`, one copy that every runtime's hooks share. A guard that cannot resolve a trusted project root denies the action.
- `.claude/hooks/hook-coverage.json` records which hook behaviours each runtime carries.
- A completion check is available as an opt-in on Claude Code, Codex and Cursor. With `hooks.pre-completion-check: true`, a turn that ends with files changed since the last passing test, build, lint or type-check run is continued, twice at most. It is off by default, and what it reports is advisory.
- On Claude Code, a failed compile or lint after an edit is reported on the channel the model sees, and so is the advice from the observers that used to print plain stdout (loop detection, the pre-task check, post-write warnings).

**Kit releases**

- A kit release is a zip with a `checksums.txt` and a `.claude/kit-contract.json` (contract version, minimum installer, kit version). `mewkit` checks the zip against them before it writes anything.
- Skills reach their own files by skill-relative paths, so they run on runtimes other than Claude Code. CI checks this.

## 2.15.0 (2026-07-27) — Strategic Supervision & the Portable Backend Surface

Ships as kit **2.15.0** and **`mewkit` CLI 2.3.1** (patch — the CLI gains a new command surface and a safer upgrade path without changing an existing flag or subcommand). A new advisory agent can supervise a single delivery run when you ask for it, and the backend skill surface becomes portable across every supported runtime.

### Highlights

Pass `--advice` to a supported skill and the `athena` agent supervises that one run: it sets direction before work starts, unblocks a stalled run, and reads finished work against its own evidence before the normal reviewer sees it — and it can send the work back for correction. It approves nothing. Every directive is evidence a human reads at a gate, never the approval itself, and supervision never counts as verification. Without the flag there are zero calls and no state is written.

The backend surface is also rebuilt around discovery instead of defaults. `mk:backend-development` and `mk:devops` join a redesigned `mk:database`, and `mk:api-design` becomes `mk:api-design-principles`. The four now read the engine, platform, and contract a project already has before proposing anything — no assumed database, no assumed cloud, no invented latency target — and each states plainly what it does not own.

### New Skills

| Skill                      | Purpose                                                                                                     |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `mk:backend-development`   | Drives a backend change end to end and routes the contract, data, and auth parts to their owners.           |
| `mk:devops`                | Infrastructure, containers, CI/CD, deployment safety and rollback — reads no secrets and approves no release. |

### New Agents

- `athena` — strategic supervision at named checkpoints, and a stateless strategy consult where a runtime exposes direct delegation. Read-only, and it never interviews the user.

### New Commands

- `mewkit advice begin` — opens a checkpoint, enforcing the caps, stage legality and idempotency before anything is delegated.
- `mewkit advice commit` — records the result, writes the receipt, and refuses a disposition that is illegal for the stage.
- `mewkit advice status` — the resume view: current stage, calls used, latest directive, next safe action.
- `mewkit advice validate-packet` — validates an input packet, an output packet, or a direct-consult brief.

### CLI

- Upgrading a Codex or Cursor project now removes a skill directory the bundle no longer ships, but only when its installed contents still match what the toolkit recorded at install time.
- A skill directory you edited is preserved byte for byte and reported by name, and `--force` does not widen this — it can overwrite a currently managed skill, never an unproven retired one.
- A dry run reports the planned removal and writes neither the directory nor the ledger.

### Features

- `--advice` on `mk:brainstorming` (deep workflow only), `mk:plan-creator`, `mk:cook`, `mk:fix`, `mk:autobuild` and `mk:ship`, composable with every existing flag.
- Supervision runs a fixed cadence — direction, rescue, review, recheck — capped per skill, with `mk:ship` carrying a separate budget for each of `prepare`, `release` and `publish`.
- Returned work goes back to its current owner with corrections that each name the proof that closes them; a second unresolved return escalates to a human rather than looping.
- Continuity comes from a compact per-run record rather than a transcript, so a crashed run resumes without re-spending a checkpoint.
- `mewkit providers <provider>` reports supervision support per runtime, tracking the harness and the direct consult as separate capabilities.
- `mewkit task-state` lists the evidence paths a record tracks.

### Improvements

- `--advice` and `--html` are orthogonal: combining them changes no activation, approval, validation, export or ownership of the visual pipeline.
- `mk:workflow-orchestrator` is not a supervision entry point — it carries only an opaque run id across phase boundaries, so an orchestrated child can never supervise itself.
- `mk:database` is now portable and engine-neutral — it discovers the engine, migration tool and ORM a project already runs instead of assuming PostgreSQL, and asks when the repository does not say.
- Database guidance leads with data invariants rather than syntax, requires a recovery path for any change to a table that already holds data, and never runs a migration or backfill against a live database.
- The accurate PostgreSQL specifics are kept, each restated as conditional on the engine actually in use rather than as a universal rule.
- Help, ask-me, the agent detector and the plan creator now share one API / backend / database / DevOps decision matrix, so the four adjacent skills route the same way from every entry point.

### Removals

- `mk:api-design` is replaced by `mk:api-design-principles` with no alias — invoke the new id, which covers RPC and event contracts alongside REST and GraphQL. The old documentation URL redirects to the new page.

### Bug Fixes

- A supervision correction could overwrite an approved visual plan artifact — a correction now writes only an existing workflow evidence index, checked on the resolved path so a symlink cannot redirect it.
- The harness inventory no longer reports read-only agents as writing the files they merely cite.

### Beta

- Supervision is authored for Claude Code, Codex and Cursor, but no runtime has been verified end to end yet: every capability reports `unverified`, and a runtime that cannot reach the agent prints an unavailable notice and continues unsupervised. Run `mewkit providers <provider>` to see the current state.

### Migration Notes

- Run `npx mewkit upgrade` to pick up the new skills. An untouched `api-design` skill directory is removed as part of the upgrade; an edited one is kept and named in the output so you can merge it yourself.
- Replace `mk:api-design` with `mk:api-design-principles` anywhere you invoke it by name — there is no alias, so the old id resolves to nothing.

- `mewkit review prepare <pr-url | owner/repo#n | n> [--remote <name>]` — provision an isolated SHA-bound worktree from a PR (fork-safe: `pull/N/head` fetched from the base-repo remote), capture one immutable hash-pinned diff + PR metadata/CI as untrusted DATA, and write a deterministic impact map + reviewer roster/briefs under `tasks/reviews/<session>/`.
- `mewkit review read --session <id> --as <role> <path>` — path-confined, evidence-recording read wrapper (assigned reviewer reads flow through it so coverage is observable).
- `mewkit review coverage --session <id>` — roster ∩ evidence gap gate; reports `evidenceLevel` (`session-observed` vs `attested`) and exits non-zero on any gap.
- `mewkit review compose --session <id>` — the mechanical gate: verify the diff hash, re-run coverage, apply the deterministic verdict cap table, resolve inline anchors by snippet, and emit a `verdict-gate`-compatible proof bundle + `SubmitPayload`.
- `mewkit review submit --session <id> --reply --confirm <payload-hash>` — the sole GitHub write path; re-checks the PR head SHA (aborts without posting if it changed) and is idempotent.
- `mewkit review cleanup --session <id>` — remove the ephemeral review worktree (manifest-nonce-owned); the session audit trail is kept.
- `mk:worktree review-pr` / `review-pr-cleanup` — detached, nonce-owned review worktrees; cleanup refuses anything but a matching manifest.

### Features

- `mk:review-pr` gains an opt-in `--assured` lane (full ReviewSession pipeline) and keeps its fast, read-only default lane unchanged.
- Scope-driven review topology (small / medium / large tiers) with whole-diff roles a per-chunk territory reviewer cannot own, plus heavy-file invariant slices.

### Improvements

- `mk:review` PR mode consumes the prepared session; step-03 runs the coverage gate before verdict composition, and step-04 composes the verdict through `mewkit review compose`.
- Gate 2 (`gate2-check.sh`) gains a narrow review-session extension that validates a review verdict's embedded coverage block (hash-clean, no gaps, `session-observed` required for PASS); inert for non-review verdicts.

### Security

- All git/gh invocations in the review pipeline use array-argv `execFileSync` (no shell). Untrusted PR content is quarantined under `untrusted/` and never treated as instructions; the read wrapper is realpath-confined against symlink exfiltration.
- Honest capability limit: subagent tool calls do not reach the parent PostToolUse hook, so `session-observed` is anti-accidental corroboration (not unforgeable) and proves session-level — not individual-reviewer — access; subagent-driven reviews are `attested` and cannot earn Approve.

### CLI

- The `mewkit` CLI is bumped to **1.19.1** for the `review` command group (`prepare` / `read` / `coverage` / `compose` / `submit` / `cleanup`).
