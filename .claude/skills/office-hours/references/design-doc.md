# Design Doc and Handoff

Write to `tasks/plans/{slug}/{user}-{branch}-design-{datetime}.md`; get the slug from `.claude/hooks/lib/workflow-slug` (or the task name). If an earlier doc exists for the branch, add `Supersedes: {its filename}`. The doc is the input to `mk:plan-creator`.

## Template

```markdown
# Design: {title}

Generated by /mk:office-hours on {date} | Branch: {branch} | Mode: {Startup|Builder} | Status: DRAFT
Supersedes: {prior filename; omit when first}

## Problem Statement
## Demand Evidence            (Startup only: quotes, numbers, behaviours from Q1)
## Status Quo                 (Startup only: the workaround users live with, from Q2)
## Target User & Narrowest Wedge   (Startup only: Q3 and Q4)
## What Makes This Cool       (Builder only: the delight or novelty)
## Constraints
## Premises
## Adversarial Perspective    (only if a second opinion ran: its read, verbatim or close)
## Approaches Considered
## Recommended Approach
## Open Questions
## Success Criteria           (measurable; "done" for Builder)
## Distribution Plan          (how users get it, and the release pipeline; omit for a service with an existing pipeline)
## Dependencies               (Startup only)
## The Assignment             (Startup: one real-world action the founder takes next, not "go build it")
## Next Steps                 (Builder only: what to implement first, second, third)
## What I noticed about how you think   (2-4 bullets quoting the user's own words back)
```

Show the draft; the user approves it or asks for changes. A spec review (a fresh-context pass over completeness, consistency, clarity, scope and feasibility, at most three rounds) runs only when the user asks.

## Handoff

State the assignment (startup) or the first build steps (builder) and name the next skill:

- `mk:plan-creator` with this doc, to plan the build;
- `mk:plan-ceo-review` once a plan exists, to check scope and ambition;
- `mk:frontend-design` for a UI-heavy idea.

Status: DONE when the doc is approved; DONE_WITH_CONCERNS when approved with open questions listed; NEEDS_CONTEXT when the user left questions unanswered; BLOCKED when something outside the session stops the work. Definitions: `.claude/rules/agent-conduct.md`.
